# TeraSchool

基于旧培训学校系统的业务升级与重新实现。Java/Spring Boot 模块化单体、PostgreSQL、React/TypeScript；以公有云 SaaS 为主，支持客户 Linux 独立部署，AI 当前只保留业务底座。

## 本地查看与验证

在 Windows 项目目录的 PowerShell 运行 `.\start-local.ps1`，退出使用 `.\stop-local.ps1` 或在该窗口按 Ctrl+C；后端与前端日志实时打印在启动窗口，同一份写入 `.local\dev\`。当前默认 WSL PostgreSQL，本地查看的详细地址、工具、秘密位置与重启操作见[本地启动与演示验收](doc/03-研发规范/开发环境/本地启动与演示验收.md)。默认不停止共享 PostgreSQL，不重置手工数据。

完整工程验证入口：

```powershell
python -X utf8 tools/engineering/verify.py
```

该脚本使用独立可销毁 PostgreSQL 容器，执行迁移、生成、后端测试与前端生成/检查/构建，需要已配置 JDK 25、pnpm、可用 Docker，以及按 `tools/progress/requirements.txt` 安装的 Python 文档生成依赖。验证入口也会检查开发总览同步状态。若当前服务占用原构建文件，应在隔离源码副本验证，具体操作与本轮限制见审阅验证记录；不要为清理构建输出停止无关服务。

## 仓库职责

| 目录 | 内容 |
| --- | --- |
| backend | 模块化业务核心与 HTTP 组合入口 |
| frontend | 按业务 feature 组织的管理端 |
| contracts | 契约生成与表示约定 |
| tools | 开发、验证、迁移与运维工具；运行前阅读对应功能和交付限制 |
| doc | 范围、规则、设计、规范、计划、决策和验证证据 |
| 参考资料 | 旧系统只读证据，整体忽略，不进入 Git/构建 |
| .local | 本机配置、缓存及隔离验证产物，忽略目录，不提交秘密 |

GitLab 为主线，GitHub 为备用；远程 CI 尚未验证。提交、推送和部署按每次任务的明确授权执行。

文档使用稳定路径，版本仅在正文维护；日常升版无需改名或批量更新引用，具体见[文档管理规范](doc/03-研发规范/文档管理规范.md)。
