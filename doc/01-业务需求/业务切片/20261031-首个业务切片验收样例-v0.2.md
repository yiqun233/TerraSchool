## 1. 确认和来源

样例 SC01：普通报名、平均价格模式1、无优惠/服务费；1000元购买10课时并收齐；一节课消耗1课时100元；随后退2课时200元，先回学员账户，再单独确认办理200元现金退出。2026-10-31 用户明确回复“采用该样例，保留退到账户和现金退出两个步骤”。

这是人工构造的首片金标准，不是真实客户数据或已在旧环境提交的结果。旧代码的模式1、退量/退费及分配/现金路径提供逻辑证据，见 SC01-E01–E13；没有执行旧结算代码。用户确认不扩大为全部结算公式、审批豁免、异常案例已批准或技术测试已通过。

案例状态分开记录：业务期望已确认 / 派生待评审；实现未开始；实际运行未执行；人工验收未开始。本轮只对算术及文档一致性核对，不新增已经通过的业务测试数。

## 4. 对账口径和来源

下列公式仅用于本例无其他费用/优惠/历史且单学校的范围，完整业务按规则版本扩展：

- 课时：购买10 = 已消耗1 + 已退2 + 剩余7。累计已退来自有效退课时单，不把同一张单的累计字段再次追加。
- 应收：原约定1000 − 有效课程退费减项200 = 当前净应收800；原约定快照仍为1000。
- 分配：原分配1000 − 本次原分配释放200 = 有效分配800；本例应收与有效分配相等，所以无欠款。
- 消费：模式1在本例单价1000÷10=100元/课时；1课时固化100元。普通退2课时对应减项200元，不是重新用800÷10计算已关闭课次。
- 课程未消金额：净应收800 − 已固化消费100 = 700；这是业务指标，不直接称为全局会计负债。
- 资金：净收支 = 实际收款1000 − 实际现金退出200 = 800；在各阶段，净收支 = 有效分配 + 账户总额。
- 账户：已确认收款 − 有效分配 − 实际现金退出 = 账户总额；账户可用 = 总额 − 有效冻结。S6 时总额200、冻结200、可用0。

收款明细、分配/释放、退课时单、现金退款单/执行、课次消费各有唯一来源ID和追踪链；汇总必须可回溯明细。不能将退课时减项和现金退出均从净应收扣除两遍，也不能把退到账户200元算作已向家长现金退出200元。

除 CASE01 的主样例外，下表为依据已有不变量设计的验收要求，仍待评审；全部业务实现与实际运行均未开始。每个案例执行时保存前置状态、输入/版本/权限、预期/实际数值、审计/错误、复现步骤和结果，不能只勾“通过”。

| ID | 场景与输入 | 必须核对的期望 |
| --- | --- | --- |
| SC01-CASE01 | 执行 S0–S7 | 逐行对齐第3节，不用只看最终余额；两次资金步骤和课次固化均可追溯 |
| SC01-CASE02 | S1 的同一收款请求重复/超时重试 | 实收及账户只增加1000一次；同幂等键改金额拒绝；历史结果读取仍鉴权 |
| SC01-CASE03 | 已分配1000后再次尝试分配200，或单次超分 | 原来源可用不足，拒绝且所有金额不变；不能新增一个负余额来凑齐 |
| SC01-CASE04 | 同手机号关联两个合成学员 | 提示核验，不自动合并主档或覆盖联系人；授权确认之外不产生关联副作用 |
| SC01-CASE05 | 草稿保存/发布/授课确认 | 草稿不发通知、不提前记消费；发布确认绑定版本，发布时资源变化或冲突拒绝 |
| SC01-CASE06 | 关闭同一课次两次、含首次响应丢失 | 有效消费仅1课时100元；审计追踪可区分重试，不能出现两条有效入账 |
| SC01-CASE07 | 退2课时方案生成后，另一人先关闭/退课时或改资源规则 | 旧版本/确认凭证失效，重新预览；不得沿用旧方案静默改变金额或数量 |
| SC01-CASE08 | S5 同键重试；另做一份独立扩展例，在累计退2后新退1课时 | 同键不再加200；新请求以本次1课时100元追加，累计应为3课时300元，不能把累计3当作本次再退3 |
| SC01-CASE09 | 退到账户事务中途失败 | 退课时、减应收、释放分配、账户增加、成功审计全部回滚，不留下已退课时但无退款权益 |
| SC01-CASE10 | 两个请求同时用 S5 的200元准备两笔200元现金退款 | 最多一个有效冻结/退款单成功；另一笔失败或返回冲突，不超出账户/来源退款预算 |
| SC01-CASE11 | S6 后确认已付超时，再提交同一执行身份 | 查询实际提交结果，最多一笔200元现金退出；实际已付款而结果不确定时不自动再付款或解冻 |
| SC01-CASE12 | S6 取消尚未支付的退款单；已支付或待核实则尝试取消 | 未支付可取消并恢复可用200；已付/待核实拒绝普通取消，不删除资金历史 |
| SC01-CASE13 | 跨租户、同租户越学校/部门范围、字段无权或权限撤销 | 查询/聚合/方案/提交/历史结果均按当前权限拒绝或过滤；不泄露他人存在性和敏感字段 |
| SC01-CASE14 | 同一主例经页面接口、测试中的第二入口执行 | 鉴权、校验、确认/审批、金额/课时、事务和审计结果一致，无需模型或页面状态才能正确 |
| SC01-CASE15 | 锁月与关闭/退课时/现金记账发生竞争 | 期间保护协议保证不回写锁定历史；拒绝或按已确认调整规则处理，不为了首片任意把日期移到下月 |
| SC01-CASE16 | 同一源快照/旧ID重复装载及装载中断重跑 | 不重复创建学校/档案/报名/期初资金；依赖、累计/本次字段和差异可追溯；无真实快照时不得宣称迁移通过 |
| SC01-CASE17 | 成功业务提交后报表投影/通知失败 | 权威事实可查询且可重建非权威投影，持久事件可恢复；失败提示不诱导再次收/退款 |
| SC01-CASE18 | 合成输入含任意tenantId、余额、确认/审批布尔，或金额为JSON数字 | 不接受调用方自造权限/余额/批准；公开金额遵守十进制字符串契约，服务端计算权威值 |

## 6. 样例与旧数据装载

主例是人工基准；将来可用它准备新系统测试数据，但不能标成已导入旧库数据。装载另需定位现有材料/只读环境中的合适来源，记录快照与映射、来源ID、规则、历史/在读边界和数值对账。本轮已核验源码，未定位并验收一套可直接作为 R5 迁移输入的在读快照，不据此推断所有材料都缺失或要求用户重发。

源字段按表分别解释：旧退课时单为本次发生量，课程/报名汇总的已退字段为累计量，见 SC01-E07；不得用“所有退费值均累计”的简写做通用增量导入。装载期初与首次业务发生分开，禁止把期初已收款再次执行一遍收款命令。

## 7. 完成与剩余边界

文档交付完成不等于 SC01 业务完成。只有主例逐阶段、相关失败/并发/权限、来源对照及两个入口的实际结果均有证据，才能提交首片验收；正式 P0 仍包括所有模式、单/多班自动排课、团培、跨月与其余已批准功能。审批配置、特殊舍入/尾差、复杂缺勤及恢复等不能从本例外推默认规则。
