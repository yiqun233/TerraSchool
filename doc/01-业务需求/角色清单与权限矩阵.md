## 1. 目的与范围

本文档回答两个问题：

1. 旧系统需要哪些岗位使用本系统；
2. 每个岗位在现有动作目录下应配置哪些功能动作，以及哪些数据范围无法表达。

本矩阵只定义**功能权限**（动作）。数据范围仍由账号/角色分配时的学校决定，不随模板生成。模板是一次性起点：生成后即普通角色，可继续增删动作，不绑定模板、不随后续模板调整同步。

本文档不覆盖：校区/部门/渠道/团队数据范围、学员/家长登录端、字段级逐字段配置、模板版本管理。

## 5. 生成规则

1. 用户在「维护角色模板 → 新建角色」选择「从模板生成」，选一个模板，确认名称与代码后生成；名称/代码默认取模板值，允许修改。
2. 角色代码是租户内唯一、创建后不可改的稳定标识；模板代码只是默认值。已存在同代码角色时返回 `ROLE_CODE_EXISTS`，不覆盖、不静默复用；用户改代码或打开已有角色。
3. 同一模板可用不同代码生成多个角色；模板本身不消耗。
4. 同一 `requestId` 重复提交返回第一次生成的角色；换参数返回 `ROLE_REQUEST_MISMATCH`。
5. 生成不自动分配给任何账号；角色必须按学校分配给账号后生效。
6. 生成后即普通角色：可改名、增删动作、停用/启用；保存走现有版本冲突与最后管理员保护。
7. 模板是一次性快照：不绑定模板，不记录来源模板代码，不随后续模板调整同步；不做模板版本。
8. 生成与角色创建审计同事务；失败整体回滚。
9. 权限沿用现有角色维护：`AUTHORIZATION_MANAGE` + 可管理学校范围；零学校的租户管理员也可生成。

## 6. 已知缺口

| 缺口 | 影响 |
| --- | --- |
| 数据范围只有学校 + 客户本人 | 校区、部门、渠道、下属团队维度无法表达；市场不能按渠道限定客户，课程顾问主管看不到团队客户/业绩，教务不能按校区隔离 |
| `REFUND_READ` 无独立校验点 | 已从财务模板移除；目录里仍保留，自定义角色配了也不生效 |
| 教师 `TEACHING_READ` 不能只限本人 | 教师能看到全校班级、课次与学员名单；本人课表接口存在，但同一动作同时打开全校列表 |
| 新建学校不自动扩展给其他账号 | 建校只给创建者铺动作；其他已分配角色的账号需要重新分配学校（租户管理员动态全量除外） |
| 角色不承载数据范围 | 模板生成不替用户选学校；学校范围仍在账号分配上 |
| 字段级只有动作级 | 敏感字段以 `STUDENT_SENSITIVE_READ`、`CUSTOMER_PHONE_READ` 控制，不能逐字段配置 |
| 学员/家长无登录端 | 两类使用者当前没有账号体系与入口 |
| 模板无版本 | 以后修改模板定义只影响新生成角色，已生成角色不追溯 |
