## 1. 方法与边界

针对已确认首片，定位报名/支付分配、关闭结算、退课时、退到账户和现金退出路径，直接读取 UTF-8 参考源码。下表路径统一相对于 `参考资料/analysis-v2/src-utf8/`，为准确证据位置，不是新代码目录；原材料未修改、未复制进版本库。旧材料本身被 Git 忽略，另一台机器须另行取得参考材料后才能核对这些路径。

只读核验能证明代码分支、单位和事务结构，不能证明某客户的当前配置、线上行为、最终库结构或实办结果。未登录旧环境提交业务、运行旧 SQL/源码或导入真实数据；人工金标准的确认来源另在样例文档记录。

## 3. 需要保留的业务事实

1. 报名履约、实际收款、资金分配是不同事实；即便某页面组合办理，也不能把三者缩成一个金额字段。进班/课次/消费必须关联具体报名，不只关联学员。
2. `CSItemClose` 先约束已确认课次，再在一个 Session 事务里写关闭、结算更新和轨迹；`FSettlementDBUpdater` 区分初次固化和后续差额。目标保持强事务及固化边界，不照搬旧“删后插”作为不可追溯改历史的许可。
3. 模式1使用总价减优惠除总购买课时；模式4改用退费后的实际金额/课时，不能混用。首片无优惠、无历史消耗/退款、非末课，避免从这个简单案例推断复杂尾差。
4. 退课时/费用减项不等于账户资金已退出。旧处理可退原分配到账户，也有配置驱动的自动组合现金退出；用户本轮明确选择首片保留两个步骤，不能反向声称旧系统只允许分两次。
5. 现金退出路径检查可用余额和费用/定金性质，按学校配置要求审批；不能因为用户确认例子就跳过实际适用的审批。

## 4. 累计值与本次发生量：修正历史摘要

旧研究曾简写“退费的课时/金额是累计值，不是本次值”。精确到源码，该表述只适用于课程/报名汇总的已退字段，不能套用每张退费单：

| 位置 | 语义 | 证据 |
| --- | --- | --- |
| `QuitFeeProcessor` 的 `csHourCurQuit / feeCurQuit` | 当前请求本次退量/费用 | 446–447初始化，513–514累加本次值 |
| `addStudentRegisterQuitFeeRecord` 写退课时单 | 保存本次发生量；参数名虽有 total，但调用传入本次变量 | 1002调用，1556–1570落单；课程明细1600附近同样写本次退量 |
| `updateStudentRegisterCurricula` 的 `CS_HOUR_QUIT / FEE_QUIT` | 历史累计 + 本次发生量 | 1637–1638显式相加 |
| 报名消费汇总的 `FEE_QUIT` | 当前累计汇总，不能作为下一次增量再追加 | 课程与各退费单汇总路径，退费/撤销后更新累计 |

迁移需要逐字段标明增量/累计、来源、单位和已有入账范围。例如已退2课时后新退1课时，应新增本次1并得到累计3；不是新增3。目标可以从不可重复的发生单据重建累计，但必须识别旧快照是否已包含历史结果，不能同时导入期初累计又重放同一历史单据。

## 5. 主例算术推导与单位

用户确认的合成样例没有折扣、服务费、额外费用、既往退量/历史消耗、超排或末课尾差。以下仅为源码分支的手工推导，不是运行旧代码的结果：

- Money、CSHour 的旧倍数均为100；1000元对应100000分，10课时对应1000单位。`ConfigManager.getCSHourMinutes()` 当前返回60；其旧注释中的可配置读取已注释，不能作为当前运行证据。
- 模式1：`fee=总价格-优惠=100000分`，`csHour=总课时=1000单位`，本节分钟60。`FClassStudent` 先算 `100000×100×60÷1000=600000`，再除60舍入到10000分、乘60保存为消费EHM。因此该课次对应100元，旧EHM到元须除6000。
- 普通按课时退费：本次2课时为200单位，单课程价格/总价均为100000分。`200×100000×100000÷(1000×100000)=20000分`，即200元。不是末次全退，也没有自定义退款额，因此不走相关特殊分支。
- 源码上述路径使用 double 再舍入；目标已确认用精确小数，不能照搬二进制浮点。此例结果整除，不能据此认定所有半分、尾差、负数/冲正或模式4/5已经等价验证。
- 退2课时后约定总购买仍为10、累计已退2、实际已消耗1，剩余7；有效应收800、分配释放后800、账户200。现金退出另记200后账户0、净收支800，不能把两个200元同时当作两次应收减项。

`StudentRegisterDictionary` 的“800/50=160”注释和其他尾差“5元”注释与算式/常量不一致，仍保留为后续复杂金标准问题；本次不借简单样例替这些冲突下最终业务结论。
