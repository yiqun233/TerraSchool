## 0. 一页结论

旧系统的"排课"不是一个页面，而是**一组围绕课次的工作台**：

1. **班级工作台**：搜索/打开多个班级 → 网格课表 → 加课次 → 拖拽调整 → 冲突检测 → 发通知 → 发布/确认。
2. **服务端可行性网格**：拖拽前一次性算出"整个课表每一格能不能放"，前端只负责染色，因此拖拽时底色变化是即时的、整屏的。
3. **冲突是分级的**：本班占用 > 学员冲突 > 教师/教室冲突 > 教师空闲 > 教室空闲，优先级写死在服务端，前端不重复判断。
4. **调课有方案**：先试同班/已打开班内交换，交换不成就搜"链式方案"（A→B→C），列出步骤，选中后批量执行并给教师发通知。
5. **发布/确认/关课分离**：排课只管排；确认课次（csconfirm）管上课事实；财务关闭（settlementprocess）管收入固化。

对新系统的判断：**业务语义可以复刻，数据底座还缺 4 块**——班可多课程、课次挂课程、班级挂校区与起止日期、教师可授课程（含课时换算规则与校区距离）。UI 侧则整块缺失（无网格课表、无拖拽、无方案）。

## 1. 复刻范围与判定标准

### 1.1 做什么

| 范围 | 说明 |
| --- | --- |
| 班级模式排课 | 主入口：打开 1–N 个班，同屏网格排课 |
| 课次增删改 | 加课次（单天/日期段/按周几/模板时段）、删课次、改时段、平移时段、备注 |
| 拖拽调课 | 拖动课次到空格或与其他课次交换，实时绿/红可行性 |
| 冲突检测 | 15 类冲突，含教师、教室、学员、班级休息日、距离 |
| 调课方案 | 同班/已打开班内交换 + 链式换课方案，批量执行 |
| 课表视图 | 班级课表、教师课表、学员课表（不同角色看不同维度） |
| 发布/确认 | 课次发布、确认上课、批量确认 |
| 关课与收入 | 关课生成课时消费（现有能力，需与课次课程对齐） |
| 通知 | 调课后给受影响教师/学生发通知（首版可只落站内信/审计） |

### 1.2 不做什么（首版）

- 跨校区报名与上课（用户已明确：初版一个校区报名即在该校区上课）。距离冲突的表与判定接口保留，默认同校区距离 0。
- 自动排课（旧 `SCIACSItemAutoArrange`/`MCIACSItemAutoArrange`）——已有 [排课算法与行为证据](./排课算法与行为证据.md)，不在本次复刻范围。
- 教室排课的图形拖拽（iapk_room 的 `RoomArrangeGraphPanel`），首版只做教室占用校验。
- ClassIn/外部系统回写、赠送课次、赔偿处理、在线课堂标记。

### 1.3 "完美复刻"判定

不是像素级一致，而是：**同样的操作能得到同样的结果与同样的拒绝理由**。具体到 6 条：

1. 打开班级后能看到与旧系统同构的网格（行=班级×时段，列=日期）。
2. 加课次能按"日期段+周几+时段"批量生成，并受班级起止日期约束。
3. 拖拽时整屏底色随目标位置变化，绿色可放、红色冲突，松手前即可预判。
4. 冲突能定位到"哪两节课、什么原因"，并给出冲突详情列表。
5. 交换做不成时能给出链式方案（旧系统上限：5 步、20 个方案），方案可预览步骤、可批量执行。
6. 排完能发布、确认、关课，收入按"哪个孩子在哪个班上了哪节课"生成。

## 2. 用户操作闭环

```
搜索/打开班级（可多选）
  → 设置班级课程 + 授课教师 + 课时计划（若未设）
  → 添加课次（批量：日期段 × 周几 × 时段）
  → 拖拽微调 / 右键改教师、改教室、改课程
  → 冲突检测（全班/全校）→ 冲突详情 → 修复
  → 搜索调课方案（交换/链式）→ 执行 → 发通知
  → 发布课次 → 确认上课 → 财务关课 → 生成课时消费
```

对应旧系统模块：

| 环节 | 模块 |
| --- | --- |
| 排课 | `iapk`（本规格主体） |
| 教室视图 | `iapk_room` |
| 全校冲突 | `clashcheck` |
| 开结课日历 | `classcalendar` |
| 课次确认 | `csconfirm` |
| 关课/结算 | `settlementprocess` |

### 3.2 课表网格

**行列表头**（`MultClassCSTableModel.java:119-164`）：

- 列 = 日期（`TDate[]`），表头显示"日期(周几)"，并在日期后蓝色显示当日已排课次数。
- 行 = 班级 × 分钟段。时段来自**学校常用时段**（`H_School_Minute_Space`，学校级唯一模板，班级不单独持久化自己的模板）；"自定义时段"只是客户端本次操作的全局扩展，不落班级配置。班级之间画分隔线，分隔行显示班级 SN。
- 一个班没有可用时段时，仍保留一行（用于提示）。
- 比例绘制模式下行高按分钟数比例分配，否则等高。

**单元格内容**（`CSItemTableCellRenderer.java:247-390`）：

- 课程名 / 教师名（可含辅助教师）/ 教室名 / 备注 / 学员或班号，按"显示模式"勾选决定显示哪几项。
- 角标：`赠`（免课时）、`赔[学员x%;教师y%]`（补偿）、锁图标（锁定，不可拖）、在线标记。
- 一格多节课次时纵向堆叠，用彩色分隔线区分。
- 空格：若该格可放置，显示带边框的浅色空面板（"可放"提示）；当前选中格额外描边。

**显示开关**（`SingleMACSEditorPanel.java:249-251`）：

- 比例绘制模式 / 全时段模式 / 全日期模式。
- 显示全部 / 仅工作日 / 仅周末 / 自定义显示（`MACmd.java:228-232`）。
- 课表显示模式面板（`CSItemShowModePanel`）：班级、课程、教师、教室、学员、备注 六项任意组合。

**交互**（`SingleMACSMouseListener_GraphMode.java`）：

- 左键在空白处拖动 = 矩形框选（框选多个课次，批量操作）。
- 左键在课次上拖动 = 移动/交换。
- 右键 = 上下文菜单（按点击位置给出不同命令：空格给"添加课次"，课次给"删除/改教师/改教室/换课程/冲突详情"）。
- 拖拽中显示课次残影，鼠标变手型；松手前不落库。

## 4. 添加课次

入口：工具栏"添加课次"（`SingleMACSItemOperator.java:86-137`）→ `ClassCSItemDialog`（"添加班级课次"）。

对话框结构（`ClassCSItemInfoPanel`）：

| 控件 | 默认 | 规则 |
| --- | --- | --- |
| 班级列表（左） | 当前打开班级 | 可多选，一次给多个班生成同样的课次 |
| 单天 / 日期段 | 日期段 | 单天只生成一天 |
| 周一~周日 | 全不选 | 至少选一个；只在这些星期生成 |
| 学校常用时段 | 选中 | 多选；来源 `H_School_Minute_Space` |
| 自定义时段 | 空 | 文本框，`08:00-10:00;10:00-12:00`，分号分隔，可跨中午 |
| 日期范围 | 班级起止日期 | 不得早于开班、不得晚于结班；跨度 ≤ 2 年 |
| 包含节假日 | 不勾 | 勾选后跳过学校节假日/班级休息日 |
| 自动算课次数 | 勾选但隐藏 | 由"按课时计划生成"入口打开，按剩余课时反推次数 |

生成规则：

- 对每个"日期 × 时段"生成一个课次；已存在同班同时段课次则跳过。
- 生成后立刻做一次冲突检测：教师未排、教室未排的课次允许存在，标记"未排教师/未排教室"。
- 成功提示："添加【N】个课次成功！"；失败部分列出原因（`CopyWeekCSItemErrorReportDialog` 同款报告表：日期、时段、课程、教师、失败描述）。

其他批量入口：

| 入口 | 作用 |
| --- | --- |
| 平移日期展开课次（`ExtendCSItemByDateDialog`） | 把已排课次按周/按天整体平移到后续日期 |
| 从其他班导入课表（`ImportOtherClassCSDialog`） | 复制另一个班的课表结构（课程/教师/教室可选择性带入） |
| 复制当前课表到下周（`ThreadCopyOneWeekCSItem`） | 一周一周复制，失败出错误报告 |
| 时段选择（`WeekAndMSDialog`） | 周几 × 分钟段网格，"选择所有时段/取消时段选择" |

## 5. 拖拽与实时可行性

### 5.1 服务端一次算整屏

拖动开始时，客户端把"源课次 + 目标区域"发给服务端，服务端返回 `TMoveScheme`：**行=日期，列=统一的分钟段**，每格一个状态码（`CSItemMoveProcessor.java:38-121`）。

- 分钟段以源课次时长为准，对目标区域的时段做截断/补齐（`formateMinuteSpaceToSameLength`），按起始分钟去重。
- 因此"整屏底色"是一次请求的结果，不是每格发一次请求。

### 5.2 状态与颜色

| 状态码 | 含义 | 前端表现 |
| --- | --- | --- |
| `STATUS_FREE` | 可放 | 绿（(192,255,192)） |
| `STATUS_HAS_CS_ITEM_OCCUPIED_IN_CUR_CLASS` | 本班已有课次（含最小课间缓冲） | 红/深红 |
| `STATUS_HAS_CURRICULA_CLASH_FOR_STUDENT` | 学员冲突或班级休息日 | 红 |
| `STATUS_HAS_CURRICULA_CLASH_FOR_ROOM` | 教室冲突 | 红 |
| `STATUS_HAS_CURRICULA_CLASH` | 教师冲突 | 红 |
| `STATUS_OTHER_CLASH` | 其他 | 灰/黑 |

判定顺序（`CSItemMoveProcessor.java:232-267`，先命中先返回）：

1. 本班其他课次占用（含班级最小课间 `PKCSItemSpaceControl_MinSpaceMinute`）
2. 学员冲突 / 班级休息日
3. 教师或教室课程冲突（两者都有则归教师）
4. 教师时间轴不空闲
5. 教室时间轴不空闲
6. 否则可放

### 5.3 可拖/可交换的前置条件

`SwapCSItemQuery.getCanSwapTeacherOrCanMoveToPositionBoxInClass`（`SwapCSItemQuery.java:53-210`）：

- 只在本班（或当前打开的班）范围内。
- 自己不能拖给自己；教师、课程、教室完全相同的两节课不交换（没有意义）。
- 目标时长必须与源课次相同（不支持拖拽改变时长，改时长走"修改时段"）。
- 不能移到"昨天以前"（历史课次只读）。
- 锁定课次、有赔偿标记的课次不可拖（`MultClassCSTableModel.isCanSwap`）。
- 交换教师时，把双方教师对调后**双向**再验一次冲突，两边都干净才算可交换。

### 5.4 拖拽后的落库

- 单格移动：改课次日期/起止分钟。
- 两格互换：原子交换两个课次的时段（教师/教室随课次走，或按"交换教师/交换教室"命令只换资源）。
- 批量：框选后"整班交换教室""全课程交换教师"等。
- 每次操作写操作日志（`ViewLogCSChangeDialog`），可追溯"谁在什么时候把哪节课从哪挪到哪"。

### 6.2 检测主流程（`AllClashCheck.java:344-600`）

1. 按日期逐天取当天全部课次（ownerItems），并预取：教师活动、教师休假、其他系统占用、教室预定、教室位置占用、教室生命周期、教室座位数、班级休息日。
2. 只有勾选了"学员冲突/学员距离"时才去取"课次-学员"关系（性能考虑）。
3. 对每对课次调 `ClashCheckProcessor`：`isClashForTeacher` / `isClashForRoom` / `isClashForStudent`，返回是否冲突、是否"距离原因"。
4. 用 `ClashReasonsBuilder` 把布尔结果翻译成冲突码数组，挂到 `TClashCell`。
5. 再逐项追加单元格级冲突（活动、休假、教室生命周期、座位数、班级休息日等）。
6. 冲突数超过 500 条即停止并标记"溢出"，避免整校检测拖死。
7. 结果按"班型-冲突类型"配置排序和配色（`PK_ClashCheckList`），前端红/黄区分。

### 6.3 距离冲突的真实语义

不是"时间重叠"，而是：**两节课之间的空档 < 教师从 A 校区到 B 校区的路程分钟数**。

- 路程来自 `H_Area_Distance(Area_A_Code, Area_B_Code, Minutes)`，双向查表，缺省 0。
- 同时还有两个系统参数：教师课次最小间隔 `PKTeacherCSItemSpaceControl_MinSpaceMinute`、同班课次最小间隔 `PKCSItemSpaceControl_MinSpaceMinute`。
- 首版单校区时距离全为 0，这条规则自然不生效，但**表结构与判定位置要留好**，否则以后加校区要动冲突引擎。

### 6.4 冲突详情与"为什么不能排"

- 客户端"冲突详情"弹出列表：冲突课次、冲突对象、冲突原因（可多因）、解决方向。
- 录音里负责人强调"能指出哪两节冲突并给解决方向"，对应旧系统就是这张列表 + 右键"改教师/改教室/换时段"。
- 全校冲突中心（`clashcheck`）可按学校/班级/教师/教室/日期区间巡检，导出 Excel 给教务。

## 9. 旧系统的数据模型（复刻所需的八张表）

```
H_Class ──1:N── H_Class_Curricula ──N:M── H_Curricula（课程）
   │                └─1:N─ H_Class_Curricula_Teacher（每门课的授课教师）
   ├─1:1── H_Class_Product（班最多一个产品）
   ├─1:N── H_Class_CSHour_Plan（按日期段的课时计划）
   ├─1:N── H_CS_Item（课次：日期+起止分钟+课程+教师+教室+7 个状态位）
   │           ├─1:N── H_CS_Item_Teacher（多教师）
   │           └─1:N── 学员报名（通过班-报名关联）
   └─1:N── H_Class_Schedule_Item（排课模板条目）
H_School_Minute_Space（学校常用时段）
H_Area_Distance（校区距离）
H_School_CSHour_Rule_Student_Consume / _Teacher（分钟→课时换算规则）
```

关键字段（摘）：

- `H_Class`：School_Code、Area_Code（可空）、Begin_Date/End_Date、Max_Student_Count、Status。
- `H_Class_Curricula`：Class_Code、Curricula_Code、CS_Hour、Price、Department_Code。
- `H_CS_Item`：Class_Code、Date_Stamp、Begin_Minute、End_Minute、Curricula_Code、Room_Code、Teacher_A/B_Code、Is_Locked、Is_Audited、Is_Confirm、Is_Closed、Is_Has_Compensation、Minutes_Class/Student/Teacher。
- `H_Student_Register`：School_Code、Area_Code（报名校区）、Area_A/B_Code（上课校区）、Class_Begin/End_Date、Seller_A/B/C。
- `H_Teacher_Curricula`：教师可授课程 + 课时薪资；`H_Teacher_PK_Area`：教师可排课校区；`H_Teacher_Share_School`：跨校共享。

设计含义：**旧系统"课时"不是课次属性，而是三份分钟数**（班级/学员/教师），再用规则换算成各自的 CS_Hour。这解释了录音里"45 分钟/1 小时/半小时影响课时消耗"。

### M1 数据底座（后端为主，1 个迭代）

> **实施状态（2026-11-25）**：已完成，见 [V91__scheduling_foundation.sql](../../backend/applications/server/src/main/resources/db/migration/V91__scheduling_foundation.sql)。与下方草图的差异：新表统一用 `(tenant_id, id)` 唯一键并启用 FORCE RLS；`class_curriculum` 暂不带 `version`（首版无并发编辑）；`lesson.curriculum_id` 直接 `SET NOT NULL`；`hour_rule` 未建（课次时长已由 `lesson.hours` 表达，分钟折算等 M3 再加）。

```sql
-- 1) 班级课程：班可多课程，每课程独立课时/价格
CREATE TABLE teaching.class_curriculum (
  id uuid PRIMARY KEY DEFAULT uuidv7(),
  tenant_id uuid NOT NULL, class_id uuid NOT NULL,
  curriculum_id uuid NOT NULL,
  hours numeric(10,2) NOT NULL DEFAULT 0 CHECK(hours >= 0),
  price numeric(14,2) CHECK(price >= 0),
  version bigint NOT NULL DEFAULT 0,
  UNIQUE(tenant_id,class_id,curriculum_id)
);

-- 2) 班级校区与起止日期（校区必填，按"单校区报名即单校区上课"）
ALTER TABLE teaching.class ADD COLUMN campus_id uuid;
ALTER TABLE teaching.class ADD COLUMN begins_on date;
ALTER TABLE teaching.class ADD COLUMN ends_on date;
CHECK (begins_on IS NULL OR ends_on IS NULL OR begins_on <= ends_on);

-- 3) 课次课程（排课时必选；与班的课程集合做约束）
ALTER TABLE teaching.lesson ADD COLUMN curriculum_id uuid;

-- 4) 课次多教师
CREATE TABLE teaching.lesson_teacher (
  lesson_id uuid NOT NULL, teacher_id uuid NOT NULL,
  role varchar(10) NOT NULL DEFAULT 'MAIN' CHECK(role IN ('MAIN','ASSIST')),
  PRIMARY KEY(lesson_id, teacher_id)
);

-- 5) 教师可授课程
CREATE TABLE organization.teacher_curriculum (
  tenant_id uuid NOT NULL, school_id uuid NOT NULL,
  teacher_id uuid NOT NULL, curriculum_id uuid NOT NULL,
  hour_salary bigint,              -- 旧系统有，首版可空
  PRIMARY KEY(teacher_id, curriculum_id)
);

-- 6) 学校常用时段
CREATE TABLE teaching.school_minute_space (
  tenant_id uuid NOT NULL, school_id uuid NOT NULL,
  id uuid PRIMARY KEY DEFAULT uuidv7(),
  begin_minute smallint NOT NULL CHECK(begin_minute >= 0 AND begin_minute < 1440),
  end_minute smallint NOT NULL CHECK(end_minute > begin_minute AND end_minute <= 1440)
);

-- 7) 课时换算规则（分钟区间 → 课时）
CREATE TABLE teaching.hour_rule (
  tenant_id uuid NOT NULL, school_id uuid NOT NULL,
  id uuid PRIMARY KEY DEFAULT uuidv7(),
  audience varchar(10) NOT NULL CHECK(audience IN ('STUDENT','TEACHER')),
  priority int NOT NULL DEFAULT 0,
  minutes_min int NOT NULL, minutes_max int NOT NULL,
  cs_hour numeric(10,2) NOT NULL,
  CHECK(minutes_max >= minutes_min)
);

-- 8) 校区距离（首版可空，判定位置先留）
CREATE TABLE organization.campus_distance (
  tenant_id uuid NOT NULL, school_id uuid NOT NULL,
  campus_a uuid NOT NULL, campus_b uuid NOT NULL,
  minutes int NOT NULL CHECK(minutes >= 0),
  PRIMARY KEY(tenant_id, campus_a, campus_b)
);
```

回填与兼容：`class.curriculum_id` 保留为"主课程"，迁移期间与 `class_curriculum` 双写；新代码读 `class_curriculum`。**不做旧版兜底分支**，迁移脚本一次性回填，回填失败的班在启动检查里报错。

## 15. 与首轮 P0–P4 的关系，以及第一批做什么

### 15.1 两套编号不是两批工作

- 首轮 **P0–P4** 是按"先能看见、再能拖、再能搜方案"排的**粗阶段**（演示数据与贯通 → 只读课表 → 拖拽 → 方案与冲突收尾）。
- 本文 **M1–M7** 是把同一条排课线拆成**可独立验收的 7 段**，粒度更细、依赖关系明确。
- 结论：M1–M7 **全部是排课相关**；P0–P4 不是"M1–M7 之后再做"的另一批，而是被 M1–M7 吸收和细化。

### 15.2 对应关系

| 首轮粗阶段 | 对应 M | 说明 |
| --- | --- | --- |
| P0 演示闭环（种子数据 + 报名→进班→排课→考勤→关课打通 + 提示） | M1 前置 + M2 的一部分 | 不建数据底座，演示数据也没有"班多课程/课次课程"可展示 |
| P1 只读周课表 | M2 | 第一个能给人看的界面 |
| P2 拖拽调课 + 可行性格子 | M4 + M5 | 拖拽前必须先有可信的冲突判定 |
| P3 链式换课 + 通知 | M6 | 依赖 M5 的可行性网格 |
| P4 冲突中心/多角色视图/收尾 | M4/M6/M7 的延伸 | 独立冲突中心、教师/学员/教室视图可分批后置 |

### 15.3 第一批（"最重要的先做"）

按"能演示、能验收、不返工"三条同时满足来切，第一批只做三件：

1. **M1 数据底座**：`class_curriculum`、`class.campus_id/begins_on/ends_on`、`lesson.curriculum_id`、`teacher_curriculum`、`school_minute_space`、`hour_rule`。这是后面所有东西的地基，晚做一步就要多改一轮。
2. **演示种子数据**：一所学校、两个校区、4 门课程、1 个"暑期冲刺班"（数学+英语+物理+化学）、1 个单课班、若干学员/报名/课次，直接写进 `tools/dev/seed.sql`。让负责人登录后**第一眼有东西可点**。
3. **M2 只读课表**：教务下新增"排课"入口，行=班级×时段、列=日期，能看课程/教师/教室/学员数，空态说明原因。

M3 之后按 M 顺序推进；M4/M5 是体验分水岭，放在第二批；M6/M7 收口。

M2/M3 本轮的实现边界（避免与规格冲突）：

- **取数不新增课表总接口**：一周七天各调一次 `GET /api/teaching/reports/resource-daily-schedule`，避免每班 N+1；班课程/教师候选/教室候选/学校时段是 M3 新加的细粒度接口。
- **行是"班级×学校时段"**：时段来自 `teaching.school_minute_space`（学校级唯一，符合 Q88）；学校未配置时段时前端用三条兜底时段，落在模板外的课次进该班"其他时段"行。
- **候选教师/教室是服务端算好的**：按"选中课次时间 + 学校 + 课程"返回可用性与原因（已有课/不可用），对齐旧系统 `SetCurriculaDialog` / `SetRoomDialog`；最多三名教师的限制属于旧界面约束，首版未加。
- **发布不强制走审批**：`POST /lessons/{id}/publish` 只带 `expectedVersion`，符合 Q93“发布后可直接改、无门禁”。
