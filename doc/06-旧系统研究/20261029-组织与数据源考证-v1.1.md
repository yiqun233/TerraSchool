## 1. 结论

### 1.1 数据源形态

| 问题 | 考证结论 |
| --- | --- |
| 有没有“机构/租户”表？ | **没有**。DDL 中没有 `Tenant`、`Institution`、`Org` 之类的顶层表 |
| 机构身份存在哪？ | `Logo.xml`：`title`、`companyName`、`schoolType`、`serverCode`、`netSchoolName`、`CustomDevelopment type`；服务端启动时读入单例 `TLogo` |
| 一个库能否容纳多个机构？ | 从结构上不能可靠区分：业务表只有 `School_Code`/`Area_Code`，没有 `Tenant_Id`；品牌/授权/定制也只有一份 `Logo.xml` |
| 一个机构能否有多个学校？ | **能**。`H_School` 是一张表，`H_Area` 通过 `School_Code` 挂到学校 |
| 一个学校能否有多个校区？ | **能**。`H_Area` 就是校区（`AreaManager` 注释即“校区管理”），含地址、坐标、办学许可、营业执照等 |
| 用户是否跨租户？ | **否**。`H_Employee_User` / `H_System_User` 没有租户字段；同一手机号在不同机构是两套独立账号 |

因此：**迁移时“一个租户 = 一个旧库（一个 Logo.xml）”是合理默认**；如果某个客户历史上部署过多个库（例如总校/分校各一套），需要单独做合并方案。

### 1.2 组织层级

```
机构（一个部署 / Logo.xml）
└── 学校 H_School（财务主体：FC_Month、FC_Begin_Date、合同抬头、校长）
    ├── 校区 H_Area（1:N；教学点：地址、经纬度、办学许可、营业执照、合同模板）
    ├── 大区 H_Area_Group（对校区的可选分组，不是校区的子组织）
    └── 部门 H_Department（1:N；与校区平级，Parent_Code 可选；不强制属于校区）
```

> 2026-10-26 业务确认：学校下面有多个校区、也有多个部门，两个都是“学校→X”的 1:N 关系，彼此平级；不存在“校区下的部门”。

- `H_School`：学校/法人主体。字段含 `Code_B`（合同代号）、`Contract_Name`、`City`、`Schoolmaster`、`FC_Month`、`FC_Begin_Date`、`Is_K12`。财务锁月、收入归属、合同模板都按学校。
- `H_Area`：校区。字段含 `School_Code`、`Code_B`、`Short_Name`、`Address`、`Color`、`Is_Virtual`、`Longitude/Latitud`、办学许可证、营业执照、`Zone_Code`、`Group_Code`。
- `H_Area_Group`：大区，用于把校区分组（如“华北区”），不是每家都用。
- `H_Department`：部门，`School_Code` + `Parent_Code`（树形），另有 `Teaching_Item_Code`、`Leader_Code`、`Is_Partake_PR_Distribution`。**没有 `Area_Code`**，所以部门不是“校区下的部门”，而是“学校下的部门”；员工同时有 `School_Code`、`Department_Code`、`Area_Code`。
- `H_Employee`：员工，带学校、部门、校区；`H_Employee_Share_School`、`H_Teacher_Share_School` 支持员工/教师跨校共享。
- `H_Student`：学员只有 `Area_Code`（没有 `School_Code`）；报名 `H_Student_Register` 同时有 `School_Code`、`Area_Code`，所以“学员归属校区、报名归属学校/校区”是分开的。
- `H_Class`：班级同时有 `School_Code`、`Area_Code`。

### 1.3 用户模型

- `H_Employee_User`：`Code`、`User_Name`、`Password`、`Role_Code`、`Is_All_Data_Scope`、`Is_All_Channel_Type_Market`、`Is_All_Teaching_Item`；角色多对多在 `H_Employee_User_Role`。
- `H_System_User`：`Code`、`User_Name`、`Password`、`Is_Inner`。
- `UserSession` 只有 `sessionId/userType/userID/customerCode`，**没有 tenantId**。
- 数据权限表按 `School_Code`/`Area_Code` 配置，例如 `H_Employee_User_Data_Scope_School`、`H_Employee_User_Area_Data_Scope_School`、`H_Employee_User_Area_Data_Scope_Area`。

结论：**旧系统是“单机构多学校/校区”的部署模型，用户是机构内账号**。目标系统已确认用户为租户内独立账号；具体身份实现待设计。

关键点：`H_Department` 只有 `School_Code`/`Parent_Code`，没有 `Area_Code`；校区在 `H_Area`，两者是并列挂在学校下的组织单元。

### 2.2 代码证据

- `TSchool_Server_Config/.../config/LogoConfig.java:10-22`：`Logo.xml` 示例只有 `title/companyName/schoolType` 与 `CustomDevelopment`，没有机构列表。
- `LogoConfig.java:77-160`：`readLogo()` 读取单个 XML，设置 `serverCode`、`netSchoolName`、`webLogoImageUrl`、`CustomDevelopment.type`；`logoConfig` 是静态单例。**一个进程只有一份机构配置**。
- `AreaManager.java` 类注释“校区管理”；方法 `addAreaGroup` 管理大区。
- `SchoolManager.java`：`addSchool/updateSchool/deleteSchool`、`FC_Month` 相关配置、学校合同模板、学校课时转换规则。
- `DepartmentManager.java`：`addDepartment` 带 `Parent_Code`，挂学校。
- `UserSession.java:14-17`：只有 `sessionId/userType/userID/customerCode`，无租户。
- `H_Employee_User` / `H_System_User` DDL 无租户字段。
- `H_Employee_User_Data_Scope_School` / `..._Area_Data_Scope_School` / `..._Area_Data_Scope_Area`：数据范围按学校/校区配置。

### 2.3 与演示环境的一致性

- 登录页可选择“北京学校/上海学校”“河北大学/系统学校”，说明同一机构下有多个学校；学校选择器是数据权限/组织范围，不是租户切换。
- 两个测试账号看到的学校不同，更像“同一部署内的数据权限/角色差异”，而不是两个机构。此前分析也提示不能据此判断为两个租户。

## 3. 重启后的使用边界

默认一旧部署/源库对应一个机构，但需用最终结构和客户配置验证。客户多个旧库可能需要合并；一库多机构则需单独识别边界，不按学校编码猜租户。

学员归属校区与报名归属学校/校区分别保留；转校、转班不能覆盖历史。迁移保留旧编码、来源库身份和关系映射。财务锁月按学校，排课地点与跨校区距离按校区，部门用于归属、审批和业绩。

本文件不规定目标表名、字段类型、登录方式或密码迁移实现。完整源材料在参考资料内，特殊客户情形与真实生产分布必须另行验证。
