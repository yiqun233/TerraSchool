## 3. 覆盖到的行为

| 主题 | 结果 |
| --- | --- |
| 未配置策略 | 退课时 200 元直接通过（首版默认免审批，文档已标注生产必须配置） |
| 阈值生效 | 配置 100 元免批后：200 元无审批单返回 `APPROVAL_REQUIRED`；50 元免审批通过 |
| 申请与通过 | 申请单为 `PENDING`，审批后为 `APPROVED`；申请人不能审批自己的单据（服务层拒绝） |
| 一次性消耗 | 同一审批单第二次使用返回 `APPROVAL_ALREADY_USED` |
| 金额与报名必须一致 | 用 200 元审批单退 300 元、或用于另一报名，返回 `APPROVAL_MISMATCH` |
| 驳回不可用 | 驳回的审批单用于退费返回 `APPROVAL_NOT_APPROVED` |
| 重复待办 | 同报名同动作的第二张待审批单返回 `APPROVAL_ALREADY_PENDING` |
| 版本保护 | 过期版本审批返回 `VERSION_CONFLICT`；无审批权限的账号审批被拒 |
| 现金退款同样受控 | 配置 `CASH_REFUND` 阈值后，准备退款无审批单被拒；凭已批准单据成功生成 `PREPARED` |
| 策略版本 | 过期版本修改策略返回 `VERSION_CONFLICT`，正确版本保存后版本递增 |
| 租户隔离 | 跨租户写入策略被强制 RLS 拒绝（SQLState 42501） |
| 金额精度 | 退课时提交 3 位小数按无效输入拒绝，审批金额按两位小数比较 |

## 4. 本轮顺带修复的契约缺陷

多个模块的嵌套记录都叫 `SchoolOption`，SpringDoc 按简单类名合并，导致 OpenAPI 里只剩一份，前端类型因此把「审批能力」的学校列表推断成教学模块的结构。已把各模块的嵌套记录改为唯一名（`StudentSchoolOption`、`ProductSchoolOption`、`EnrollmentSchoolOption`、`FundsSchoolOption`、`TeachingSchoolOption`、`ApprovalSchoolOption`），重新生成契约后类型正确。

## 5. 测试稳定性调整

- 组件测试默认 5 秒上限在 18 个文件并行时会被机器负载吃掉，已在 `vitest.config.ts` 全局放宽到 20 秒，并把 Testing Library 异步查询超时设为 5 秒；断言内容未改。
- 早前两处单例超时改为全局配置后，不再逐个用例调整。

## 6. 限制与未覆盖

- 多级审批、审批人矩阵、审批时效与过期、撤销已通过单据：未实现。
- 转班、退班、延期、优惠、减款等其他固定审批类型：未接入（结构可扩展）。
- 审批通知、审批意见附件、「我的权限」展示 `APPROVAL_*`：未实现。
- **生产必须显式配置退费策略**，否则默认免审批；这是首版取舍，已在设计、README 与 AGENT 标注。
- 远程 GitLab Runner、生产初始化、密钥轮换与恢复演练仍不在本批范围。
