## 3. 追加探针与确认结果

共同样本复用既有 `SettlementModePricingTest.multiCourse`：语文 1 课时 200 元、数学 3 课时 1800 元，总价 2000、总课时 4；教师/教室保持既有测试的最小可用路径。仅在隔离副本的此测试类末尾增加以下三个方法，没有改动正式测试或业务代码。

| 探针 | 预期依据 | 实际 | 对应问题 |
| --- | --- | --- | --- |
| 模式 1 一节 4.50 课时 | 不应超过已购 4.00；拒绝或受控处理均不能记入超量消费 | 关闭成功，累计消费 **4.50**；断言 `<=4.00` 失败 | AUD-01 / REV-001 |
| 模式 2 连上两节语文各 1.00 | 已有设计为课程单价、报名总课时封顶；两节应为 **400.00**，总 4 课时未用完 | 累计仍 **200.00**，第二节被提前跳过 | AUD-01 / REV-001；该断言依据现行设计，Q40 继续确认复杂口径 |
| 同一 requestId 两次优惠 400 | 同请求只生效一次，净应收应 **1600.00** | 净应收 **1200.00** | AUD-02 / REV-002 |

复现代码（追加到既有测试类中）：

```java
@Test
void reviewLessonMustNotExceedPurchasedHours() throws Exception {
  var enrollment = multiCourse(1);
  consume(enrollment, CHINESE, "4.50");
  var result = asActor(OPS, () -> teachingQueries.reconciliation(enrollment.id()));
  assertThat(new java.math.BigDecimal(result.consumedHours()))
      .isLessThanOrEqualTo(new java.math.BigDecimal("4.00"));
}

@Test
void reviewModeTwoMustUseTotalHoursAsCap() throws Exception {
  var enrollment = multiCourse(2);
  consume(enrollment, CHINESE, "1.00");
  assertThat(consume(enrollment, CHINESE, "1.00")).isEqualTo("400.00");
}

@Test
void reviewDiscountRequestMustBeIdempotent() throws Exception {
  var enrollment = multiCourse(1);
  var request = new ApplyDiscount(UUID.randomUUID(), "400.00", "review duplicate");
  asActor(OPS, () -> enrollments.applyDiscount(enrollment.id(), request));
  var replay = asActor(OPS, () -> enrollments.applyDiscount(enrollment.id(), request));
  assertThat(replay.netAmount()).isEqualTo("1600.00");
}
```

隔离 `review_probe.py` 继续使用原验证脚本的临时库/角色准备、迁移和生成步骤，只把 Maven verify 参数改为：

```text
verify -Dtest=SettlementModePricingTest#review* -Dsurefire.failIfNoSpecifiedTests=false
```

探针先在隔离副本执行 Spotless 格式化，以免格式错误掩盖断言。Maven 因 3 个业务断言失败退出 1，验证脚本保存 failed 报告并清理临时库。新增三个探针未加入正式仓库测试；修复批次应将其整理为正式回归，确认超界的业务处置后同步断言。
