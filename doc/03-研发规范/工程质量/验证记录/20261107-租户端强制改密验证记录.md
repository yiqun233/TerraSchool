## 1. 为什么需要这一页

平台开通或重置密码后，账号处于「必须改密」状态。服务端已经把除会话自身以外的接口全部挡成
`403 PASSWORD_CHANGE_REQUIRED`，但业务端没有对应界面——客户登录后只会看到一片报错。
这一页把那条链路补完：**开通 → 交付 → 登录 → 改密 → 重新登录 → 进入工作台**。

## 2. 实现

| 文件 | 说明 |
| --- | --- |
| `shared/http.ts` | 新增 `changePassword`：带 CSRF 头提交；401 抛会话失效，400 原样展示服务端原因 |
| `features/identity/ChangePasswordGate.tsx` | 当前密码 / 新密码 / 确认新密码；两次不一致就地拦下；成功后交给调用方 |
| `features/organization/OrganizationPage.tsx` | `me.data.passwordChangeRequired` 为真时只渲染改密页；改密成功后清空会话并回到登录页，并给出“密码已更新，请用新密码重新登录” |

几个刻意的取舍：

- **不在前端判断权限**：是否必须改密完全以服务端权限快照为准，前端只读一个布尔值。
- **改密成功后不假装能继续用**：改密会递增凭据版本，当前会话必然失效，所以直接回登录页并说明原因。
- **错误不清空输入**：服务端拒绝（例如与新密码与登录名相同）时保留已填内容，便于就地修改。
