## 1. 前端测试门禁可复现

### 问题（实测）

同一份代码、同一台机器，两次全量运行结果不同：19:32 那次 96 项中 5 项失败，
19:42 那次 96 项全通过。逐项测量后定位到成本结构：

| 观测 | 数值 |
| --- | --- |
| 裸 React 组件挂载 / 查询 / 点击 | 15ms / 50ms / 37ms |
| antd `Table` 单次挂载（jsdom） | 约 1.0–1.7s（0 行数据也一样） |
| 整页教务工作台一次渲染 | 挂载 4 张以上表格，单用例 5–30s |
| `userEvent.type` 逐字输入 antd `Input` | 约 90–300ms/字符 |

即：20 秒用例上限与 5 秒异步等待窗口，对这种“整页 + 多表格”的用例只是薄薄一层余量，
机器负载稍高就会越过。不是断言错误。

```json
{"status": "passed",
 "checks": {"image_build": "passed", "db_init": "passed", "migrate": "host",
            "compose_up": "passed", "healthz": 200,
            "session_status": 401, "session_problem_code": "AUTHENTICATION_REQUIRED",
```

各检查证明的东西是分开的，不要合并成一句“通了”：

| 检查 | 只证明 | 不证明 |
| --- | --- | --- |
| `healthz` 200 | Nginx 进程活着 | 后端可用 |
| `/api/session/me` 401 + `AUTHENTICATION_REQUIRED` + `X-Trace-Id` | 请求经入口到达后端，且由后端安全过滤器返回 | 用户可登录 |
| 后端日志 `Started SchoolApplication` + 连接池 `Start completed` | 应用上下文与数据库连接建立成功 | 业务数据正确 |
| `schema_version == 源码最高版本（80）` | 库已迁移到位 | 迁移内容被业务验证 |

产物 `.local/deploy-smoke/5eef71d29cda/result.json`（最终文件上的复跑）。

过程中修掉的真实缺陷：PostgreSQL 18 起数据目录改为 `/var/lib/postgresql`，沿用
`.../data` 挂载会让容器反复重启；健康检查不能用 `/dev/tcp`（镜像 `/bin/sh` 是 dash）；
`add_header` 在 location 出现后会覆盖 server 级继承，因此缓存策略统一改用 `expires`，
安全头才能对所有路径生效；初版冒烟把 `/api/auth/session`（不存在的路径）当成功判据，
`anyRequest().authenticated()` 对任意路径都返回 401，证明不了什么，已改用真实端点并校验
问题码与追踪头。

### 录入状态下沉（行为级改动）

姓名与电话是页面上唯一“每敲一个字就变”的状态，放在主组件里会让本人客户表、公海表、提醒表
跟着重算。现在这两个输入的状态收进 `CustomerCreateFields`：主组件通过 `draft` 引用同步拿到
最新草稿，提交成功时改变 `key` 重挂载输入组件来清空，而不是把值再传回去。

`pending`、`notice`、`busy`、`guard` 仍留在主组件——查看电话、转公海、转派、合并、转学员
都要用它们，下沉会把共享语义拆成几份。因此这次只下沉逐字符输入，不动共享动作状态。

没有给面板加 `React.memo`：打字已经不再触发主组件重渲染，面板自然不重渲染；而分页、`busy`
这类切换传下去的回调每次都是新函数，加了 `memo` 也拦不住，要加就得同步补 `useCallback`，
属于收益很小的改动，本批不做。
