## 3. 结果

| 场景 | 结果 |
| --- | --- |
| 模式 4：100 课时 1000 元，退 50 课时退 200 元 | 净应收 800.00，上一节课 16.00 |
| 模式 4：随后一节上完剩余 49 课时 | 累计 800.00（尾差补齐） |
| 模式 4：净课时耗尽后继续上课 | 不再消耗，保持 800.00 |
| 模式 5：按课程退 50 课时退 200 元 | 课程净额 800/50，上一节课 16.00 |
| 自定义退费额 1200 元（剩余应收 1000 元） | `409 AMOUNT_EXCEED_REMAINING` |
| 模式 0 发布 | `409 SETTLEMENT_MODE_UNSUPPORTED` |

## 4. 旧帮助文本笔误

旧客户端示例写 `(1000-200)/(100-50) = 800/50 = 160 元/课时`，但 800 ÷ 50 = **16**。实现按公式计算得 16.00，并在测试与设计文档中标注该笔误，避免误判为程序缺陷。

## 5. 限制

- 模式 0（自动）需要班型判断，未实现；
- 优惠/折扣、服务费未参与计价；
- 缺勤按分钟计价、跨报名拼接与超排未实现；
- 前端"按课程退费"的下拉交互没有自动化测试（组件测试环境操作 antd Select 不稳定），由后端按课程退费的用例覆盖。
