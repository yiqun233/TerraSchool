## 问题与实现

用户反馈浏览器点击总览中的 Markdown 链接后看到原始文本。原页面直接指向 `.md`，浏览器没有 Markdown 排版能力；该行为不满足连续阅读需求。

生成器新增锁定版本的 `markdown-it-py` 渲染依赖，把 `doc` 下全部 Markdown 及根 README/AGENT 的排版正文、章节目录、源路径一起内嵌到原 HTML。默认文档链接转为阅读器路由；相对 Markdown 内链和章节链接继续在阅读器中打开，明确点击“查看 Markdown 源文”才访问原文件。阅读器没有 fetch、CDN 或服务端依赖；Markdown 原文仍是唯一维护依据。

所有内嵌 Markdown 内容参与指纹与 `--check`，修改非主台账文档后同样会提示总览过期。原始 HTML 禁用，代码围栏转义；Mermaid 保留代码，不加载外部脚本。文档索引使用 Map，未知路径及 `__proto__`、`constructor` 等片段进入未找到提示，不读取对象继承属性。

## 实际验证

- 生成与 `--check` 通过，主模块、细项、问题和任务数量不变。
- 浏览器从“问题登记”进入阅读器，标题、13 张表格、引用和强调正常显示；左侧目录可定位章节。
- 正文链接进入执行路线，浏览器后退回问题登记、前进回路线均正常；带章节刷新仍恢复对应文档，返回总览正常。
- 内嵌文档的 Markdown 内链和章节目标逐项核验存在；重复标题定向样例生成独立 ID，原始 HTML 与危险链接探针未产生可执行内容。
- 页面脚本语法、未知文档提示、总览原有筛选和生成物一致性通过；没有重跑业务后端或前端全套测试。

内置浏览器只允许 HTTP/HTTPS，本次浏览器验证使用本机临时静态服务；本地文件离线结构通过静态检查，未在内置浏览器绕过 file 协议限制。临时服务在本轮收尾停止。
