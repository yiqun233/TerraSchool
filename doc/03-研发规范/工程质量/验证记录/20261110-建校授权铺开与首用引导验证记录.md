## 1. 要解决的问题

新机构管理员建完第一所学校后，学员、报名、教务、财务全部 403。原因是建校只给创建者铺了 9 个动作
（组织、员工、教师、教室、授权管理），学员与业务动作一条都没有。这不是“权限没配好”，而是
建校流程本身少铺了一层；同一现象在本地被报成三条不同的问题（落到学员档案红字、教务菜单没权限、财务菜单没权限）。

## 2. 实现

| 文件 | 说明 |
| --- | --- |
| `backend/.../identity/api/PermissionCatalog.java` | 新增 `SCHOOL_PROVISION_ACTIONS`（目录内 48 个按学校动作）与空的 `SCHOOL_PROVISION_EXCLUDED`。显式列举而不按范围自动派生：新增敏感动作是否随建校授出必须逐次评审 |
| `backend/.../identity/internal/SchoolProvisioner.java` | 建校事务内改为按该集合铺开（原为 9 个动作的内联列表） |
| `backend/.../server/PermissionCatalogTest.java` | 新增门禁：任一按学校动作既不在铺开集合、也不在排除集合时失败；集合里不能有目录外或租户级动作 |
| `frontend/src/features/identity/PermissionConsole.tsx` | “开通学校”从权限页移除，只留组织目录一个入口；零学校时提示“先到组织目录开通第一所”并给跳转 |
| `frontend/src/features/organization/OnboardingGuide.tsx` | 补“学校建好之前业务菜单不可用”的说明与“先跳过”（只对本次访问有效，不落库） |
| `frontend/src/features/organization/OrganizationDirectory.tsx` | 跳过引导后正常加载组织目录，不再停在引导页 |

## 4. 限制与后续

- **存量学校不回溯补授权**：本次只改“新建学校”路径。已有机构里那些按旧规则建的学校仍只有 9 个动作，
  需要手工在“权限管理 → 账号与角色”授权，或新建一所学校验证新逻辑。批量补授权属于业务可见的数据变更，
  按既定原则不在产品迁移里做，只可在本地演示种子中处理。
- **起始角色模板未做**：文档第 5 节给出的是建议取值，且明确“具体动作集合在 P1 评审时确定”。
  直接实现等于把未确认的岗位矩阵写成事实，因此留待确认后再做。
- 未做浏览器人工走查（建校后菜单、引导跳过、权限页入口三处）。
