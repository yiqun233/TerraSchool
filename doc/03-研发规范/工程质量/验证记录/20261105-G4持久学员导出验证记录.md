## 实现内容

- 新增租户 RLS 保护的 `infra.student_export_task`，保存任务状态、请求摘要、原执行人会话版本、学校、文件内容、敏感字段清单、尝试次数、租约和到期时间。业务任务记录是请求与结果事实；db-scheduler 只定时派发，不直接读取业务表。
- 学员导出新增独立 `STUDENT_EXPORT` 学校动作，授权管理和角色模板可配置；学员查看权本身不足以导出。任务创建使用请求 ID 与参数摘要防重，重复同参返回原任务，任务只允许创建者查询、取消、重试与下载。
- 后台重新建立原账号身份并复核学校查看、导出动作和字段授权后生成 CSV。下载时再次复核当前学校查看、导出权限及文件生成时实际暴露的敏感字段；撤权后拒绝下载。
- 支持 `PENDING/RUNNING/COMPLETED/FAILED/CANCELLED/EXPIRED`。排队任务可取消；异常任务自动重试最多 3 次、失败后可手动重试最多 3 次；运行中的任务用租约恢复，旧 run token 不能覆盖新执行结果。文件到期后清空结果内容并标为 `EXPIRED`。
- 临时策略采用成功生成后保留 24 小时（配置范围 1～168 小时）、自动 3 次与手动 3 次重试、仅排队可取消。它们没有业务负责人确认，持续挂 Q63，不作为最终规则。
- 学员目录可创建任务、轮询状态、取消/重试、手动刷新进度并在完成后下载。原同步 CSV 入口仍存在，后续需迁移/淘汰计划和权限矩阵一并处理。
