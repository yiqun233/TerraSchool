# G4 预收款登记与报名分配初版验证记录

状态：预收款候选初版已接入并通过前端全量回归；是否作为定金的财务语义与退款、期间、票据口径待负责人确认（Q72），REV-010 未关闭。

## 实现范围

- 报名工作台按当前学校的 `FUNDS_RECEIPT` 能力显示“登记学员预收款”入口。
- 收款人从学员目录检索；客户端仅提供同校候选，最终学校/学员权限与财务期间由服务端校验。
- 登记实际收款后先形成学员账户可用余额，不虚构报名或课程课时；正式报名后复用现有收款分配流程抵扣该报名未收金额。
- 请求参数未变化时重试复用相同 `requestId`；超时、网络异常或 5xx 显示结果未知并保留请求身份，暂时关闭再打开窗口后仍可用原请求重试，防止重复记账。
- 现有分配服务继续校验收款人与报名学员一致、可用金额及报名未收金额；本轮未修改资金服务端规则。

## 验收边界

- 本初版使用现有“学员收款余额 + 报名分配”资金模型。Q72 尚未确认定金会计性质、正式报名转换时点、未报名退款/撤销、锁月/跨期和票据处理；这些未确认内容未伪装为财务结论。
- 收款登记的权限拒绝、锁月拒绝、同学员跨报名分配、余额/流水勾稽仍由已有后端测试及财务验收负责；本轮前端用例不替代后端并发或人工财务验收。
- 当前入口需要学员读取权限与收款权限；岗位权限矩阵待 Q55 确认。
