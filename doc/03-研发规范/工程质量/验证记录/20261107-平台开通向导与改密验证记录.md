## 1. 本次范围

平台运营端从“只读列表”补成“可完成一次开通”的最小闭环：

1. **开通向导**：两步——填机构名称与管理员登录名 → 展示一次性初始密码；
2. **重置管理员密码**：选租户 → 列出管理员 → 重置 → 一次性展示新口令；
3. **首次强制改密**：新租户管理员登录后只能改密，改完旧会话立即失效。

学校仍不在开通范围内，由客户登录后自建（DEC-024）。

## 2. 后端

| 变更 | 说明 |
| --- | --- |
| `identity.account.password_change_required` 参与权限快照 | `CurrentPermissions` 新增字段；强制改密期间只放行会话自身五个接口 |
| `POST /api/session/password` | 本人改密；校验当前口令、长度 ≥12、不得与登录名或旧口令相同、不得纯数字/字母 |
| `GET /api/platform/tenants/{id}/administrators` | 受控函数 `platform.tenant_administrators`，只返回登录名与状态 |
| `POST /api/platform/tenants/{id}/administrators/{login}/reset-password` | 受控函数 `platform.reset_tenant_admin_password`：置回强制改密并递增凭据版本；不传口令时服务端生成 16 位 |

改密的读写分离值得记一笔：**业务角色不允许读取口令散列**（既有安全不变量测试明确断言），
所以散列读取走身份连接、写入走业务连接；本轮先是给业务角色加了列级授权，被
`AuthorizationManagementTest.runtimeSqlHasTenantRlsAndCannotReadPasswordsOrChangeLogin` 抓出来并撤回。
