## 1. 本批做了什么

平台运营后台此前只有「租户管理」一页，侧栏的总览、开通记录、审计日志都是“即将开放”占位。
本批把这三页做成可用的只读能力，仍然守住 DEC-024 的边界：**平台只看到租户状态、规模与自己的操作轨迹，不读租户业务数据。**

| 页面 | 内容 | 动作 |
| --- | --- | --- |
| 总览 | 租户总数/正常/停用/本月开通、学校总数、账号总数、最近 5 条开通与审计 | `TENANT_READ`（摘要再按动作裁剪） |
| 开通记录 | 每次尝试一行：机构名、管理员登录名、操作者、成功/失败、错误码、完成时间；按状态与关键字筛选 | `PROVISIONING_READ` |
| 审计日志 | 时间、动作、操作者、目标租户、变更摘要、追踪号；按动作/租户/操作者/时间筛选 | `PLATFORM_AUDIT_READ`（本批新增） |

接口：

| 方法 | 路径 |
| --- | --- |
| GET | `/api/platform/overview` |
| GET | `/api/platform/provisioning-requests?page=&size=&status=&keyword=` |
| GET | `/api/platform/audit-events?page=&size=&action=&tenantId=&operator=&from=&to=` |

## 2. 迁移 V90

| 变更 | 原因 |
| --- | --- |
| `platform.provisioning_request` 增加 `tenant_name`、`admin_login` | 失败行没有 `tenant_id`，原来只存指纹与错误码，页面无法说明“谁失败了” |
| `provision_tenant` 同步写入两列 | 开通成功行也不靠反查，历史失败行保持为空、页面显示“—” |
| 动作目录增加 `PLATFORM_AUDIT_READ`，并从持 `TENANT_READ` 的账号派生授权 | 能看租户不等于能看全平台操作轨迹；升级后保留既有能力 |
| `audit_event(action, happened_at)` 索引 | 审计页按动作筛选 |
| `platform.tenant_totals()` | 平台角色没有业务表权限，学校/账号总数只能由受控函数返回两个数字 |

## 3. 一个顺手修掉的问题

开通成功时原来会写两条审计：`provision_tenant` 内写 `TENANT_PROVISIONED`（带 `tenant_id`），
接口层又写一条 `TENANT_PROVISION`（无 `tenant_id`）。审计页会把同一次开通显示成两行。
本批删除接口层那条，保留函数内的事务内记录。这是行为变化，已在测试中按「一次开通一条审计」断言。

## 4.1 过程中修掉的两个问题

1. **测试种子违反组织单元约束**：`organization.unit` 有 `CHECK(kind<>'SCHOOL' OR id=school_id)`，
   种子里漏了 `id`，第一次运行在 `@BeforeAll` 就失败。改为 `id=school_id` 后通过。
2. **Maven 依赖下载挂起**：首次定向运行停在 `archive` 模块的测试依赖解析，主线程停在 Aether 下载等待，
   20 秒 CPU 零增长。补齐本地仓库（沿用主工作区已缓存依赖）后一次通过；不是代码问题。

## 5. 边缘情况与测试清单

| 场景 | 预期 |
| --- | --- |
| 失败开通（登录名冲突） | 开通记录出现 `FAILED` 行，含机构名、登录名与 `ADMIN_LOGIN_TAKEN` |
| 迁移前的历史开通记录 | `tenant_name`/`admin_login` 为空，页面显示“—”，不报错 |
| 平台登录事件 | 审计页可见，目标租户为空 |
| 缺 `TENANT_READ` / `PROVISIONING_READ` / `PLATFORM_AUDIT_READ` | 分别 403；前端说明缺哪个动作 |
| 只读运营（无开通/审计动作） | 总览返回空摘要而不是报错或越权内容 |
| 非法 UUID、非 ISO 时间、起止倒置 | 400，响应不含 SQL 或堆栈 |
| 动作码未登记 | 原样显示动作码，不隐藏也不编造中文名 |
| 同名租户并存 | 列表与筛选按 id，不用名字当键 |
| 空库 | 三个页面都走空态，不报错 |
