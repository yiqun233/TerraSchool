## 3. SC01 主例逐阶段结果

`fullAcceptanceS0ToS7` 用真实服务与数据库走完整个流程，逐阶段断言：

| 阶段 | 断言结果 |
| --- | --- |
| S0 报名 | 冻结价格 `1000.00`、课时 `10.00`、净应收 `1000.00`、账户 `0.00`、未收 `1000.00` |
| S1 收款 | 账户总额与可用均为 `1000.00` |
| S2 分配 | 账户 `0.00`、未收 `0.00` |
| S3–S4 关闭课次 | 消耗 `1.00` 课时 / `100.00` 元，剩余 `9.00` |
| S5 退 2 课时 | 本次 `2.00` / `200.00`，净应收 `800.00`，有效分配 `800.00`，账户总额与可用 `200.00`；对账 已消耗 1 + 已退 2 + 剩余 7 = 购买 10 |
| S6 准备现金退款 | 退款单 `PREPARED`，账户总额 `200.00`、冻结 `200.00`、可用 `0.00` |
| S7 确认已付 | 退款单 `PAID` 且带凭据，账户总额/冻结/可用均为 `0.00`，现金退出 200.00 |

## 4. 覆盖到的其他行为

| 主题 | 用例与结果 |
| --- | --- |
| 超退防护 | 退课时超过可退（购买 − 已消 − 已退）返回 `HOURS_EXCEED_REFUNDABLE`；消耗 1 课时后只可退 9 |
| 未收足 | 只收 500 时退 2 课时：净应收 800、分配仍 500、账户不增加，未收 300 |
| 冻结约束 | 账户已全部用于报名时准备退款返回 `INSUFFICIENT_AVAILABLE`；冻结后可用为 0，再次准备被拒 |
| 取消退款 | 取消 `PREPARED` 退款单后可用恢复 200；已取消的退款单确认支付返回 `CASH_REFUND_NOT_PREPARED` |
| 权限分离 | 只有 `REFUND_APPLY` 的账号确认支付被拒 |
| 幂等 | 同请求号重复退课时只记一次（已退课时仍为 2.00）；换参数返回 `IDEMPOTENCY_MISMATCH` |
| 租户隔离 | 跨租户写入退款单被强制 RLS 拒绝（SQLState 42501） |
| 第二入口 | 真实 HTTP 走完退课时 → 准备 → 确认已付，返回的金额与余额均为字符串，完成后总额与冻结为 `0.00` |
