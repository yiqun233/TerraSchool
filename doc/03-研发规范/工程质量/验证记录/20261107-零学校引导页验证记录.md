## 1. 要解决的问题

客户开通后第一次登录，机构里没有任何学校。此前它会看到一个普通的空组织列表，
很容易被当成“系统坏了”。设计第 4.7 节要求这时给三步引导：建学校 → 建校区/部门 → 加员工并授权。

## 2. 实现

| 文件 | 说明 |
| --- | --- |
| `features/organization/OnboardingGuide.tsx` | 三步引导；第一步内嵌现有的 `SchoolCreator`（它自己检查 `canCreate`），后两步只作说明，不给点不通的按钮 |
| `features/organization/OnboardingGuide.module.css` | 中性样式，沿用既有令牌，没有新增色值 |
| `features/organization/OrganizationPage.tsx` | 判定 `needsOnboarding` 并在组织目录分支前置渲染；建校完成后重置查询，引导随事实消失 |

**判定方式是刻意的**：`canReadOrganizations && readableSchoolIds.length === 0`。
不新增“已引导”标记，就不会出现“标记说引导过、其实还没有学校”这种两处维护不一致——
建好第一所学校后，可读学校范围不再为空，引导自动消失。

## 4. 取舍与已知限制

- 判定用的是**账号可读学校范围**，不是“租户是否存在学校”。对租户管理员两者等价；若将来给
  普通员工使用，需要换成租户级事实（后端加一个只读计数）。
- 引导只在“组织目录”分区出现；其它分区仍可切换，但新租户点进去会是空列表或权限提示。
- 未做真实浏览器走查与窄屏适配。

## 5. 闭环状态

开通 → 交付一次性密码 → 客户登录 → 强制改密 → 引导建校 → 正常业务，这条链路现在首尾相接。
