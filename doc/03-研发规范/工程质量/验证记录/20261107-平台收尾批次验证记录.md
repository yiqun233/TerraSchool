## 1. 本批四项

### 1.1 平台租户详情

`GET /api/platform/tenants/{id}` 返回名称、状态、开通时间与三个计数（学校 / 账号 / 管理员）。
计数由 `platform.tenant_summary` 受控函数给出，只返回数字，不返回任何业务明细。

前端：租户名变成可点开的按钮，打开详情对话框。

### 1.2 主动改密

`ChangePasswordGate` 增加 `variant`：`page` 用于首次强制改密，`modal` 放进对话框用于主动改密。
工作台头部新增“修改密码”，改完同样回到登录页并说明原因（凭据版本递增，旧会话必然失效）。

### 1.3 开通失败留痕

失败时在 `platform.provisioning_request` 写一条 `FAILED` 行并记录 `error_code`
（唯一冲突、幂等不匹配、参数不合法）。同一 `requestId` 重试时，`provision_tenant` 会先删掉失败行再走完整编排，
所以“失败 → 处理冲突 → 重试”这条路径是通的。

### 1.4 租户名唯一（做了又撤回）

一开始加了 `CREATE UNIQUE INDEX tenant_name_unique ON identity.tenant (lower(name))`，
想堵住“并发同名”的理论缺口。加完跑全量后端，**109 项错误**：大量既有测试夹具会建同名租户，
说明这条约束与产品现实冲突——不同客户完全可能叫同一个名字（“明德学堂”不止一家），
用名字当标识只会把合法开通卡住。

已撤回：删除唯一索引，同时删掉 `provision_tenant` 里的重名检查；
`duplicateNameOrLoginIsRejectedWithStableCodes` 改名为 `sameNameIsAllowedButRepeatedLoginIsRejected`，
断言“同名可以开、同一登录名不行”。

保留的标识口径：**租户 id 是标识，登录名全平台唯一**。

## 2. 本批发现并修掉的真问题

**平台角色读不到租户列表。** `identity.tenant` 是 FORCE RLS，V81 只授了列权限却没建策略，
`ts_platform` 一行也看不到——列表接口一直返回空数组。之前没有暴露，是因为列表的前端验证用的是
模拟接口，后端也没有断言过“列表非空”。本批补上策略 `platform_read`，并在测试里断言开通后列表
能看到这个租户。

这是本轮最值得记的一条：**只在模拟接口上验证过的界面，等于没验证过数据能不能读出来。**

## 5. 未完成：真实浏览器端到端

没有做，原因是环境而非取舍：本机要跑起来需要后端 + 临时数据库 + 前端两套入口，
而 Windows 工作机不构建镜像、也没有常驻的浏览器 E2E 编排（AGENT.md 第 15 节）。
现有的“浏览器实拍”是上一批在真实后端下拍登录页、列表页用的是模拟接口，
**不构成端到端证据**。建议在 CI 里补 Playwright，覆盖：平台登录 → 开通 → 一次性口令 →
客户登录 → 强制改密 → 建校 这条主链路。

## 6. 其他限制

- 详情页的计数是即时查询，没有缓存；租户数量大时仍是单行查询，代价可忽略。
- 租户名不做唯一，因此“两个客户同名”不是问题；但也无法靠名字定位租户，界面必须显示短 id（已做）。
