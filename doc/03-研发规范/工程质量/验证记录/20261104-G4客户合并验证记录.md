# G4 客户合并与撤销验证记录

状态：REV-009 已增加同校同负责人客户线索的显式合并、合并记录和撤销入口；学员主档合并及负责人确认的最终冲突规则仍未验收。

## 暂定实现边界

- 操作人需具备学校客户维护权限，并且合并来源与主档都由本人负责、属于同一学校、均不在公海且尚未合并。
- 操作人明确选择保留主档；通过来源与主档双版本检查及事务内稳定排序行锁避免并发更改。合并和撤销都会递增两侧版本；有副档的主档不能转入公海，避免副档关系失去负责人视图。同版本并发合并仅一个提交，另一个返回 `VERSION_CONFLICT`。
- 合并只在来源客户写入 `merged_into_id` / `merged_at` 并递增版本。副档不物理删除，跟进、请求和审计仍引用原客户；主档跟进查询可查看来源副档的既有跟进。
- 可由主档合并记录执行带版本撤销，来源客户恢复到本人客户列表。合并或撤销均不会迁移学员、报名、消费或资金。
- 公海客户、跨负责人、跨校、已合并来源或存在下级副档的来源不允许合并；不以电话重复提示自动选择主档。
