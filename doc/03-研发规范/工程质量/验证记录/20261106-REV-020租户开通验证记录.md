## 1. 做了什么

### 1.1 数据结构（V82）

| 变更 | 原因 |
| --- | --- |
| `identity.account.tenant_admin` | 租户管理员标记。现有“覆盖全部学校”的判断在没有学校时返回否，新租户连第一所学校都建不出来 |
| `identity.account.password_change_required` | 首次登录强制改密的标记，本批只建列，未接流程 |
| `identity.tenant.created_at` | 租户列表需要开通时间；既有租户回填为迁移时刻 |
| `platform.provisioning_request` | 请求身份 + 参数摘要，用于幂等与失败解释 |
| `platform.provision_tenant(...)` | SECURITY DEFINER 函数：建租户 + 建管理员 + 记开通 + 记审计，一个事务 |
| `platform.tenant_administrators(...)` / `platform.reset_tenant_admin_password(...)` | 平台查看与重置租户管理员凭据；平台角色仍不能直接读写 `identity.account` |

行级权限之外还有一个坑：`identity.account` 的读取是**列级授权**，新增列必须显式授权，
否则权限快照查询会整条失败（本次就是因此先报 `permission denied for table account`）。

### 1.2 权限模型

`CurrentPermissions` 增加 `tenantAdmin`，`PermissionRules.calculate` 在租户管理员时直接给出
组织读取/维护与授权管理能力。学校范围仍由显式学校授权决定——“覆盖全部学校”由
`SchoolProvisioner.full()` 结合标记判断：**租户管理员恒为真，其它账号仍按原逻辑，空集不放行**。

`AccountAuthorizations.managed()` 原来要求“可管理学校集合非空”，零学校的租户管理员会被挡在
建校之外；现在改为“租户管理员除外”。

### 1.3 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/platform/tenants` | 开通：`{requestId, name, adminLogin, adminPassword}`，201 返回租户与账号 id |
| GET | `/api/platform/tenants?page=&size=` | 租户列表：只有名称、状态、开通时间 |

密码策略：≥12 位、不得与登录名相同、不得为纯数字或纯字母；参数在进入数据库前校验。

## 3. 过程中修掉的问题

| 问题 | 处理 |
| --- | --- |
| 列级授权漏了新增列，权限快照查询整条失败 | V82 补 `GRANT SELECT(tenant_admin, password_change_required)` |
| 重名检查放在幂等判断之前，重放请求被当成“机构已存在” | 把重名检查移到幂等分支之后 |
| `managed()` 要求“可管理学校非空”，零学校管理员建不了校 | 允许租户管理员通过 |
| `load()` 的账号行查询没取 `tenant_admin` | 补列 |

### 2.1 首次强制改密与平台重置

| 用例 | 证明 |
| --- | --- |
| `firstLoginMustChangePasswordBeforeAnyBusinessCall` | 新租户管理员登录后调业务接口返回 403 `PASSWORD_CHANGE_REQUIRED`；改密成功后旧会话立即失效（401），用新口令登录后业务接口 200 |
| `platformResetForcesChangeAgainAndInvalidatesOldPassword` | 平台可列出该租户的管理员并重置；旧口令登录被拒、新口令可用，且再次被要求改密 |

实现要点：改密会递增 `credential_version`，所以**当前会话也会失效**，客户端应跳回登录页；
口令散列的读取走身份连接而不是业务连接——安全不变量测试明确禁止业务角色读取散列
（本轮先误加了列级授权，被 `AuthorizationManagementTest` 的既有用例抓出来）。

## 5. 限制

- 容器内未验证；Windows 开发机不构建镜像（AGENT.md 第 15 节），交付链验证在 Linux/CI 执行。
- 租户名称**不做**唯一：曾尝试 `lower(name)` 唯一索引，全量测试立刻暴露它与现实冲突（不同客户会同名），已撤回。租户 id 才是标识。
- 管理员登录名沿用 `identity.account.login` 的**全局唯一**约束，不是租户内唯一；不同租户不能使用
  相同登录名。这是既有约束，未在本批改动。
