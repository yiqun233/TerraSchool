## 1. 授权与验证范围

用户在“范围明确的最小技术验证，由验证结果确定版本与安装清单，再建立正式工程”的推荐后回复“进行下一步吧”。本批任务 R3-CORE-001 的交付是独立、可复核的核心技术原型，不是正式业务工程或可上线业务。

验证路径为 Flyway → 全新临时 PG → jOOQ 元数据生成 → Java 编译/真实隔离事务与 HTTP 测试 → 实际 OpenAPI → TypeScript/类型客户端 → React/Vite 组件组合构建。演示草稿表、固定测试身份与权限仅为测试夹具，不定义真实报名、结算或退款规则，没有对照旧系统建立业务金标准。

## 4. 复现与产物政策

入口为[run.py](../../../../tools/verification/core-stack/run.py)，Windows 原生源码与子进程执行。需要可连接的 Linux Docker 引擎、Python 3、Node/pnpm 和本轮 JDK 21；首次生成 Wrapper 时需要 Maven 3.9.12，之后可用已生成 Wrapper。常规复现命令：

```powershell
# 在项目根执行；仅对当前终端/本次验证指定 Java，不修改系统环境。
$env:PROBE_JAVA_HOME = 'C:\Program Files\Java\jdk-21'
python tools/verification/core-stack/run.py
```

脚本为每轮生成新的随机凭据与 `core_probe` 临时库，随机映射回环端口，角色仅存在于该临时 PG；不接受把现有 vectordb 作为测试目标。会话表由迁移建立，运行账号不自动建表。Testcontainers 另行创建测试容器，保持资源回收机制，不关闭检查伪造成功。

Maven 仓库/Wrapper、pnpm store、缓存与 Java 临时目录使用项目 `.local`，通过子进程环境和项目独立 Maven 设置生效；没有改变全局 JAVA_HOME/PATH、用户镜像源、缓存权限、Docker 配置或现有服务。便携 Temurin 25 的压缩包/目录及工具缓存在 .local，全部被 Git 忽略。

保留原型源码、Flyway SQL、生成配置、Maven Wrapper 和 pnpm-lock.yaml；生成 jOOQ 留在 target、OpenAPI 和前端派生类型留在生成目录，不手改、不提交。正式工程是否沿用生成不入库方式仍需在初始化任务中落实。`.local` 日志保留失败尝试和真实结果，不将失败报告改写为成功。
