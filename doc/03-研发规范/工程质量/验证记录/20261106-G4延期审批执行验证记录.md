# G4 延期审批执行验证记录

状态：延期批准后执行首版已实现并完成定向验证；延期起算规则和历史报名补录待负责人确认，不据此关闭 REV-010/REV-012。

## 实现范围

- 新报名保存候选有效截止日：`enrolledOn + study_days - 1`，报名日计入学习期限；没有 `study_days` 的产品不生成截止日。旧报名的报名日未持久保存，迁移后 `valid_until` 保持空值，不猜算历史截止日。
- 延期申请显式提交目标截止日，金额必须为 0；日期写入申请、幂等摘要和审批视图。目标日必须晚于报名当前截止日。
- 学校须配置有效的 `ENROLLMENT_DEFER` 审批策略。审批通过本身不修改报名；具备报名维护权限的操作人再发起执行，服务端校验审批单、动作、学校、报名和目标日匹配，并在同一租户事务内消耗审批与更新有效截止日。
- 相同审批标识和目标日重试返回已执行报名；复用审批更改目标日拒绝。延期申请不能配置金额免批阈值。
- 课次结算和期初消费的业务日期晚于有效截止日时拒绝，不生成消费流水；延期后可按新截止日继续执行。
- 审批工作台可填写新截止日、查看审批日期、配置延期策略，并对已批准且未消耗的延期单执行。

## 待确认与限制

- `study_days` 是否从 `enrolledOn` 开始且首日计入仍待 Q55/Q60 确认；代码当前按候选口径实现。
- 历史报名期限空值，不能申请延期；尚无可信报名日可用于回填。
- 该首版只修改报名有效截止日；未实现过期学员自动状态转换、通知、延期次数/上限、课次预约排除或延期费用。
- 正式审批岗位矩阵、免批策略、岗位授权及财务/教务期间影响仍待 Q55/Q62 等问题项确认。
