## 3. 覆盖到的行为

| 主题 | 结果 |
| --- | --- |
| 锁月拦截收款 | 锁定 2026-03 后，3 月 10 日收款返回 `PERIOD_LOCKED`；4 月 10 日收款正常 |
| 锁月按课次日期拦截消费 | 课次在 2026-05，锁定 5 月后关闭课次返回 `PERIOD_LOCKED` |
| 锁月拦截退费 | 锁定当月后退课时返回 `PERIOD_LOCKED`；解锁后同一操作成功并返回 200.00 |
| 解锁需版本 | 缺版本或版本不符返回 `VERSION_CONFLICT`；正确版本解锁为 `OPEN` |
| 未锁定不可解锁 | 已开放的期间执行解锁返回 `PERIOD_NOT_LOCKED` |
| 重复锁定幂等 | 连续锁定两次均为 `LOCKED`，审计只记一条 |
| 期间列表 | 固定返回 12 个月，已锁月份为 `LOCKED`、其余为 `OPEN` |
| 权限 | 只有 `PERIOD_READ` 的账号锁月被拒 |
| 租户隔离 | 跨租户写入期间被强制 RLS 拒绝（SQLState 42501） |

## 4. 影响面确认

`funds` 与 `teaching` 都在写库前经过期间闸门，因此锁月同时覆盖：确认收款、撤销收款、分配、释放分配、退课时、准备现金退款、确认已付、关闭课次。既有测试与演示数据未锁定任何月份，行为不变。

## 5. 限制与未覆盖

- 财务月不等于自然月的情况不支持；
- 期末结转、跨期调整单据、期间重开的多级审批未实现；
- 锁定前不做完整性校验（例如未分配完的收款不会阻止锁月）；
- 报表/导出仍按实时数据，未做锁定快照；
- 「我的权限」页面未展示 `PERIOD_*`；
- 时区按服务端本地日期。
