## 1. 要解决的问题

在本地跑通“平台开通机构 → 用该机构管理员登录”后，验收发现四类问题：

1. 点“退出登录”停在原页面，必须刷新才回登录页。
2. 新机构管理员一登录就落在学员档案，显示“无法读取学员档案权限”。
3. 教务、财务等业务菜单对租户管理员可见，点进去 403。
4. “账号与角色”四个入口里只有“开通学校”能用；建完学校也不知道该去哪看。

## 2. 根因与证据

| 现象 | 根因 | 证据 |
| --- | --- | --- |
| 退出后不回登录页 | `AppShell.leave()` 与 `SessionProvider.onUnauthorized` 都是先 `queryClient.clear()` 再写 `setQueryData(["session-context"], null)`。`clear()` 把 Query 实例摘出缓存，已挂载的 observer 仍绑旧实例，随后写 `null` 只是新建实例，页面读到的仍是旧会话 | 同版本 `@tanstack/query-core` 5.105.0 探针：clear+写 null 后 observer 值不变；改成先写 null 再清其余缓存后立即读到 null。回退实现时 `session.test.ts` 断言失败 |
| 落到学员档案后 403 | `StartPage` 用 `readableSchoolIds`（`ORGANIZATION_READ` 的范围）判断“能不能用业务”，而建校只铺 9 个动作，不含 `STUDENT_READ` | `router.tsx` 原判定；`SchoolProvisioner.provision` 的授权清单 |
| 业务菜单可见但 403 | `navigation.ts` 只给招生渠道、本人客户加了 `visible`，教务、财务、报名、产品、审批、迁移仍常显 | 菜单配置与 `PermissionConsole`/`TeachingWorkspace`/`PeriodManager` 的首屏能力请求 |
| 只有“开通学校”能用 | 管理范围为空时 `slots()` 返回空串，SQL 变成 `id in ()`，PostgreSQL 直接报语法错误（接口 500）。租户管理员在还没有学校时正是空范围 | 回退实现后新增用例报 `BadSqlGrammarException: ... id in ()`；`SchoolCreator` 因 `tenantAdmin` 兜底不受影响 |

## 3. 实现

| 文件 | 说明 |
| --- | --- |
| `frontend/src/app/session.tsx` | 新增 `endSession(client, tenantId)`：先 `setQueryData(null)`、再清其余缓存；退出与会话失效共用，避免两处各写一套 |
| `frontend/src/app/AppShell.tsx` | `leave()` 改调 `endSession` |
| `frontend/src/app/navigation.ts` | 业务菜单按 `grantedActions` 显隐；新增 `startPath()` 统一登录落点 |
| `frontend/src/app/router.tsx` | `StartPage` 改用 `startPath`；新增 `/start` 路由 |
| `frontend/src/app/PendingAccessPage.tsx`（新增） | “登录成功但没有任何业务动作”时的说明页：说清缺什么、谁能开通、下一步点哪里 |
| `frontend/src/features/identity/PermissionConsole.tsx` | 零学校时提示“先开通学校”并给组织目录入口（配合 `AccountAuthorizations` 的修复，四个入口不再 500） |
| `backend/.../identity/internal/AccountAuthorizations.java` | `slots()` 空集合改拼 `select null::uuid where false`，`in`/`not in` 都得到空集语义 |
| `backend/.../identity/internal/RoleTemplates.java` | 同一处空范围拼接，同样处理 |
