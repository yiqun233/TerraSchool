## 1. 背景与适用范围

在此之前的开发以业务完成度优先，页面能完成动作即可，标题、空态、错误提示、密度和文案各写各的。
从平台管理端开始，新做和改动的页面按本规范执行；已有页面在后续批次里按同一标准补齐，
不要求一次性重写。

本规范针对**内部管理端**：目标是让业务人员少出错、看得懂、找得到。不追求营销页面的视觉效果，
但以下四件事不允许妥协：

1. **看得懂**：每个页面一眼能回答“我在哪、这页干什么、我现在能做什么”；
2. **不误导**：没有数据、没有权限、加载中和出错，四种状态必须能区分；
3. **少出错**：危险动作有确认、有后果说明；表单错误就地提示；
4. **可完成**：任何一次操作都有明确的成功/失败反馈与下一步。

## 2. 视觉基线

复用 DEC-012 的主组件库与主题变量，不引入第二套样式体系。

| 项 | 约定 |
| --- | --- |
| 主色 | 现有 `colorPrimary: #254c78`；强调色只用于主操作与关键状态 |
| 圆角 | 现有 `borderRadius: 6`；不逐处覆盖 |
| 间距 | 4 / 8 / 12 / 16 / 24 五档；页面区块间距 24，区块内 12，行内 8 |
| 字号 | 页面标题 20、区块标题 16、正文 14、辅助说明 12；不靠加粗堆层级 |
| 密度 | 管理端取紧凑：表格 `size="small"`，但行高不低于 32 |
| 装饰 | 不用渐变、不用重阴影、不用大色块；层级靠间距、留白与字号建立 |
| 图标 | 沿用组件库图标；不手工画 SVG，不混用图标集 |

## 3. 页面结构

一个页面只承担一个任务。统一骨架：

```text
标题（做了什么）        ← 一句话说明这页干什么
说明文字（可选）        ← 规则、范围、限制；不超过两行
筛选/操作区             ← 主操作放右侧，次操作靠左
内容区                  ← 表格/表单/卡片，一屏内可见重点
```

- 分区用 `Card` 或明确的标题分隔，不把十几个控件堆成一堵墙；
- 主操作每页最多一个（主按钮），其余为默认按钮；
- 页面级信息（总数、状态、口径）放在内容区上方，不塞进表格列。

## 4. 四种状态必须区分

| 状态 | 要求 | 反例（现状常见） |
| --- | --- | --- |
| 加载中 | 表格用 `loading`，局部用骨架或占位；不显示“0 条” | 加载时显示空表 |
| 空 | 说明为什么空 + 下一步做什么（可为空操作） | 只显示一行“暂无数据” |
| 错误 | 可读原因 + 重试入口；不暴露堆栈或状态码 | 只弹“操作失败” |
| 无权限 | 说明缺什么权限、找谁开通；不伪装成空数据 | 直接不显示，用户以为没数据 |

新租户“还没有学校”就是典型的空状态：必须给引导，而不是空白页。

## 5. 表单

- 标签统一放上方；必填标记统一用组件库的 `required`；
- 就地校验：字段失焦即提示，不等到整表提交；
- 提交中：按钮 `loading` 并禁用重复提交；网络结果不确定时保留输入，提示“用相同内容重试”；
- 失败：保留已填内容，焦点回到出错字段；
- 危险或不常见字段给一行说明（例如“留空表示不限”），不靠占位符承载规则。

## 6. 反馈与确认

- 成功：轻提示（`message`/`Alert`），不弹模态框打断；
- 危险操作（停用、删除、重置密码、退款）：二次确认，确认文案必须写清**后果与范围**，
  例如“停用后该机构所有人将无法登录，数据保留”；
- 长任务：给进度或至少给“已提交，可在 X 查看”；
- 一次性凭据（初始密码）：**只展示一次**，提供复制按钮，并明确“离开后无法再次查看”。

## 7. 文案

- 动词开头：“新建学校”“重置密码”“停用租户”；
- 说人话：不写内部术语与英文状态码；必要展示时同时给中文；
- 错误文案三段式：发生了什么 + 为什么 + 怎么办；
- 同一动作全站同一叫法（例如统一“重置密码”，不要混用“重置”“恢复”）。

## 8. 可访问性与可测试性

- 所有输入有可访问名称（`aria-label` 或关联 `<label>`）；这既是无障碍要求，也是现有测试的查询依据；
- 键盘可达：主要操作可用 Tab + Enter 完成，焦点样式不被移除；
- 对比度满足 WCAG AA（正文 ≥ 4.5:1）；
- 弹窗打开后焦点进入弹窗，关闭后回到触发元素。

## 9. 验收方式

新页面或改版按以下清单走查，由负责人用真实业务任务点一遍：

1. 进入页面 3 秒内能说出这页做什么；
2. 空/错/无权限/加载四种状态都能看到（可用构造数据或临时开关）；
3. 每条主路径操作完有明确反馈，失败后能重试且不丢输入；
4. 危险动作有确认且写明后果；
5. 全键盘可完成一次主路径；
6. 与相邻页面在标题层级、间距、按钮位置上看起来是一套。

## 10. 当前差距（诚实记录）

| 现状 | 处理 |
| --- | --- |
| 多数页面标题与说明缺失或不统一 | 后续批次按第 3 节补 |
| 空态多为一句“暂无数据” | 优先补有引导意义的空态（如未建学校） |
| 错误提示多为通用文案 | 按第 4、7 节改写成可读原因 + 下一步 |
| 危险操作部分无确认 | 按第 6 节补齐 |
| 无统一的设计 token 文档 | 先沿用现有主题变量，积累后再沉淀 |
