## 为什么需要它

迁移管道已经能「装载 → 干跑 → 只读预检」，旧主体确认导入已停用，但入口一直是手工 CSV。真实迁移时第一道坎不是导入，而是**从 SQL Server 把行抽出来并做单位换算**：
旧库金额以"分"存、课时以 0.01 单位存、日期是 `yyyyMMdd` 整数、家长在独立的 `H_Student_Guardian` 表里。

## 映射（依据 `TSchool_SQLServer.sql` 的真实字段）

| 旧表 | 旧字段 | 输出列 |
| --- | --- | --- |
| `H_Student` | `Code` / `SN` / `Name` / `Sex` / `Birthday` / `Cert_Code` / `Phone` | `legacy_id` / `studentNo` / `name` / `sex` / `birthday` / `certCode` / `phone` |
| `H_Student_Guardian` | `Student_Code` / `Guardian_Order` / `Name` / `Phone` | `contactName` / `contactPhone`（取 `Guardian_Order` 最小的一条） |
| `H_Student_Register_Pay_Record` | `Code` / `Student_Code` / `Date_Stamp` / `Money` | `legacy_id` / `studentNo` / `occurredOn` / `amount` |
| `H_Student_Register_Consume` | `Student_Code` / `Pay_Money` / `Consume` / `CS_Hour_Consume` | `openings.csv`：余额 = `Pay_Money − Consume`，课时 = `CS_Hour_Consume` |

换算：金额 ÷100（分→元）、课时 ÷100（0.01→两位小数）、`Date_Stamp` → ISO 日期、性别 `1/2/0` → `MALE/FEMALE/UNKNOWN`。

## 用法

```powershell
# 1) 从 SQL Server 导出旧表为 CSV（SSMS"导出结果到文件"或 bcp）
#    H_Student.csv / H_Student_Guardian.csv / H_Student_Register_Pay_Record.csv / H_Student_Register_Consume.csv
python tools/migration/extract_legacy.py --raw-dir ./raw --out-dir ./out
```

产出 `students.csv` / `receipts.csv` / `openings.csv` 与 `report.json`（计数、换算说明、被丢弃的行及原因）。
**不静默丢弃**：缺主键、缺金额、日期非法都会进 `dropped` 并在报告里列出。

自检（已并入 `verify.py` 的 `[extract]` 步骤）：

```powershell
python tools/migration/extract_legacy.py --self-check
```

## 本机实测

用样例数据（2 名学员、3 条收款含 1 条非法日期、1 条报名级汇总）跑通：

| 项 | 结果 |
| --- | --- |
| 学员 | 2 条；缺学员号的 1 条进 `dropped` |
| 家长 | 同一学员两条时取 `Guardian_Order=1` 的"甲妈妈" |
| 收款 | 2 条（1000.00 / 500.00）；`20260231` 非法日期进 `dropped` |
| 期初 | 余额 900.00（1500−600）、课时 4.00 |

## 限制（要如实知道）

- **`sqlserver` 模式没有实现也没有验证**：本机没有 SQL Server 与 ODBC 驱动，因此脚本只做"文件 → 文件"；真要直连需要另写一个连接层并用真实旧库验证；
- 只抽取学员、家长、收款、报名级汇总四类；报名/课次/消费的逐条迁移仍卡在 C1–C6 口径；
- 旧库"退班/拼接/优惠类型"没有映射，属于已知丢弃项（见口径候选表）；
- 没有增量抽取：每次全量导出。
