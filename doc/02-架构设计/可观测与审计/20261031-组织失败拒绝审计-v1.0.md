## 1. 范围与依赖

用户要求先提交现有代码、再继续开发；前批本地启动/WSL切换已提交c49ba9a。本批沿用执行路线CORE-005和DEC-019，补齐组织新增/改名的失败、拒绝独立记录及成功/失败追踪关联，依赖ORG-002、身份可信主体与租户事务。

不实现完整授权/角色管理、通用审计查询界面、登录失败审计、限流/保留清理、监控平台或AI。只围绕当前两个组织修改动作，低风险列表查询不逐次追加失败审计；不能称CORE-005或DEC-019全部完成。

## 2. 两条记录路径

成功组织事实与audit.business_event继续在同一个Spring/jOOQ业务事务提交，V4增加可空trace_id，历史记录不伪造追踪。正常新操作写入当前追踪号；同键成功重放不重复生成业务事实或成功变更审计。

公开OrganizationCommands仅由AuditedOrganizationCommands实现；内部OrganizationMaintenance不再充当另一份公开命令入口。装饰入口覆盖完整授权、校验、事务及提交异常，HTTP与测试直接调用均不可绕过失败记录。

失败路径使用ts_audit独立连接池和原始JDBC连接，自动提交、不使用业务事务的连接或DataSourceUtils。audit.operation_failure无可回滚业务行外键，记录不因业务回滚消失，也不等待业务行锁。每次仅尝试一次；连接获取最多2秒，SQL超时2秒，池上限2，不无限重试。

调用方已有事务时，命令成功返回并不代表整个事务已提交。入口捕获追踪/可信主体/动作，在afterCompletion针对外层回滚追加TRANSACTION_ROLLED_BACK，未知终态记录TRANSACTION_OUTCOME_UNKNOWN；已在命令catch记录的失败不重复登记回调。回调使用捕获上下文，不依赖届时线程身份。外层已提交则不额外追加失败。

## 3. 主体与记录字段

| 字段 | 语义与来源 |
| --- | --- |
| id | 数据库uuidv7，失败事实主键 |
| attempt_id | 服务端为本次记录生成的UUID，不是创建请求的幂等键 |
| trace_id | 服务端入口生成的诊断UUID，外部X-Trace-Id不作为权威值 |
| tenant_id / actor_id | 从已认证账号ID重新查询identity.account，二者成对为空或有值 |
| action | ORGANIZATION_CREATE / ORGANIZATION_RENAME固定动作目录 |
| source | HTTP / APPLICATION，可信调用入口设置 |
| result | REJECTED / FAILED；描述调用或事务结果，不据异常断言资金/业务必然未提交 |
| code | 固定拒绝/错误码，不采用异常消息或用户任意理由 |
| resource_id | 改名尝试的UUID对象引用，或外层回滚时捕获的对象；不表示对象存在或调用方有权查看 |
| happened_at | PostgreSQL实际时刻 |

账号/租户停用后仍可为该已认证主体归属审计，但AuditSubject不提供业务权限，授权仍走完整CurrentActor规则。未知主体或身份库无法核实时，tenant/actor均为空；不从请求tenantId、用户名、余额或外部追踪头补全身份。停用后的业务请求依然拒绝。

记录不保存名称、请求/响应正文、密码、CSRF/Cookie、SQL参数、异常原文或堆栈。被尝试的对象UUID只是输入引用，不回查或泄露无权对象详情。

## 4. HTTP与前端行为

TraceFilter在安全链之前建立并在finally恢复/清理上下文；响应X-Trace-Id与RFC9457错误中的traceId一致。直接应用入口自行建立并清理上下文。失败事务回调捕获该编号，支持跨入口关联，未实现后台任务/跨线程传播平台。

| 拒绝/失败 | HTTP与稳定码 | 记录位置 |
| --- | --- | --- |
| 未认证的组织修改 | 401 AUTHENTICATION_REQUIRED | 安全拒绝处理器；CSRF缺失可能先返回403 |
| 无CSRF / 无学校维护权限 | 403 ACCESS_DENIED | 安全处理器或应用入口各负责自身阶段 |
| 无效JSON/字段/参数 | 400 INVALID_INPUT | MVC解析阶段或应用入口，避免同次重复记录 |
| Content-Type / Accept不支持 | 415 UNSUPPORTED_MEDIA_TYPE / 406 NOT_ACCEPTABLE | MVC契约拒绝处理器 |
| 版本/幂等/类型动作冲突 | 409 原业务码 | 公开应用入口 |
| 业务事务异常 | 500 OPERATION_FAILED | 公开应用入口，原事务回滚；若结果不确定必须按原请求身份核对 |
| 独立审计不可写 | 503 AUDIT_UNAVAILABLE | 不伪称审计已保存；安全日志含AUDIT_WRITE_FAILED及追踪号 |

前置记录只分类明确的POST新增或单段id改名路由，不保存原始路径。缺id、多余路径段等不会因审计解析越界而破坏原状态。失败/拒绝不因已进入错误处理器而再次记录一遍。

前端新增/改名失败时展示服务端有效UUID追踪号。新增5xx/408或网络结果不确定仍保留原requestId并锁定输入，重试沿用原请求；不因503新增一次操作身份。改名冲突保持编辑时版本快照。前端不将追踪号或缓存作为授权。

## 5. 权限、配置与审计失败

V4迁移启用并强制失败表RLS。ts_audit为受限基础设施追加身份，仅可INSERT失败表，不可读业务/身份/失败历史，也不能UPDATE/DELETE/TRUNCATE；不拥有表、不是超级用户且无BYPASSRLS。其INSERT策略允许记录未知主体或经可信入口确定的租户；这是专用审计基础设施路径，不能用于普通业务连接。

ts_app不能伪造失败表INSERT，只具备按当前租户RLS的SELECT供受控应用能力使用；本批没有对外审计查询入口或学校/字段审计查询政策，不能将租户级SQL权限当成已完成审计产品授权。未知主体行不会被普通租户读取。

启动配置新增teraschool.database.audit.username/password；本地工具仅新增随机audit密码与带本环境标记的ts_audit，原密码和种子数据不变。专用角色先由本地开通工具建立，再由ts_migrator执行V4，不给迁移角色CREATEROLE。自动化仍只用临时库和随机凭据。

审计不可写时原失败不转换成成功，也不伪造持久记录。同步路径明确返回/抛出AUDIT_UNAVAILABLE；外层事务afterCompletion已经不能改变已终结的调用结果，追加失败另输出AUDIT_AFTER_COMPLETION_FAILED，不声称此时有数据库记录。原失败/回滚依然有效。日志不包含异常原文；尚无外部告警渠道、容量/保留清理或审计不可用时的持久备用队列。

## 6. 验收与剩余

需真实PG验证：业务失败回滚而独立记录存在、成功返回后外层回滚、权限/停用归属、未知主体、跨租户不可读、追加账号不能读取/篡改、审计不可写明确失败、HTTP401/403/400/406/415/409追踪关联且不重复、缺id路由、成功审计关联及线程清理。组件回归同时检查冲突和5xx追踪显示、原幂等身份和版本保护。

完整岗位/字段授权、认证失败审计、审计查询/导出/保留/归档、日志轮转和监控告警、后台任务追踪仍待后续。当前切片未完成报名资金主链，不能因失败审计交付而宣称完整业务或生产可用。
