## 现实前提

`参考资料/TSchool_SQLServer.sql` 只有**结构、没有数据**（0 条 INSERT），所以本轮不可能做"真实迁移"。能做且必须现在做的，是把**装载 → 干跑 → 确认 → 对账**这条管道建起来并验证，等 FULL/OPENING 快照到位直接灌。

## 三段式

| 阶段 | 做什么 | 写业务表 |
| --- | --- | --- |
| 装载（stage） | 把旧库行按契约写入 `migration.legacy_*` 暂存区，按旧主键 upsert | 否 |
| 干跑（dry_run） | 统计将导入多少、金额合计、逐条差异 | 否 |
| 确认（commit） | 学员/联系人/收款落库，按旧主键写 `migration.import_log` | 是 |

**幂等**：`import_log` 以 `(tenant, kind, legacy_id)` 为主键，重复确认不会重复导入。

## 本轮覆盖的实体

| 旧库对象 | 新库对象 | 关联键 | 说明 |
| --- | --- | --- | --- |
| 学员 | `archive.student` | 学员号 | 证件类型未确认，按原值保留、不统一认定为身份证（见[迁移口径候选表](迁移口径候选表.md)与[只读预检契约](../报表与数据交换/旧库只读预检契约.md)） |
| 家长联系人 | `archive.contact` + `archive.student_contact` | 学员号 | 只有姓名没有电话时跳过联系人（库约束要求至少一种联系方式） |
| 收款流水 | `funds.receipt` + `funds.account_entry` | 学员号 | 金额与日期进入对账 |

## 对账报什么

- 暂存学员数 / 已导入数 / 待导入数；
- 暂存收款金额合计 / 已导入金额合计；
- 差异清单：新库还没有这个学员、同一学员号在旧库出现多次、收款找不到学员、新库没有对应金额的收款。

差异不会阻断导入：缺学员的收款会跳过并记入问题，需要人工补学员后重跑（幂等，不会重复）。

## 期初批量导入

单学员的期初接口再多，也要能"一次灌一个学校"。因此提供批量入口：

| 项 | 做法 |
| --- | --- |
| 契约 | `POST /api/migration/openings`，一行 `学员号, 金额, 课时, 已消耗金额` |
| 定位 | 按学员号找学员；课时按该学员**最近一条在读报名**记期初消耗 |
| 事务 | **逐行独立事务**：单行失败不影响其他行，也不会把整批标记为回滚 |
| 幂等 | 请求号由 `batchId + 学员号 + 类型` 派生，同批次重跑不会重复记期初 |
| 结果 | 逐行 `OK / SKIPPED / FAILED` 与说明，另给成功/跳过/失败计数与合计 |
| 干跑 | `dryRun=true` 只做解析与校验，不写库 |
| 无在读报名 | 课时不导入，行内注明"没有在读报名，课时未带入"（金额仍可导入） |

## 批次对账报表

逐行成功不等于整批对上（重复导入、人工补录都会让"实际"偏离"应有"）。因此导入时就把**应有值**落库，随时可以对账：

| 项 | 做法 |
| --- | --- |
| 记录 | `migration.opening_row`：批次 + 学员号 + 应有金额/课时 + 本次结果 |
| 接口 | `GET /api/migration/openings/reconciliation?schoolId&batchId` |
| 实际值 | 现查：该学员 `OPENING` 分录合计、该学员在该校的 `OPENING` 消耗合计 |
| 对比 | 逐行给出应有、实际、差额与 `MATCHED/MISMATCHED`，并给全批合计 |
| 立场 | **不抹平**：差额原样呈现，包含"失败行"（应有值存在、实际为 0） |

举例：批次导入 200.00 后有人又手工补录 150.00，对账会显示应有 200.00、实际 350.00、差额 150.00——这正是要发现的问题。

## 刻意不做的

- **不做报名/课次/消费的自动迁移**：报名依赖价格版本与课程明细，课次依赖排课规则，直接映射会把旧系统的口径差异带进新系统。这三类需要先定"旧→新"口径表，再单独做；
- 不做增量同步（OPENING 期间的双写/追赶）；
- 不写旧库，只读（本轮连旧库数据都没有，只有结构）。

## 界面

组织页「数据迁移」：粘贴 CSV → 装载并干跑 → 确认导入，展示计数、金额合计与差异表。真正的写权限由服务端 `MIGRATION_MANAGE` 校验（界面上的学校下拉只用于选择范围）。
