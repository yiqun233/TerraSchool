## 1. 本轮纠正与不能越过的边界

原 v0.1 中“丢弃退班/锁账/拼接/多教师”“退班迁为 ACTIVE”“用汇总实收造普通收款即可自然对余额”的建议撤回；它们不是已确认需求，也不能以新模型暂不支持作为理由直接采用。原对账公式混合实收、期初、未履约价值与账户余额，下面改为分层核对。

FULL 全量必须支持仍是已确认范围；可以采用“正式业务承接 + 受权只读历史归档”保存不同类型事实，不要求照搬每张旧表，但应能查询、追溯并解释。选择先做 OPENING/HYBRID 是上线批次安排，不能取消 FULL 能力。CUSTOM 必须补依赖闭包。

本机旧 SQL 目前只有结构；下面表/字段是已收集的映射线索，不是对真实旧数据的完整实测。单位转换需要逐表字段核验，不把所有金额或课时字段一律按同一倍率处理；脚本支持的已知转换与异常报告需结合真实导出验证。

## 2. 承接模式与推荐讨论顺序

| 模式 | 必须承接 | 可查询/可办理边界 |
| --- | --- | --- |
| FULL | 全部历史业务、关键字段、附件、关系、状态和来源 | 历史归档只读；在读对象具备继续消费、退款、调整等所需规则及累计数据 |
| OPENING | 主数据、在读报名、余额、未收、剩余课时、未关闭课次、累计消耗/已退/固化值/规则版本 | 不能只带余额和课时而丢掉决定续算的维度；历史明细访问方式需明确 |
| HYBRID | 指定日期内明细 + 更早汇总 + 完整来源映射 | 不重复计入收入或余额；时间边界和历史更正路径可解释 |
| CUSTOM | 选定学校/校区/实体/时间及自动依赖闭包 | 不允许出现孤立收款、失去报名来源的消费或跨校错误关联 |

建议先取一个具有多报名、多课程、优惠、已退和锁月的脱敏样本，验证 OPENING 续算及历史归档查询，再扩展 FULL 的明细装载。此顺序是实施建议，不是已批准迁移降级。

## 3. 映射与业务所有权

A：结构上可直接映射、仍需数据验证；B：需规则或语义确认；C：当前模型缺少承接。C 进入补建/归档清单，不等于丢弃。

| 旧来源/字段线索 | 新归属与候选映射 | 类 | 验证与限制 |
| --- | --- | --- | --- |
| 部署/源库、`School_Code` 等 | 源系统命名空间 + tenant/school/campus 映射 | B | 旧主键必须连同源库保存；一库多机构、多库合并另核验，不能按裸 Code 去重 |
| `H_Student`、`Code`/学员号/姓名/联系方式 | archive 学员主档及来源映射 | A/B | 经学员域导入契约；学员号冲突不能仅凭相等自动认同一个人 |
| `H_Student_Guardian` | 联系人、关系、顺序和主联系人 | B | 不只保留第一人；证件类型不明保留 UNKNOWN/待核，不全部认定身份证 |
| `H_Student_Register`、课程明细 | enrollment 报名、冻结课程金额课时与规则 | B | 原价、优惠、服务费、净应收分别保留；学员、产品、课程、组织来源可追溯 |
| `Is_Quit`、退班日期、审核/锁账字段 | 业务状态 + 正交财务/历史限制 | B/C | 不迁为可正常办理的 ACTIVE；旧单据锁账不自动等同整校月份锁定 |
| 旧 `Price_Discount`、优惠明细/活动码 | 报名优惠及历史类型/规则来源 | B | 只存总额可作当前计算候选，历史活动/审批关联仍需归档，避免二次折价 |
| 服务费及类型明细 | 服务费应收、已结算/已退及来源 | B/C | 不把服务费并入课程价格来凑总额；独立退费与收入规则待 Q1 |
| `H_Student_Money_Record` 等真实外部收支 | funds 收款/退款及旧来源、日期、方式 | B | 区分实收、账户支付、冲销、退款、撤销；不能把账户内分配再迁成外部收款 |
| `Is_Account_Pay`、报名支付关系 | 资金分配/释放或历史关系 | B | 映射到目标报名和资金来源；是否已计入期初要有排除规则 |
| 旧 `Pay_Money`/欠费汇总 | 对账参考及必要期初履约数据 | B | 汇总不是新增收款凭证；不能按汇总制造当期收入；未收与账户欠余额区分 |
| `H_Class_Student_CS_Item_Consume` | teaching 消费明细或历史归档 | B | 课次、课程、报名、结算版本、金额与课时；课时反推需真实样本核对 |
| `H_Student_Register_Consume` 等汇总 | 对账与历史/期初消费累计 | B | 逐项拆已消费、已退、剩余及金额；避免明细和汇总重复累计 |
| `Pre_Code` 拼接关系 | 跨报名承接或受限历史关系 | B/C | 保留两条报名来源，不无条件合并或断开；未实现续算时限制相应办理并显式报告 |
| 多教师/多校区/旧课次和未关闭课次 | 教务资源、课次关系及历史快照 | C | 当前单教师/教室模型不足时补建或完整归档，不能把多教师信息丢失 |
| 原合同、收据、附件、审计 | 私有原件、版本与来源归档 | B/C | 文件内容、元数据、访问权和查询路径一起迁移，不能只有文本备注 |

写入由各领域负责校验、授权、期间、并发和审计，迁移模块只处理来源、映射与编排。临时需要直接 SQL 的特殊步骤，应逐条评审并记录所有权/隔离/不变量，不能把现有旁路当范式。

## 4. 期初与历史明细不能重复计算

| 层次 | 需要明确的选择 | 禁止的捷径 |
| --- | --- | --- |
| 外部实收 | 迁真实历史交易，明确是否只读历史、是否影响当前经营报表 | 用累计 `Pay_Money` 造切换日普通收款，污染当期实收 |
| 账户余额 | 用余额期初，或由完整真实资金/分配流水重建 | 同一段历史既迁真实流水又叠加未排除的期初余额 |
| 报名应收与未收 | 原始约定+调整、已分配、尚欠分别承接 | 把欠费直接视为负账户余额而不确认含义 |
| 消费和剩余履约 | 保留决定模式 0～5 续算的累计/课程维度/已退及规则版本 | 只给总课时，不保留课程消费/退费维度；把消费额直接从账户余额再次扣除 |
| OPENING 可用性 | 明确余额是否可退、能否重新分配报名、受何期间约束 | 认为“能写 OPENING”就等于已实现所有历史资金后续操作 |

新系统当前分配以 receipt 为来源，单独 OPENING 余额的后续分配能力也必须专项核验。模式 4/5 的续算依赖退课后的净费用、净课时和历史已消费；不能只凭最终剩余量推定可继续计算。

## 5. 正确的对账层次

对账按同一源快照、租户、学校、日期边界、币种/单位、规则版本、源实体到目标实体映射进行。不能把不同基数直接作等式；下面是新系统不变量及旧侧应匹配的对应口径。

| 核对量 | 新侧不变量/核对方式 |
| --- | --- |
| 真实收款 | 同范围有效真实 RECEIPT 与旧外部实收逐笔/合计核对；OPENING 单独列示，不能相加冒充历史实收 |
| 账户总余额 | 带符号账户分录求和：期初 + 收款 + 释放 − 分配 − 已付现金退款等实际分录；旧侧匹配未分配账户口径 |
| 账户可用 | 总余额 − 有效冻结；与已付、取消退款分开核对；负余额语义另确认 |
| 报名净应收 | 原始应收 + 有效调整；课程价、服务费、优惠、已退分别可追溯 |
| 报名未收 | 净应收 − 当前有效分配；旧侧匹配该报名未收，不能拿账户余额替代 |
| 消费金额 | 按报名/课程/规则版本对比历史累计、已迁明细和期初累计；三者不能重复计入 |
| 课时 | 每个报名/必要课程：购买 = 已消费 + 已退 + 剩余；多报名汇总相等不能掩盖目标报名错配 |
| 业务关系与状态 | 主档、在读/退班、锁账/锁月、审批、拼接、多教师、附件引用及孤儿数量逐项核对 |
| 批次归属 | 每行应有值与该批对应目标分录/消费实际值、消费金额、状态核对；单列其他批次与人工调整 |

差异分级：阻断（金额/课时/权限/关键关系不确定）、需人工确认的例外、可解释非阻断差异。阻断级差异不得以“跳过但整体成功”进入真实业务；例外保留负责人、原因、源记录和处置，不通过补一笔不明收款抹平。

## 6. C1～C6 仍使用原编号沟通

| 编号 | 需要决定的内容 | 本轮修正后的建议；均待确认 |
| --- | --- | --- |
| C1 | 首批切换采用 FULL、OPENING 或 HYBRID 的哪种明细深度 | 先验证真实样本的在读续算和历史可查；FULL 仍保留为必须能力，不能选“不迁”取消需求 |
| C2 | 余额期初还是完整资金流水重建 | 依据旧侧可核验口径选择，期初与真实流水明确去重；撤回“按汇总造普通收款”的建议 |
| C3 | 拼接/超排的继续办理需求 | 保留源关系，需继续办理则补模型；暂不支持的对象受限并报告，不默认丢弃 |
| C4 | 优惠的承接层次与历史元数据 | 原价与优惠分开保留，冻结原结算口径；活动/审批来源可归档，不自动折进价格 |
| C5 | 历史逐课次的查询与追责要求 | 可以评估归档查询承担历史，但须确定完整度、访问权和查询入口；不是无记录丢弃 |
| C6 | 已退班/终止报名的展示与可办理状态 | 原状态与日期保留为终止/历史只读，不能默认 ACTIVE；补合法纠错/恢复路径需另确认 |

## 7. 进入真实试迁前的检查

先补领域导入契约、源库命名空间、目标报名精确关联、批次实际分录引用、干跑与提交同校验、原子性/部分成功和完整失败台账。然后用脱敏真实样本证明：重复运行不重复计账、多批次不互扰、异常不静默丢失、迁后消费/退费/锁月结果与人工预期一致。只确认 C1～C6 不足以保证可跑真实快照，还需实现与验收证据。
