## 1. 已确认结构原则

统一代码仓库，前后端分别构建部署；后端模块化单体，长任务按需独立运行；按业务领域组织，公开契约与内部实现分离，依赖边界通过自动检查固定。用户已接受该方案，见 DEC-003。

## 3. 业务所有权

| 模块 | 权威业务事实 |
| --- | --- |
| 租户与运营 | 租户开通、订阅、配额、可用状态 |
| 身份与授权 | 账号、角色、权限、数据策略、会话与未来委托 |
| 组织与资源 | 学校、校区、部门、员工、教师、教室 |
| 产品与价格 | 课程、班型、产品、价格版本、优惠规则 |
| 招生客户 | 线索、公私海、分配、跟进和转化 |
| 学员档案 | 学员、家长、联系人及关系 |
| 报名履约 | 报名、合同、进退转班与延期 |
| 教务排课 | 班级、课次、排课、发布、确认与考勤 |
| 资金结算 | 收款、分配、流水、消耗、退款、差额与锁月 |
| 报表查询 | 指标、只读投影、报表与导出查询 |

模块随实际开发增加，后续教学服务等按职责扩展；文件、审计、通知和任务是职责明确的公共能力，不设包揽全部业务的 common。

## 4. 模块内部

以 academic 为例：公开 api 契约；internal 下按 application、domain、infrastructure、web 分职责。简单模块允许简化，禁止为了目录对称增加空接口和空类。

其他模块只引用公开契约，不读写内部 Mapper 或直接修改他域表。公开契约不暴露持久化实体。应用服务完成授权、校验、状态和事务处理，HTTP、任务、未来 AI 只是不同适配入口。

自动检查至少覆盖模块循环依赖、内部类型越界、允许的依赖集合和启动装配模块的反向依赖。DEC-014 已选 ArchUnit，具体规则与 Maven 依赖约束在工程建立时验证；Spring Modulith 未设为必需依赖。静态依赖检查不替代动态 SQL 的数据所有权与授权验证。

## 5. 跨域原子操作

课次关闭通过应用用例完成权限与状态校验，调用教务状态变更和财务入账，在同一本地事务内成功或回滚。通知与投影可在提交后可靠异步处理。

采用单向依赖或专门用例编排，不能让教务与财务互相依赖。内部可组合步骤不作为绕过权限的外部入口。排课计算、导出等长任务复用业务服务，不复制规则。

## 6. 前端与未来 AI

按 feature 聚合页面、业务组件、请求协调与交互逻辑；通用 UI 和基础能力进入 shared，领域校验仍由后端负责。普通页面独立完成完整业务。

未来助手复用同一业务契约，不在聊天组件内部再实现资金、权限、状态或排课规则。后期入口变化以已有草稿、确认、任务与结果模型为基础，当前不创建 AI 服务。

R3-CORE-001 的目录、真实结果和边界见[核心技术组合验证记录](../../03-研发规范/工程质量/验证记录/20261031-核心技术组合验证记录.md)。独立原型内部为便于验证集中组织，不作为正式模块边界或领域划分的定稿。


SC01 的具体数据归属、组合用例与单向依赖见[首片领域与操作设计](../业务切片/首个业务切片领域与操作设计.md)。业务用例编排只调用各域公开契约，不跨域写表、不形成报名/教务/资金循环依赖；内部步骤不自动对外公开。正式模块和 Flyway 结构已建立，当前实现与剩余边界见功能台账；不能继续将设计初期“尚未创建正式模块”作为当前事实。


## 表所有权与跨域只读清单（REV-004）

业务表按 schema 唯一归属对应模块：identity（身份授权）、organization（学校与人员资源）、archive（学员联系人）、product（课程产品价格）、enrollment（报名快照、应收、优惠及退课时）、funds（收款、分配、账户流水、冻结、现金退款及请求账本）、teaching（班级、课次、考勤、消费及排课资源）、approval（审批）、finance（期间）、migration（暂存、批次与事实映射）、admissions（渠道客户跟进）。server 集中管理 Flyway，不因此拥有所有业务表。

共享 schema 也明确归属：audit.student_event→archive；product_event→product；enrollment_event→enrollment；funds_event→funds；teaching_event→teaching；approval_event→approval；period_event→finance；channel_event/customer_event→admissions；authorization_event/role_template_event/account_lifecycle_event→identity；resource_event→organization；business_event/operation_failure→platform。通用事件通过 platform 公开契约追加，不直接写他域审计表。infra.mail_key_verifier 归 organization；infra.spring_session 及属性表属于 server 装配的会话基础设施，使用独立会话角色。

以下登记当前经过 REV-004 只读评审的直接查询例外，限定现有用途，不授权他域写表或扩大敏感字段/学校范围：

| 调用实现 | 他域权威表 | 用途及约束 |
| --- | --- | --- |
| enrollment/EnrollmentService | archive.student、product.curriculum | 报名学员名称及课程标签，沿用报名读取范围 |
| funds/FundsService | archive.student、enrollment.hours_cancellation | 收款展示及退后金额，沿用资金/退费学校范围；退课时经报名契约写入 |
| identity/AccountAuthorizations、SchoolProvisioner | organization.unit | 授权选项、最后完整管理员覆盖；同租户 SCHOOL，停校仍保留管理员覆盖 |
| organization/EmployeeAccountLinkService | identity.account | 绑定账号身份与状态，限本租户及本校员工，账号生命周期经身份契约维护 |
| teaching/SchedulingService | organization.teacher、organization.room | 排课资源展示及冲突，限教务学校范围，资源经组织契约维护 |
| teaching/TeachingService | organization.teacher、organization.room、product.curriculum、enrollment.hours_cancellation | 教务展示、课程匹配与退后消费，消费只写 teaching；报名通过公开命令修改 |
| migration/LegacyMigrationService | archive.student、enrollment.enrollment、funds.receipt、funds.account_entry、funds.creation_request、teaching.consumption | 期初目标确认及事实对账；机构锁内复检迁移及资金/教务范围，事实经公开命令写入，迁移模块只写自己的批次 |

查询通过 TenantTransactions 的事务局部租户与 RLS。权威表结构/状态/精度变化须同步检查调用方授权和对账；后续优先提取领域只读投影契约，不继续扩张直接查询例外。

ModuleBoundaryTest 自动发现正式模块，检查 internal/server 反向依赖和循环。SqlOwnershipTest 扫描正式模块 SQL 字面量及相邻常量拼接，禁止他域直接写表，并固定上述实现的只读引用集合及共享表归属。它有常量拼接反例自检，但不解析带变量的动态表名、任意反射、存储过程或完整 SQL 语义；这些变更仍需评审和数据库验证。

## 机构锁与异常组合边界（REV-004）

授权、停校、教务、资金及锁月共用 `authorization:tenantId` 的 PostgreSQL 事务 advisory 锁，要求 READ COMMITTED。锁内重读授权、学校和期间：闸门先提交则排队写入拒绝，业务先持锁则先完成再让闸门生效。失败回滚权威事实、请求账本和成功审计并释放锁，同请求可重试。

停校保留历史读取、禁止业务事实变更，涵盖发布/考勤/关课/期初消费、撤销收款/分配/释放、确认退款已付及取消未付退款。恢复后仍按当前状态与版本办理。外部现金已交付但登记失败等不确定结果，仍按退款异常闭环核实，不自动重付。

同机构不同学校也会排队，异机构锁独立。本轮用阻塞 PID 和同/异机构收款小样本记录等待与延迟，保留原锁。真实岗位负载、长事务、公平性、连接池及多实例容量在 REV-018 验收，不凭小样本放宽保护；实际结果见[异常与并发组合验证](../../03-研发规范/工程质量/验证记录/20261103-REV-004异常与并发组合验证记录.md)。
