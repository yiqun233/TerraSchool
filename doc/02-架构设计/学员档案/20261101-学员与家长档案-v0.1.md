## 范围与旧系统证据

本批是报名到退款闭环的第一步：建立学员主档、家长/联系人身份与关系，落实按学校的数据范围、敏感字段权限和重复档案处理，为后续报名提供稳定主体。用户已按业务依赖确认顺序：学员与家长档案 → 课程与产品 → 报名与收款 → 排课考勤消费 → 退款与闭环验收。

旧结构 `H_Student` 保存学员编号、姓名、性别、生日、证件、手机、邮箱、归属校区、状态、审核与合并标记；`H_Student_Guardian` 以学员编号与监护人序号保存姓名、电话、证件、职务、单位、关系；`H_Student_Customer` 保存家长网登账号与密码。旧表不自动批准新字段的权限、去重和登录能力：本批不迁移网登账号与密码，不复用「一个字段塞多值」的做法。

## 数据归属与对象

| 对象 | 关键内容 | 权威边界 |
| --- | --- | --- |
| `archive.student` | 学员号、姓名、英文名、性别、生日、证件类型/号码、电话、邮箱、归属学校与校区、状态、版本 | 学员是稳定身份；显示名称与手机号不是主键 |
| `archive.contact` | 联系人姓名、电话、备用电话、邮箱、微信、版本 | 联系人与学员分开，可被多位学员复用 |
| `archive.student_contact` | 学员×联系人的关系、是否主要联系人、顺序 | 同一学员最多一个主要联系人 |
| `archive.student_request` | 请求身份、操作者、学员号与参数摘要 | 同主体同请求号只产生一次创建事实 |
| `archive.student_number` | 按租户递增的下一个学员号 | 编号规则待业务确认，当前仅作可读标识 |
| `audit.student_event` | 创建、修改、敏感字段读取 | 只记录动作与变化字段名称，不保存证件号等正文 |

学员归属学校为本批唯一归属，跨校共享与转校需后续显式操作，不因报名或改校区自动改写归属。校区可空，有值时必须是同一学校的启用校区。

## 权限与数据范围

动作进入统一权限目录，与其他模块共用同一套 ALLOW/DENY 与学校范围计算（DENY 优先，维护范围与查看范围相交）：

| 动作 | 含义 |
| --- | --- |
| `STUDENT_READ` | 查看学员列表与详情（敏感字段脱敏） |
| `STUDENT_MAINTAIN` | 新建、修改学员与联系人（需同时具备查看范围） |
| `STUDENT_SENSITIVE_READ` | 在查看范围内返回完整证件号、电话、邮箱与生日 |

敏感字段在服务端脱敏后才返回，前端拿不到原文：电话保留前三后四位（`138****5678`），证件号只保留后四位（`****1234`），邮箱保留首字母与域名，生日只到年月。返回完整值时在同一事务写入 `STUDENT_SENSITIVE_READ` 审计，可追溯谁看过。脱敏不替代数据库权限，`archive` 表对运行账号只开必要读写，无删除与改表权限。

## 重复档案处理

- 证件号是硬重复：同租户同证件类型下由唯一索引保证唯一，重复创建返回 `DUPLICATE_CERTIFICATE`，不自动合并、不覆盖已有主档。
- 同名且同生日、或同名且同电话是软重复：创建成功并返回 `possibleDuplicates` 提示，由人工核验；提示不阻断，也不会自动合并或改写联系人与报名。
- 联系人按「姓名 + 电话（或姓名 + 邮箱）都一致」才复用；只有电话相同说明不了是同一位家长，因此新建联系人并在返回中给出被复用标识。
- 本批不提供合并、拆分、归属变更与删除；这些操作需要独立单据、影响评估与审计，列入后续任务。

## 操作与契约

| 操作 | 契约 | 说明 |
| --- | --- | --- |
| 能力查询 | `GET /api/archive/capabilities` | 当前可维护学校列表与是否可读敏感字段 |
| 列表 | `GET /api/archive/students?page&size&search` | 先按学校范围过滤再分页；按姓名或学员号模糊检索 |
| 详情 | `GET /api/archive/students/{id}` | 返回联系人与脱敏标记 |
| 新建 | `POST /api/archive/students` | 携带 `requestId` 幂等身份；返回学员、联系人复用与重复提示 |
| 修改 | `POST /api/archive/students/{id}/update` | 整套提交并携带 `expectedVersion`；联系人整套替换 |
| 启停 | `POST /api/archive/students/{id}/status` | 只提交版本与目标状态，避免无敏感权限的账号把脱敏值写回 |

错误使用真实 HTTP 状态与 RFC 9457 问题详情：`403 ACCESS_DENIED`、`409 VERSION_CONFLICT`、`409 IDEMPOTENCY_MISMATCH`、`409 DUPLICATE_CERTIFICATE`、`400 INVALID_INPUT`。提交内容含脱敏标记（例如 `***` 邮箱）时按无效输入拒绝，防止掩码被写成权威值。金额与课时不涉及本批；字段均使用字符串，日期使用 `YYYY-MM-DD`。

## 事务、并发与审计

新建与修改在应用服务内完成权限复核、校验、写库与审计，页面与测试中的第二入口调用同一服务：

1. 事务外先按当前快照取得查看/维护/敏感范围；
2. 事务内取与学校停用、授权替换共用的机构锁，再复核范围，防止锁前撤权；
3. 锁内校验学校启用与校区归属；
4. 创建使用「租户 + 操作者 + 请求号」的事务级咨询锁，重试返回首次结果，换参数返回 `IDEMPOTENCY_MISMATCH`；
5. 修改使用 `id + version` 条件更新并检查影响行数，过期版本返回 `VERSION_CONFLICT`；
6. 成功审计与业务同事务；失败/拒绝仍由独立失败审计记录（HTTP 路径映射到 `STUDENT_CREATE`、`STUDENT_UPDATE`、`STUDENT_SENSITIVE_READ`）。

学员跨租户写入由强制 RLS 拒绝；`archive` 表启用并强制行级安全，租户取自连接上的 `app.tenant_id`。

## 本批非目标

- 学员/家长网登账号、密码与登录（旧 `H_Student_Customer` 的账号能力）不在本批，也不新增学员端入口；
- 合并、拆分、归属变更、批量导入与旧库装载；
- 按电话检索（等同暴露敏感事实，待与字段策略一并确认）；
- 完整字段级权限策略、脱敏字段单独授权、导出与打印；
- 报名、收退款等资金事实。

## 已知边界

- `archive` 的数据访问沿用现有模块的做法：表不在 jOOQ 代码生成范围内，使用参数化 SQL，类型与边界由应用服务与测试保证；
- 「我的权限」页面仍只展示组织与授权范围，尚未展示学员动作，需在字段策略批次补齐；
- 学员号前缀与位数是临时约定，正式编号规则（含合同/收据编号）随产品与报名批次确认；
- 脱敏只覆盖返回展示，数据库中的权威值仍是完整值，日志与失败审计不写入这些字段。
