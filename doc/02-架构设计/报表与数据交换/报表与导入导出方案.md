## 1. 已确认范围

用户确认首期日常 Excel 导入优先新版 .xlsx 模板，旧文件可先转换；并接受受控指标查询 + Apache POI + 版本化导入预检 + 持久导出任务与结果快照的组合。

页面、导出和未来 AI 共用业务口径与授权契约；查询复用 jOOQ/PostgreSQL，长任务和结果复用 DEC-009/010，当前不创建独立数仓、BI 或通用任务平台。既有 11 项报表/查询及 1 项导出能力仍为 P0 候选，逐项对照旧系统与验收预期，不因技术确认自动批准全部菜单或计算口径。

报表和 Excel 已由 DEC-020 确认；PDF 导出与合同/收据/课表打印随后统一由 DEC-021 确认输出流程及 HTML/CSS + Chromium 首选方向，见[PDF 打印与模板方案](../打印与文档/PDF打印与模板方案.md)。既有套打保留，模板编辑方式、具体版本和效果待验证，图表库、CSV 首期能力及可视化编辑器未自动批准。

## 2. 指标目录与受控查询

指标和查询元数据以受版本控制的代码/声明维护，记录稳定名称/代码、业务定义、单位与精度、时间归属、公式版本、合法维度/筛选/排序/关联、数据与字段权限、新鲜度和查询边界。用户保存的是合法组合，不是可任意执行的 SQL 或脚本。

收款、确认收入、课时消耗和余额分别定义，权威事实仍归业务模块；报表不另维护一份权威余额。跨域查询遵循公开契约或受控只读投影，特殊联合查询记录所有权与维护边界。关联前明确粒度，避免一对多连接重复聚合金额/课时或让比例分子分母使用不同数据范围。

页面、图表、导出与未来 AI 结构化请求复用相同指标目录和查询契约。输入只允许已定义指标、维度、运算和参数，拒绝任意 SQL、字段/表达式拼接及无界查询；参数化、范围/时间/行数/开销约束继续由服务端执行，不信任模型或前端自报权限。

查询在授权范围内聚合和分页，覆盖详情、选项、汇总和下钻；缺失租户拒绝，实际事务连接使用普通受限角色和 RLS。字段授权同样影响返回列及组合能力，不能因只返回汇总就默认可读敏感事实。

## 3. 查询性能与结果一致性

普通查询先使用受控 jOOQ/PostgreSQL，实现有界排序/分页与必要索引。较重查询按真实负载评估汇总、物化或专用只读投影，显示数据更新状态，不直接将投影当作实时事实；投影/缓存有自己的租户、字段与撤权协议，不能假定自动继承原表隔离。

实时经营查询、已锁定财务期间与冻结结果区分，公式/期间版本明确。相同口径不保证不同时刻相同数值；需要复现时使用同一结果快照或固化期间版本。单纯限制某个时间字段，不能自动解决并发更新、回填和分批读取的一致性。

较小结果可采用有界一致读取；较大导出优先形成受控结果快照/中间数据后再生成文件。明确查询隔离、快照标识、筛选/列与指标版本、数据范围及生成完成状态；数据库读取有资源/时间边界，不将渲染、对象上传和用户等待放入同一个长事务。

分页或游标不是一致性协议本身；持久快照/中间结果的权限、空间、清理和版本也需设计。jOOQ 延迟读取须结合 pgJDBC fetch size/事务条件实际验证，不能以调用流式 API 断言没有全量加载。

## 4. Excel 工具、类型与资源

采用 Apache POI 做业务薄封装：普通工作簿按实际规模处理，大文件读取使用事件式 API、大文件写入使用流式 API。模板、列映射、字段校验和结果报告由业务契约声明，不建设任意表名/字段写入的通用入库引擎。

- 日常导入优先版本化 .xlsx 模板；旧 .xls/旧模板可先转换，转换仍检查列、值、前导零和时间/数值语义，不能只改扩展名。首期不承诺直接兼容全部历史列模板。
- 手机号、编号、证件号、UUID 等使用明确文本类型。金额和课时沿用 BigDecimal/numeric、单位与业务精度，不能无条件转 double 后宣称精确；超过 Excel 有效数值精度时采用明确标识的精确文本，权威计算仍在后端。
- 用户内容按文本处理，防止被生成公式。导入模板要求明确值，不自动执行公式、宏或外部链接，不以公式缓存结果作为权威财务输入。
- 校验实际内容与模板版本，限制文件解压/解析、工作表、行列、单元格和样式等资源；大文件堆内存、临时磁盘和句柄一起控制，成功/失败/取消后清理。
- POI 的共享字符串、合并区域等仍可能占内存；流式写入不代表数据库查询或临时文件也自动有界。模板/文件规模和 Excel 客户端兼容性按样本验证。

EasyExcel 原仓库已归档，未选为新项目默认依赖；不自动引入替代 fork。CSV、特定图表库、复杂公式或其他文件格式按实际需求另评估。

## 5. 导入预检与业务提交

目标流程：上传固定文件版本 → 解析/列映射 → 校验和预检 → 展示错误及影响 → 确认提交 → 按业务单元执行 → 结果/审计。

模板定义版本、字段/类型/单位、代码表、引用匹配、必填/空值与错误语义。解析只生成规范化输入和预检结果；实际写入调用对应应用业务操作，复用授权、状态、并发、幂等和事务规则，不让导入框架直接跨域写表。

- 匹配候选与真正关联分开，姓名/手机号不能直接认定同一学员或自动合并；覆盖、合并和危险变更明确确认。
- 批次确认关联文件版本、映射、预检和必要目标版本；执行前重新检查权限与数据状态，过期预检不能成为永久写入授权。
- 错误报告说明行/字段/原因与可处理建议，保护无权档案信息和敏感字段，不因查重错误泄露其他机构数据。
- 各模板声明整批或部分成功，按完整业务单元定义原子性。档案可按规则分批，报名/资金保持完整业务事务，不用固定行数切块破坏不变量，也不静默跳过错误。
- 批次和已完成业务单元有稳定执行身份与结果，重试只执行应执行内容；不单靠文件哈希全局去重而误拒合法再次导入。取消和失败不能把已提交结果伪装成已回滚。

原始材料、预检与正式结果分别授权和保留，进度与错误数可追踪。完整/部分旧系统数据库迁移仍按独立迁移协议、来源映射和对账执行，不缩减为日常 Excel 导入。

## 6. 导出任务、文件与撤权

小查询可同步；较大导出复用持久任务。任务记录可信发起主体、租户、条件/列、指标与结果版本，执行时复检授权并限制资源/并发。数据库读取、文件生成、固化关联与失败清理各阶段有明确状态，最终结果通过文件 ID/版本管理。

创建、执行、结果查看和下载分别授权与审计；权限收窄后既有产物也需失效或重生成，不能仅检查用户仍有导出功能。快照本身含有历史范围数据，其查询/下载与清理遵守同样协议，短时签名链接不提供立即撤销所有下载的保证。

文件默认私有，元数据关联原始查询、任务和模板/格式版本；结果过期和物理清理按用途定义。导出完成不自动发送原文到外部系统，也不要求浏览器全量拉取数据再生成文件。

## 7. 未来 AI 复用

AI 问数将自然语言转换为指标/维度/筛选等受控参数，服务端校验并执行；自由组合限于既定业务目录，不向模型提供数据库连接或任意 SQL 权限。结果可生成页面、图表或授权导出，展示真实新鲜度/期间/版本。

AI 资料处理和导入助手以后复用相同材料版本、预检/确认、提交和结果接口。模型不决定合并、授权或事务，原始文件内容视为不可信数据；当前不开发 AI、报表设计器或完整查询平台。

## 9. 官方依据

- [Apache POI 事件/流式 API](https://poi.apache.org/components/spreadsheet/how-to.html)及[限制](https://poi.apache.org/components/spreadsheet/limitations.html)：读取/写入资源特性与兼容性边界。
- [EasyExcel 原仓库](https://github.com/alibaba/easyexcel)：讨论时已归档，未作为当前默认依赖。
- [jOOQ 延迟读取](https://www.jooq.org/doc/latest/manual/sql-execution/fetching/lazy-fetching/)与[pgJDBC 查询](https://jdbc.postgresql.org/documentation/query/)：游标和驱动条件需配套验证。
- [PostgreSQL 事务隔离](https://www.postgresql.org/docs/current/transaction-iso.html)：一致读取机制，不替代业务口径与结果快照协议。
- [Excel 规格与限制](https://support.microsoft.com/en-us/excel/excel-specifications-and-limits)：数值精度和格式范围。
