## 1. 确认范围

DEC-011 确认 REST/JSON + OpenAPI；主要业务 ID 使用 UUIDv7；金额与课时采用 Java BigDecimal、PostgreSQL numeric，接口用十进制字符串；区分日期、当地业务时间、实际时刻和业务期间；统一分页、空值、稳定枚举、RFC 9457 错误及幂等/并发语义。

本条确定表示和契约约束，不改变旧系统业务公式，不提前确定每个字段的精度/舍入/尾差、业务编号规则、时间配置粒度或全部 API 字段。具体 OpenAPI 规范版本、生成器、UUID 库、前端小数/日期工具和配置仍需验证。用户随后授权 R3 独立原型，已从实际 HTTP 导出契约并生成客户端类型，具体版本与已验证范围见文末。

## 2. 业务操作与契约权威

普通资源查询/修改与发布、退款、锁月等明确业务动作分开。动作的授权、前置状态、输入、版本、幂等、事务和副作用在应用契约中表达；不提供修改任意表/字段的万能入口，也不允许通过普通状态赋值绕过发布、审批或财务规则。

公开 DTO、显式校验及接口声明是服务端实现来源，构建导出 OpenAPI，再派生前端类型和客户端；不手工维护两套同字段 schema。生成结果仍需验证实际 JSON，尤其数值字符串、可空、枚举、分页、错误及认证/CSRF 行为，不能让文档与序列化配置不一致。生成文件不手工修补，契约变化先改权威定义。

领域实体、jOOQ Record/生成类型和内部服务不直接出现在对外契约。对输入设置允许字段，调用方不能通过附加 tenantId、actor、余额、审计状态或 confirmed 等字段获得权限或跳过业务动作。更新字段的接受范围由具体操作决定。

每个操作有稳定名称/标识、中文说明、输入单位、权限/状态前提、错误和副作用。内部任务通过同一应用服务调用，不要求所有调用都转成 HTTP。未来 Agent 仅适配已选择的操作，工具描述/参数校验不代替服务授权，OpenAPI 不自动全量变成工具白名单。

官方依据：[OpenAPI 规范](https://spec.openapis.org/oas/latest.html)。引用最新说明不表示锁定其版本，生成/消费工具兼容后再确定规范版本。

## 3. 身份、编号与枚举

主要业务实体首选 UUIDv7，数据库用原生 uuid，JSON 用规范字符串；字典与枚举的稳定业务代码不要求机械改为 UUID。具体生成位置/库及与数据库版本的组合后续验证，不自行手写生成算法或依赖尚未批准的数据库版本特性。

UUIDv7 的时间信息不代替业务时间和显式排序，也不构成访问权限。相较自增整数，其存储/索引及排查成本更高；采用明确业务编号辅助人工查找，不将手机号、名称、合同号或数据库行号当作稳定关联身份。

学员号、合同号、收据号等与主键分离，编号范围、唯一性、改号/作废规则按具体业务确定。迁移保留来源库、旧 ID/编号与新 ID 的映射，不将旧部署中重复的整数直接作为全局新主键。

枚举采用稳定业务代码，中文名称用于展示。旧数字 0–5 等编码是迁移和业务证据，需显式映射，不能以 Java 枚举 ordinal 或显示文字作为对外身份。枚举扩展可能影响客户端分支，纳入兼容检查。

官方依据：[RFC 9562 UUIDv7](https://www.rfc-editor.org/rfc/rfc9562.html)。

## 4. 金额、课时与精度

权威金额、单价和课时使用 BigDecimal/numeric，接口输入输出为十进制字符串，单位在字段及操作说明中明确。金额按元、课时按课时表达，币种处于明确业务上下文；不要求每个字段重复币种对象，也不因此增加首版多币种范围。

例如 amount 为 "1280.50"、currency 为 "CNY"、lessonHours 为 "1.50"；这些值是表示示例，不是统一字段名或精度上限。整数字段如合理范围内的计数、页码仍按其类型表达，不将全部 JSON 数值都改成字符串。

前端不得把金额/课时字符串转成普通 number 计算权威结果；需计算时通过统一精确小数工具，并由服务端最终校验。Java 也不能先用 double 计算再包装 BigDecimal，序列化与导入导出必须遵循同一单位和精度协议。

numeric(p,s)、输入合法范围与小数位、单价/比例/中间结果精度、实收/结算结果精度、舍入时点和尾差分别按金标准定义，不统一强制两位小数。超精度输入须按契约拒绝或明确处理，不依赖数据库隐式舍入替代业务规则。

旧系统分、0.01 课时、分钟及部分“分 × 60”的字段逐列转换和对账，不以名称猜单位，也不让新字符串表示掩盖换算错误。迁移后固化历史不因数值类型变化被重新计算。

官方依据：[Java BigDecimal](https://docs.oracle.com/en/java/javase/25/docs/api/java.base/java/math/BigDecimal.html)、[PostgreSQL numeric](https://www.postgresql.org/docs/18/datatype-numeric.html)。Java/PostgreSQL 引用版本不自动成为工程锁定版本。

## 5. 日期、时刻与业务期间

| 语义 | 约定 | 注意事项 |
| --- | --- | --- |
| 日期 | YYYY-MM-DD，与 date/LocalDate 等语义匹配 | 生日、上课日不通过 UTC 转换改变日期 |
| 实际发生时刻 | 有明确时间线语义，接口统一输出 UTC；数据库/Java 使用相应类型 | 操作、收款、审计时刻不使用无时区含义字符串 |
| 当地业务时间/周期规则 | 日期/当地时间或周期规则与明确业务时区配合 | 每周五 19:00 的排课规则不能仅存一个 UTC 时刻 |
| 财务等业务期间 | 显式期间及归属规则 | 不按服务器当前 UTC 日期自动推断锁月或收入归属 |

需要保留原始时区时显式记录时区名称，不能认为 timestamptz 保存了原时区；服务端/前端不依赖机器隐式本地时区。业务时区默认值和作用范围按已有业务核验，本轮不擅自增加全球运营或多时区产品承诺。

官方依据：[PostgreSQL 日期时间语义](https://www.postgresql.org/docs/18/datatype-datetime.html)。精确格式、精度、日期库和转换配置在实现前统一验证。

## 6. 空值、分页与成功响应

输入必填、可选和可空分别声明。部分修改中缺字段表示不修改，null 仅在契约允许清空时表示清空；空串、零和 null 不自动互换。完整替换/创建按各自必填要求执行，不将部分修改规则机械套到所有操作。具体 PATCH 格式与更新 DTO 后续细化，不默认允许任意字段赋值。

普通管理列表采用页码分页；日志、轨迹等连续读取按需游标分页。页码起点、默认/最大页大小、total 是否必返与游标格式在契约模板中统一后再锁定；限制无界查询，大结果走持久导出任务。排序有允许字段和稳定的并列处理，不依赖数据库自然顺序。

权限先于分页、聚合和计数；游标也不能承载可篡改的授权或绕过当前权限。分页不自动保证并发修改下的完整快照；报表/导出的数据截止点和一致性由业务查询契约说明。

成功返回明确 DTO，分页返回统一分页结构，不强制所有成功结果包一层无意义状态码。HTTP 状态表达真实结果：创建、任务接受、无内容等按相应语义处理，任务接受不代表业务已完成。下载、上传和未来流式接口使用各自明确内容类型，不强制包装成普通 JSON。

## 7. 错误协议

失败采用真实 HTTP 状态与 RFC 9457 Problem Details，使用相应媒体类型，并扩展稳定业务码、字段错误和追踪标识。未认证、权限不足、输入错误、对象不存在、状态/版本冲突与系统失败按统一规则区分，不全部返回 HTTP 200。

业务码面向机器分支，例如 SCHEDULE_RESOURCE_CONFLICT；中文说明面向人。字段错误标识实际输入位置和原因；调用方不能通过解析中文消息猜应重试、补字段或重算。明确各码的处理建议，不把所有异常标成可重试。

错误中的资源、差异和上下文仍受权限约束；隐藏对象存在性的场景使用一致策略，不能泄漏其他租户数据。HTTP 错误结构不包含 SQL、堆栈、凭据或原始敏感材料。任务失败与内部应用错误可映射到相同业务语义，不要求内部返回 HTTP 对象。

官方依据：[RFC 9457 Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html)。具体错误目录、字段名称与状态映射在接口模板中细化。

## 8. 幂等、并发与确认

关键非天然幂等操作携带稳定请求身份，按租户、主体、操作及参数摘要校验，重复执行不重复产生业务效果。相同键不同参数拒绝，历史结果返回仍检查当前权限；HTTP 头与内部命令的适配位置、保留期限和并发协议后续确定，不能仅靠前端禁按钮或内存缓存。

更新、发布等动作携带业务版本条件；版本/状态冲突明确失败，禁止静默覆盖。幂等解决重复发送，版本检查解决并发变化，二者不能混用。具体 body/header 形式和错误映射统一后落地，若使用 HTTP 条件请求须遵循其标准语义。

确认/审批凭证绑定实际动作、对象、内容、主体/租户、版本和有效期，执行前重新鉴权及预检；模型传入 confirmed=true 不构成批准。任务 ID、追踪 ID、幂等身份和审批凭证各有职责，不相互替代。

## 9. 兼容、验证与未决

生成链路纳入构建检查，验证真实响应和 schema 一致、客户端重新生成可编译，并检查契约差异；不机械认为新增字段或枚举总是兼容。API 主版本路由/协商、弃用策略与 OpenAPI/生成工具版本继续确定，避免前端、接口描述与实际应用各维护一套事实。

首次工程验证至少覆盖 UUID 往返/旧 ID 映射、金额/课时字符串及精度边界、时区/日期/期间不混淆、缺字段/null/空串、权限后分页和稳定排序、正确错误媒体类型/状态、幂等并发、旧版本提交与过期确认拒绝，以及模拟第二入口调用一致。

未决为具体工具/版本、UUID 生成方案、字段精度/范围/单位细节、编号与时区配置、分页模板、错误目录、契约兼容门禁和凭证适配。R3-CORE-001 已验证 UUIDv7 往返、金额字符串/大数、日期与 UTC、可空字段、数字金额/越界租户字段拒绝、权限错误及实际生成/编译；见[验证记录](../../03-研发规范/工程质量/验证记录/20261031-核心技术组合验证记录-v1.0.md)。分页、旧 ID 映射、真实业务幂等/并发、完整错误目录与确认凭证仍未覆盖。
