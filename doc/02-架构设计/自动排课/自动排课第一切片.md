## 范围

旧系统排课有单班、多班、自动排教师与教室；本切片只做**单班、固定时段、按周几批量生成**，并把冲突判断做成"可用/跳过 + 原因"的预览。

| 做 | 不做（明确列出） |
| --- | --- |
| 按周几 + 固定时段在日期范围内生成草稿课次 | 自动选教师/教室（本轮教师与教室由调用方指定） |
| 同班重叠、同教师重叠、同教室重叠、重复时段四类冲突 | 教师活动/休假、教室预订、座位数、跨校区距离 |
| 预览不写库、确认才落库、重复确认幂等 | 深度交换搜索与"排不下再调整" |
| 生成后仍是草稿，发布/确认/关闭走既有状态机 | 多班联合排课与班级优先级 |

## 规则

- 日期范围 ≤ 180 天，候选时段 ≤ 400 个，避免一次生成过多；
- 周几为 1–7（ISO），至少一个；时段 `HH:mm` 且结束晚于开始；课时 > 0、最多两位小数；
- 班级必须 `ACTIVE`、学校在用、调用方有该学校的 `TEACHING_MAINTAIN`；
- 冲突判定顺序：完全相同（`DUPLICATE`）→ 同班重叠（`LESSON_OVERLAP`）→ 教师重叠（`TEACHER_CLASH`）→ 教室重叠（`ROOM_CLASH`）；
- 确认只插入 `available` 的时段，状态为 `DRAFT`；重复确认会因为 `DUPLICATE` 全部跳过，因此天然幂等；
- 教师/教室为空时跳过对应冲突检查（相当于不占用资源）。

## 契约

| 操作 | 契约 |
| --- | --- |
| 预览 | `POST /api/teaching/classes/{id}/schedule/preview` |
| 确认 | `POST /api/teaching/classes/{id}/schedule/confirm` |

请求体（`ScheduleRule`）：`startDate`、`endDate`、`weekdays[]`、`startsAt`、`endsAt`、`hours`、`teacherName?`、`roomName?`、`topic?`。

预览返回 `SchedulePreview`（候选数、可排数、跳过数、逐时段原因）；确认返回 `ScheduleResult`（创建数、跳过数与 `日期:原因` 列表）。

新增错误码：`SCHEDULE_RANGE_INVALID`、`SCHEDULE_RANGE_TOO_LONG`、`SCHEDULE_WEEKDAY_REQUIRED`、`SCHEDULE_WEEKDAY_INVALID`、`SCHEDULE_TIME_INVALID`、`SCHEDULE_HOURS_INVALID`、`SCHEDULE_NO_DATE`、`SCHEDULE_TOO_MANY_SLOTS`、`CLASS_NOT_ACTIVE`。

## 为什么不做"自动选教师/教室"

旧系统的 `ClashTypeDictionary` 有 15–23 种冲突原因，其中教师活动、休假、教室预订、座位不足、跨校区距离都属于软约束，且旧文档明确写着"分类必须按操作定义，需教务确认"。在这些规则没确认前，自动选资源只会给出看似合理、实际不可用的结果。因此本轮把资源选择留给调用方，把冲突如实报出来。

## 已知边界

- 没有"锁定课次不参与重排"（本轮不重排，只新增）；
- 没有最小课间间隔、午休/晚休、休息日与节假日；
- 没有多班联合与班级优先级排序；
- 没有失败后的交换搜索，排不下就是跳过并给出原因；
- 教师与教室已关联员工/教室实体（`V22__lesson_resources.sql` 起）；自由文本仅作为历史数据兼容输入。

## 教师/教室实体化（后续切片）

第一切片把教师与教室当自由文本，这会让"同一老师两处上课"只能靠名字碰运气。本切片把课次挂到真实资源上：

| 项 | 内容 |
| --- | --- |
| 数据 | `teaching.lesson.teacher_id` / `room_id`（可空）+ 外键到 `organization.teacher` / `organization.room`；名称仍作快照保留 |
| 回填 | 既有课次按同校同名回填，找不到同名的保持为空（历史文本不强行匹配） |
| 写入 | 创建课次与自动排课时可传 `teacherId`/`roomId`：校验同校且在用，名称由实体回填；只给名称仍按原方式工作 |
| 冲突 | 有实体时按 `teacher_id`/`room_id` 比较，同时兼容历史同名文本（`teacher_id=? or teacher_name=?`） |
| 校验 | 跨校资源返回 `RESOURCE_NOT_IN_SCHOOL`，停用资源返回 `RESOURCE_INACTIVE` |
| 前端 | 自动排课弹窗的教师/教室改为资源下拉（`/api/organization/resources/{kind}/options`） |

这样"同一老师同一时段"不再依赖名字一致，改名也不会让历史冲突检测失效。
