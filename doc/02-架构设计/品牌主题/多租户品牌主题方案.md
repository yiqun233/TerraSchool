## 1. 背景与范围

培训机构客户需要“登录后就是我们的系统”。旧系统的 Logo 是进程级单例，一个部署只有一份机构配置
（见[组织与数据源考证](../../06-旧系统研究/组织与数据源考证.md)）；SaaS 多租户下必须按租户动态下发。

本方案解决四件事：

1. 租户可更换 Logo、品牌色与系统显示名；
2. 换色后所有页面仍满足可读性与对比度要求；
3. 平台运营端与租户端的主题互不污染；
4. 界面、导出与打印使用同一份品牌数据。

非目标（明确不做）：暗色模式、完全白标、自定义布局/密度/圆角/字体、租户皮肤市场、按用户设置主题。
初版不支持客户内网独立部署；将来启用私有化时按单租户写入同一张品牌表，不另设“配置文件写死”的第二条路径。

## 2. 已确认决策

| # | 事项 | 结论 | 影响 |
| --- | --- | --- | --- |
| D1 | 账号与租户 | 一个账号只属于一个租户（`identity.account.tenant_id NOT NULL`） | 登录后租户唯一，主题只需解析一次；不做会话内切换 |
| D2 | 私有化部署 | 初版不考虑 | 不为单租户部署保留第二套品牌来源 |
| D3 | 平台端入口 | 同源路径 `/platform`，暂不配独立域名 | 与租户端共享源站；主题隔离靠构建与路由，不靠域名 |
| D4 | 租户端入口 | 规划为子域名（`<code>.主域`），证书由平台代管；当前无域名环境先按“登录后应用品牌”降级 | 代码保留 host→租户 解析点，域名到位后不改主题逻辑 |
| D5 | 前端构建 | 同一仓库、Vite 多入口独立构建 | 平台端与租户端可分别发布，共享组件与令牌 |
| D6 | 可改范围 | 预设品牌色、Logo、系统显示名、favicon | 布局、密度、圆角、字体、状态色一律不可改 |
| D7 | 治理 | 租户管理员自助 + 平台可代改；改完立即生效；保留最近 10 版可回滚 | 需要版本号与审计 |
| D8 | 预设色板 | 6 个（冷色 4 + 中性 2）；P0 不开放自定义取色 | 自定义色放到 P1，且必须过对比度门禁 |

## 3. 三层主题模型

| 层 | 内容 | 归属 |
| --- | --- | --- |
| L0 骨架 | 间距、字号、行高、圆角、密度、导航结构、表格样式、四态样式 | 平台锁定 |
| L1 品牌 | 品牌色及其派生色、Logo、系统显示名、favicon | 租户可配，受控 |
| L2 语义 | 成功、警告、危险、进行中、中性，以及图表分类色 | 平台锁定，永不跟随品牌 |

### 3.1 品牌色允许与禁止

| 允许出现 | 禁止出现 |
| --- | --- |
| 主按钮、当前导航项、文字链接 | 状态标签、错误/警告提示条 |
| 选中行左侧指示条、选中态背景（浅色） | 危险操作按钮、危险确认弹窗 |
| 进度条、图表主系列 | 侧栏/顶栏大面积背景 |
| 向导当前步骤、焦点环 | 表格斑马纹、页面大色块 |

侧栏背景固定为白色。允许深色侧栏会把“骨架”交给租户，对比度和导航可读性无法兜底，因此不开放。

## 4. 品牌令牌

前端只消费以下变量，不直接读 seed。

| 变量 | 含义 | 用法 |
| --- | --- | --- |
| `--ts-brand` | 品牌主色 | 主按钮底色、当前导航文字、进度条 |
| `--ts-brand-hover` | 悬停 | 主按钮 hover |
| `--ts-brand-active` | 按下 | 主按钮 active |
| `--ts-brand-soft` | 浅底 | 当前导航底、选中行底 |
| `--ts-brand-line` | 描边 | 选中行左边条、焦点环 |
| `--ts-brand-link` | 链接色 | 正文中的文字链接（单独保证对白底 ≥ 4.5:1） |
| `--ts-on-brand` | 主色上的文字色 | 主按钮文字，按对比度取 `#fff` 或 `#1f2937` |

映射到 antd：`colorPrimary`、`colorPrimaryHover`、`colorPrimaryActive`、`colorPrimaryBg`、
`colorPrimaryBorder`、`colorLink`、`colorTextLightSolid`。开启 `theme.cssVar`（前缀 `ts`）后，
antd 自身生成 `--ts-color-*` 变量；上表的 `--ts-brand*` 是同一组值在根元素上的别名，
供 CSS Modules 引用。两处值必须来自同一次派生结果，不允许各写一份。

L0 的间距、字号、密度等令牌由[界面与交互规范](../../03-研发规范/界面与交互规范.md)定义，本方案不复制。

## 5. 品牌色管线

```text
预设 seed / 自定义 hex
  → 对比度校验（不过则自动调整或拒绝）
  → 派生 6 个令牌
  → 落库（含算法版本）
  → 下发前端与导出服务
```

### 5.1 校验规则

| 检查项 | 阈值 |
| --- | --- |
| 主按钮文字对品牌色 | ≥ 4.5:1 |
| 品牌链接文字对白底 | ≥ 4.5:1 |
| 焦点环对白底 | ≥ 3:1 |
| 选中行文字对浅底 | ≥ 4.5:1 |

### 5.2 派生规则（HSL）

| 令牌 | 规则 |
| --- | --- |
| hover | 明度 −8% |
| active | 明度 −14% |
| soft | 保留色相饱和度，明度 96% |
| line | 保留色相饱和度，明度 88% |
| link | seed 本身；若对白底 < 4.5:1 则逐档压暗直到达标 |
| on-brand | 白色与 `#1f2937` 取对比度高者 |

不达标时自动调整并记录 `adjusted=true` 与原始值，用户看到“已为可读性调整”。P0 只有预设，恒通过；
自定义色在 P1 开放，届时仍走同一校验。

### 5.3 为什么由服务端计算

PDF、收据、Excel 导出与邮件模板由后端渲染，必须和界面用同一组色值。若前端自行派生，
同一租户的单据和界面会出现两种蓝。算法变更时提升 `algo_version`，读取时重算。

### 5.4 反例

| 输入 | 对白底对比度 | 结果 |
| --- | --- | --- |
| `#c2410c` 深橙 | 5.18:1 | 通过，但与警告色同色相，不进预设 |
| `#ffd400` 亮黄 | 1.43:1 | 拒绝 |
| `#ffffff` 白 | 1.00:1 | 拒绝 |
| `#4338ca` 靛蓝 | 7.90:1 | 通过（预设候选） |

## 6. 预设色板

| 名称 | 色值 | 对白底 | 说明 |
| --- | --- | --- | --- |
| 深蓝 | `#254c78` | 8.81:1 | 现有主色，默认 |
| 靛蓝 | `#3b4e9b` | 7.64:1 | 与深蓝区分度足够 |
| 青 | `#0f6e6e` | 6.04:1 | 冷色中最亮的一档 |
| 墨绿 | `#1f5b4a` | 7.91:1 | 教育机构常用 |
| 石墨 | `#3d4453` | 9.77:1 | 中性，接近无彩色 |
| 暖棕 | `#6b4a2f` | 7.94:1 | 中性偏暖，与警告橙明度差大 |

排除项：橙（`#f79009`）、红（`#f04438`）、绿（`#12b76a`）三个状态色相及邻近色不进预设。
理由见验收时橙色租户的实测：品牌主按钮与“课时不足”标签在扫视时难以区分。

自定义色（P1）使用系统取色器或十六进制输入，实时展示按钮、链接、选中行三个预览，校验不通过时即时提示。

## 7. Logo 规格

| 资产 | 用途 | 规格 |
| --- | --- | --- |
| 横版 Logo | 侧栏头部、登录页 | 透明底，显示高度 24/28/40 三档，建议 SVG 或 2x PNG |
| 方形图标 | 折叠侧栏、favicon、消息通知 | 1:1，最小 32px |
| 单色版 | 打印、导出 PDF、收据、深色底 | 单色透明，由租户上传或系统按主色反白生成 |

约束：

- 单文件 ≤ 200KB，宽高比 1:1 至 4:1；服务端校验尺寸与格式，生成 64/128/256 三档。
- SVG 必须消毒：移除 `<script>`、`<foreignObject>`、`on*` 事件属性与外部引用；拒绝 GIF。
- 存储走受控对象存储，公开读加版本号防缓存；替换 Logo 时换 URL 而非覆盖同名文件。
- 打印与导出读取同一份记录，黑白单据使用单色版；无单色版时按主色反白生成。
- 侧栏仅显示横版 Logo；空间不足时退化为方形图标，不裁切。

2026-11-08 实现口径：先开放 PNG/JPEG 的横版与方形上传，服务端校验文件签名、大小、最小边与比例，
按租户/类型/版本写入私有对象存储；SVG 消毒、GIF、单色版和 64/128/256 多尺寸生成仍待后续，
当前由浏览器按显示高度缩放。对象存储未配置时上传返回 409，不落本地目录。

## 8. 数据与接口

### 8.1 表结构

```sql
identity.tenant_branding(
  tenant_id uuid primary key references identity.tenant(id),
  primary_seed char(7) not null,
  brand char(7) not null, brand_hover char(7) not null, brand_active char(7) not null,
  brand_soft char(7) not null, brand_line char(7) not null, brand_link char(7) not null,
  on_brand char(7) not null,
  logo_wide_url text, logo_mark_url text, logo_mono_url text,
  display_name varchar(60),
  adjusted boolean not null default false,
  algo_version smallint not null,
  version int not null,
  updated_by uuid not null, updated_at timestamptz not null
);

identity.tenant_branding_history(
  tenant_id uuid, version int, snapshot jsonb, changed_by uuid, changed_at timestamptz,
  primary key (tenant_id, version)
);
```

历史只保留最近 10 版，由写入事务裁剪。`version` 同时作为乐观锁与回滚依据。

### 8.2 接口

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/tenant/branding` | 登录态 | 租户端启动时读取，返回令牌、Logo、显示名、version |
| PUT | `/api/tenant/branding` | `TENANT_BRANDING_WRITE` | 需 `If-Match: version`，冲突返回 409 |
| GET | `/api/platform/tenants/{id}/branding` | 平台登录态 | 平台查看与代改 |
| PUT | `/api/platform/tenants/{id}/branding` | 平台登录态 | 写平台审计，标注 actor 为平台 |
| POST | `/api/platform/tenants/{id}/branding/rollback` | 平台登录态 | 指定 version 回滚，生成新版本而非删除历史 |
| GET | `/api/public/branding?host=` | 匿名（P1） | 子域名登录页使用，只返回显示名、Logo、色值，限流且不返回租户标识 |

匿名端点不得成为租户枚举入口：仅按 host 精确解析，未命中返回通用响应。

### 8.3 平台代改的边界

品牌属于开通与呈现信息，不属于业务数据。平台可读写品牌记录，仍不获得任何业务表权限
（DEC-024 的边界不变）。

## 9. 加载与防闪烁

| 场景 | 做法 |
| --- | --- |
| 平台端 | 使用构建期常量，永不请求租户品牌 |
| 租户端登录后 | 登录响应返回租户标识后拉取品牌；首屏先用本地缓存（按租户键）避免闪一下平台色 |
| 无域名环境的登录页 | 使用中性平台主题，登录后再应用品牌（明确接受这一次性切换） |
| 子域名到位后 | 登录页按 host 请求公开端点，首屏即品牌；必要时服务端注入初始样式 |
| 退出或切换身份 | 清除品牌缓存，避免上一个租户的颜色残留 |

本地缓存只存色值与 Logo 地址，不存权限或业务数据。

## 10. 平台端边界

- 同源 `/platform`，独立构建入口、独立会话（`/api/platform/*`）、独立菜单。
- 平台构建不引入租户主题模块；租户主题代码放在租户入口，靠构建入口隔离而非运行时判断。
- 将来平台端迁移独立子域名时，只改入口与 cookie 域，主题逻辑不变。

## 11. 生效、回滚与审计

- 保存即生效，无需发布流程；一次保存产生一个新 `version`。
- 回滚是把历史版本复制成新版本，不改写历史。
- 审计记录操作人、来源（租户/平台）、旧值、新值、是否自动调整；平台代改写平台审计。
- 品牌接口响应 `Cache-Control: private, no-store`，前端每次启动以版本号校验缓存。

## 12. 验收

1. 6 个预设逐一渲染关键组件（主按钮、链接、选中行、标签、进度条、焦点环），截图留档；
2. 极端输入被拒绝：纯白、纯黄、纯黑、低饱和灰；
3. 全仓扫描：主题模块之外不得出现十六进制颜色（提交前检查）；
4. 两个租户并排对比，确认骨架完全一致、只有点缀不同；
5. 导出 PDF/Excel 与界面同色同 Logo；
6. 键盘走查：焦点环在品牌色下可见，对比度达标；
7. 切换租户/退出后无颜色残留。
