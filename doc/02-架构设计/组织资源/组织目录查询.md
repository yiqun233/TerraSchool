## 1. 任务与验收

ORG-001 依赖 CORE-001/002、IDENTITY-001，落实 BASE-02/03 的学校、校区、部门查询，作为首片基础资料入口。一个学校下的校区与部门平行，部门不挂在校区下。ORG-001 原批只读，后续已有[校区与部门维护](校区与部门维护.md)、员工/教师/教室及局部财务能力；完整生命周期和验收缺口以 F 台账及细项追踪为准。

验收要求：有权限账号只能读取已授权学校；跨租户拒绝，学校范围先于计数和分页；同一学校的 SCHOOL/CAMPUS/DEPARTMENT 显示正确；停用/撤权后后续读取拒绝；HTTP 与第二服务入口执行相同授权。对应自动测试及结果见验证记录，人工验收未进行。

## 2. 数据、隔离与依赖

organization.unit 保存 id/tenant_id/school_id/kind/name/version；SCHOOL 自关联，CAMPUS/DEPARTMENT 关联同租户、类型为 SCHOOL 的上级。联合外键同时阻止跨租户引用和把部门挂在校区下；名称非空、类型稳定代码。业务新增 ID 由 PostgreSQL uuidv7() 默认生成；版本留给后续维护用例。ORG-001无写入HTTP；新增的明确业务动作见ORG-002。

租户表启用且强制 RLS，USING/WITH CHECK 均绑定事务局部 app.tenant_id；缺少上下文不可读。ts_app 非 owner、非超级用户、无 BYPASSRLS、无 TRUNCATE，初批仅获组织SELECT；V3对维护用例增加有限INSERT和name/version列UPDATE，不开放DDL或删除。TenantTransactions 在实际 Spring/jOOQ 事务连接上绑定，嵌套切租户拒绝；完成或回滚后不遗留当前租户。

OrganizationQueries 是公开入口，OrganizationService 只使用 identity.api.CurrentActor 和 platform.api.TenantTransactions；jOOQ 生成类型留 organization.internal.generated。跨模块不依赖内部实体，HTTP 装配不实现独立授权副本。组织来源是合成夹具，未导入旧学校数据。

## 3. HTTP 与页面

GET /api/organization/units?page=0&size=20 → `{items:[{id,schoolId,kind,name,version}],page,size,total}`。页码从0开始，size为1–100、page最多100000，按 UUID id 稳定排序；参数错误400/INVALID_INPUT，未认证401，当前权限拒绝403/ACCESS_DENIED，失败为 application/problem+json。空学校范围返回空列表/total0，不默认放开全机构。

分页和计数在同一个租户事务执行；当前 READ COMMITTED 下未来并发维护可能造成两条查询之间数目变化，不承诺财务对账快照。财务查询另按其一致性协议实现。

React 页面为 `/organization` 组织目录（`/` 现为登录与零学校引导入口），含登录、退出、分页、刷新、空态与错误。查询键区分当前账号/租户/页码，身份切换销毁旧 QueryClient 及组件观察者；请求可取消；查询错误隐藏旧列表及总数。敏感状态只留内存，不写 localStorage。

OpenAPI 由实际接口导出再生成 paths，前端不重复声明 DTO；Security 的登录/退出保持表单协议。ORG-002已补充校区/部门新增改名的同事务成功审计；当前组织修改的失败拒绝独立审计已由CORE-005A实现；浏览器E2E/人工视觉验收、组织树变更与完整字段策略仍未完成。

## CORE-003A授权与查看入口

组织读取和维护统一使用[角色/账号计算](../身份权限/角色与账号组织授权.md)，每次调用复核当前账号/机构/角色状态与ALLOW/DENY；功能允许不等于全校范围。组织页面增加“我的权限”，仅查看本人当前功能资格和可查看/可维护学校数量；重新打开重新读取，读取失败时隐藏旧结果。账号已登录但没有组织读取资格时，仍能通过错误区域的入口核对自身权限；真正业务查询/写入继续由后端独立拒绝。
