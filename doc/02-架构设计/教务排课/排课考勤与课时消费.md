## 范围与证据

报名到退款闭环的第四步：班级、报名入班、课次、发布、授课确认与考勤、关闭课次并固化课时消费，覆盖 SC01 的 S3–S4。旧结构 `H_Class*`、`H_CS_Item`、`H_KQ_Record_Student` 用多个布尔表达发布/授课/关闭/签到；本批不照搬布尔堆叠，改为单一状态机加正交事实（考勤与消费各自独立记录）。

## 数据归属与对象

| 对象 | 关键内容 | 权威边界 |
| --- | --- | --- |
| `teaching.class` | 班级名称、学校、校区、开班/结班日期、状态、版本 | 属于一个学校与一个校区；名称同校唯一；班容按班（不按课程）；首版单校区报名即在该校区上课 |
| `teaching.class_curriculum` | 班×课程、课时、价格 | 一个班可绑多门课程（暑期冲刺班=数学+英语+物理+化学；单课班=美术/书法/数学/英语），课程须同校启用；旧 `class.curriculum_id` 仅保留为主课程，迁移期双写 |
| `teaching.enrollment_class` | 报名×班级、入班日期、是否当前 | 已放宽为同一班级不重复加入，可承接多课程分别入班；转班历史仍需显式用例 |
| `teaching.lesson` | 日期、起止时间、课程、教师、教室、课题、授课课时、状态、版本 | 每课次挂一门班课程（多课程班交替排课时各扣各的课时）；草稿/发布/确认/关闭四态；关闭是唯一固化点 |
| `teaching.lesson_teacher` | 课次×教师、主/辅 | 主教师一名，辅教师可选；旧 `H_CS_Item_Teacher` 与 `Teacher_A/B_Code` 对应 |
| `teaching.attendance` | 课次×报名的出勤事实 | 每次确认覆盖全部在班报名 |
| `teaching.consumption` | 报名×课次的消费课时与金额、结算模式与快照 | 同一报名×课次只能一条；纠错留给后续批次 |
| `teaching.creation_request` | 班级/课次创建幂等身份 | 同主体同请求号只产生一次事实 |
| `teaching.school_minute_space` | 学校时段模板（起止分钟） | 学校级唯一，班级不单独持久化；对应旧 `H_School_Minute_Space` |
| `teaching.schedule_policy.minutes_per_hour` | 每课时折算分钟数（15–240，默认 60） | 课时数 = 课次时长 ÷ 该值；未显式填写课时的建课次按此换算，显式填写则保留原值（用于特殊课次）；只影响之后新建的课次 |
| `organization.teacher_curriculum` | 教师可授课程 | 排课、换课只列可授该课程的教师；对应旧 `H_Teacher_Curricula` |
| `audit.teaching_event` | 班级、成员、课次、考勤、关闭 | 同一课次可还原创建→发布→确认→关闭 |

授课课时（`hours`）与钟表分钟分开表达：SC01 的 60 分钟记 1.00 课时，不把「60 分钟」硬编码成所有班型的规则。折算参数放在学校级排课策略里（`minutesPerHour`），45 分钟/课时的学校把 90 分钟课次计为 2.00 课时。

## 状态机与消费规则

```
DRAFT --发布--> PUBLISHED --授课确认+考勤--> CONFIRMED --关闭--> CLOSED
```

- 草稿保存不占用资源、不产生消费；
- 发布要求课次仍为草稿，带读取版本；发布不产生消费；
- 已发布课次可直接修改时间/课程/教师/教室（按旧系统不设审批门禁），但不得改成无课程/无教师；修改前后值写操作日志，通知由操作人手动发；
- 授课确认必须覆盖**当前全部在班报名**，状态为出勤/缺勤/请假之一，重复报名或未知状态拒绝；
- 关闭课次只为**出勤（PRESENT）**的报名生成消费，缺勤与请假不消耗课时；
- 消费金额按报名**冻结快照**及已解析的结算模式计算；原首片总价÷总课时只是模式 1 主例。当前模式 1/4 扣优惠、2/3/5 不扣，服务费不摊课时单价，尾差及退后续算以结算模式专项设计为准；不读取后来发布的价格重算历史；
- 同一报名×课次的消费由唯一索引与「已关闭」状态双重阻止，重复关闭返回 `LESSON_NOT_CONFIRMED`；
- 对账等式已扩展为：购买课时 = 已消耗 + 已退 + 剩余；跨越剩余课时暂时拒绝，不能将剩余写为负值或静默截断整节。

## 权限与数据范围

| 动作 | 含义 |
| --- | --- |
| `TEACHING_READ` | 查看班级、课次、考勤与对账 |
| `TEACHING_MAINTAIN` | 新建班级/课次、加入报名、发布课次 |
| `ATTENDANCE_RECORD` | 授课确认与考勤登记 |
| `LESSON_CLOSE` | 关闭课次并固化消费 |

关闭课次决定财务事实，单独授权；发布与维护共用 `TEACHING_MAINTAIN`（发布确认凭证在后续批次补齐）。学校停用、授权撤销与教务写入共用机构锁。发布、考勤确认、关闭及期初消费均在锁内复检学校状态，停校拒绝写入、保留历史读取，恢复后按原状态与版本办理；组合及故障回滚结果见[REV-004 验证](../../99-归档/验证记录/20261103-REV-004异常与并发组合验证记录.md)。

## 事务、并发与审计

报名入班、课次创建、发布、确认与关闭都在应用服务内完成授权、校验与审计；课次行使用 `FOR UPDATE`，并发关闭只有一个成功（另一个按状态或版本冲突返回）。同一课次的审计记录可还原完整生命周期。

## 本批非目标

- 单班固定时段批量预览/确认、教师教室占用和部分不可用冲突已补；多班自动选资源、容量/距离/校历矩阵仍未完整；
- 补课、合班、锁定课次；手动排课工作台的课表网格、拖拽调课、链式换课已单列规格（[手动排课界面复刻规格](../../06-旧系统研究/手动排课界面复刻规格.md)），本批不实现；
- 消费纠错与冲销单据；
- 退课时、退到账户与现金退出已由退款专项实现；完整口径与人工验收仍待完成；
- 课表、听课证等打印与移动端。

## 已知边界

- 已支持多课程报名加入多个班级，同一班级不重复入班；完整转班、合班及历史费用课时转移仍需显式用例；
- 课次已引用同校教师与教室实体并校验占用，保留名称快照及历史文本兼容；多教师和完整占用类型未齐；
- 班级无业务编号；
- 「我的权限」页面未展示 `TEACHING_*`/`ATTENDANCE_RECORD`/`LESSON_CLOSE`；
- 发布与维护共用权限，发布确认凭证尚未实现。
