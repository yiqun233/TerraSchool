## 范围与证据

报名到退款闭环的第四步：班级、报名入班、课次、发布、授课确认与考勤、关闭课次并固化课时消费，覆盖 SC01 的 S3–S4。旧结构 `H_Class*`、`H_CS_Item`、`H_KQ_Record_Student` 用多个布尔表达发布/授课/关闭/签到；本批不照搬布尔堆叠，改为单一状态机加正交事实（考勤与消费各自独立记录）。

## 数据归属与对象

| 对象 | 关键内容 | 权威边界 |
| --- | --- | --- |
| `teaching.class` | 班级名称、课程、状态、版本 | 属于一个学校；名称同校唯一；课程须同校且启用 |
| `teaching.enrollment_class` | 报名×班级、入班日期、是否当前 | 同一报名只允许一个当前主班，历史保留 |
| `teaching.lesson` | 日期、起止时间、教师、教室、课题、授课课时、状态、版本 | 草稿/发布/确认/关闭四态；关闭是唯一固化点 |
| `teaching.attendance` | 课次×报名的出勤事实 | 每次确认覆盖全部在班报名 |
| `teaching.consumption` | 报名×课次的消费课时与金额、结算模式与快照 | 同一报名×课次只能一条；纠错留给后续批次 |
| `teaching.creation_request` | 班级/课次创建幂等身份 | 同主体同请求号只产生一次事实 |
| `audit.teaching_event` | 班级、成员、课次、考勤、关闭 | 同一课次可还原创建→发布→确认→关闭 |

授课课时（`hours`）与钟表分钟分开表达：SC01 的 60 分钟记 1.00 课时，不把「60 分钟」硬编码成所有班型的规则。

## 状态机与消费规则

```
DRAFT --发布--> PUBLISHED --授课确认+考勤--> CONFIRMED --关闭--> CLOSED
```

- 草稿保存不占用资源、不产生消费；
- 发布要求课次仍为草稿，带读取版本；发布不产生消费；
- 授课确认必须覆盖**当前全部在班报名**，状态为出勤/缺勤/请假之一，重复报名或未知状态拒绝；
- 关闭课次只为**出勤（PRESENT）**的报名生成消费，缺勤与请假不消耗课时；
- 消费金额按报名**冻结快照**计算：单价 = 报名价格 ÷ 购买课时（保留 6 位），本次金额 = 单价 × 本次授课课时（四舍五入 2 位）；不读取当前价格，也不因后续改价重算；
- 同一报名×课次的消费由唯一索引与「已关闭」状态双重阻止，重复关闭返回 `LESSON_NOT_CONFIRMED`；
- 对账等式：购买课时 = 已消耗 + 剩余（退款批次会加入「已退课时」，届时扩展为 购买 = 已消耗 + 已退 + 剩余）。

## 权限与数据范围

| 动作 | 含义 |
| --- | --- |
| `TEACHING_READ` | 查看班级、课次、考勤与对账 |
| `TEACHING_MAINTAIN` | 新建班级/课次、加入报名、发布课次 |
| `ATTENDANCE_RECORD` | 授课确认与考勤登记 |
| `LESSON_CLOSE` | 关闭课次并固化消费 |

关闭课次决定财务事实，单独授权；发布与维护共用 `TEACHING_MAINTAIN`（发布确认凭证在后续批次补齐）。学校停用、授权撤销与教务写入共用机构锁。

## 操作与契约

| 操作 | 契约 | 说明 |
| --- | --- | --- |
| 能力 | `GET /api/teaching/capabilities` | 可读学校与各动作能力 |
| 班级列表 | `GET /api/teaching/classes?schoolId` | 含在班人数 |
| 在班报名 | `GET /api/teaching/classes/{id}/members` | 考勤与对账入口 |
| 课次列表 | `GET /api/teaching/lessons?classId` | 含考勤条数 |
| 考勤记录 | `GET /api/teaching/lessons/{id}/attendance` | 已登记的出勤事实 |
| 课时对账 | `GET /api/teaching/enrollments/{id}/reconciliation` | 购买/已消耗/剩余与消费明细 |
| 新建班级 | `POST /api/teaching/classes` | 幂等 `requestId` |
| 加入班级 | `POST /api/teaching/classes/{id}/members` | 报名须已生效且同校 |
| 新建课次 | `POST /api/teaching/lessons` | 幂等 `requestId`；时间与课时校验 |
| 发布课次 | `POST /api/teaching/lessons/{id}/publish` | 带 `expectedVersion` |
| 授课确认 | `POST /api/teaching/lessons/{id}/attendance` | 覆盖全部在班报名 |
| 关闭课次 | `POST /api/teaching/lessons/{id}/close` | 需 `LESSON_CLOSE`，固化消费 |

错误码：`403 ACCESS_DENIED`、`409 VERSION_CONFLICT`、`409 IDEMPOTENCY_MISMATCH`、`409 DUPLICATE_CLASS_NAME`、`409 CURRICULUM_INACTIVE`、`409 CLASS_NOT_ACTIVE`、`409 CLASS_HAS_NO_MEMBER`、`409 ENROLLMENT_NOT_ACTIVE`、`409 ENROLLMENT_ALREADY_IN_CLASS`、`409 LESSON_NOT_DRAFT`、`409 LESSON_NOT_PUBLISHED`、`409 LESSON_NOT_CONFIRMED`、`409 ATTENDANCE_MUST_COVER_MEMBERS`、`400 INVALID_INPUT`。

## 事务、并发与审计

报名入班、课次创建、发布、确认与关闭都在应用服务内完成授权、校验与审计；课次行使用 `FOR UPDATE`，并发关闭只有一个成功（另一个按状态或版本冲突返回）。同一课次的审计记录可还原完整生命周期。

## 本批非目标

- 自动排课（单班/多班）、资源冲突与容量、教师/教室占用（后续批次）；
- 补课、换课、合班、停课、锁定课次；
- 消费纠错与冲销单据；
- 退课时与退款（最后一批）；
- 课表、听课证等打印与移动端。

## 已知边界

- 一个报名首片只允许一个当前主班，转班与历史关系需后续显式操作；
- 课次只有单一授课教师与教室文本，未接教师/教室资源占用；
- 班级无业务编号；
- 「我的权限」页面未展示 `TEACHING_*`/`ATTENDANCE_RECORD`/`LESSON_CLOSE`；
- 发布与维护共用权限，发布确认凭证尚未实现。
