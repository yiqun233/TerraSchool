## 范围与定位

报名到退款闭环上线前最关键的缺口：现在的退款**没有审批**。本批建立最小可用审批：按「学校 + 动作」的金额免批额度、审批单的申请/通过/驳回（禁止自批），并把退课时与现金退款接入审批闸门。

首批覆盖动作仅两个：`REFUND_HOURS`（退课时并退回账户）与 `CASH_REFUND`（现金退款准备）。转班、退班、延期、优惠、减款等其他固定审批类型留待后续批次，结构上已可扩展。

## 数据与规则

| 对象 | 含义 |
| --- | --- |
| `approval.policy` | 学校 + 动作的唯一策略行：`free_below` 为免批额度，0 表示全部需要审批；`active` 控制是否生效 |
| `approval.request` | 审批单：动作、报名、金额、原因、状态、申请人与审批人、是否已被消耗 |
| `audit.approval_event` | 策略变更、申请、通过/驳回、消耗 |

规则：

- **未配置策略视为免审批**（首版默认，便于既有闭环继续可用）。这是显式取舍：**生产环境必须为退费动作配置策略**，否则审批形同虚设，已写入设计、验证记录与 AGENT。
- 金额 `< free_below` 免审批；`>= free_below` 必须持有审批单。
- 审批单必须同时满足：状态 `APPROVED`、动作一致、报名一致、**金额完全相等**（避免"批大用小"或"批小用大"）、未被消耗、学校在操作范围内。
- 审批单被业务动作消耗时写入 `used_at`，同一单据不能复用；消耗与业务动作同事务，失败则一并回滚。
- 申请人不能审批自己的单据（数据库 `CHECK (decided_by <> requested_by)` + 服务层校验双保险）。
- 同一报名同一动作只允许一张 `PENDING` 单据（部分唯一索引），避免重复申请堆积。
- 策略是配置行：不传版本视为整条覆盖；传版本则要求匹配，防止覆盖他人修改。

## 权限

| 动作 | 含义 |
| --- | --- |
| `APPROVAL_READ` | 查看策略与审批单 |
| `APPROVAL_MANAGE` | 维护免批额度 |
| `APPROVAL_DECIDE` | 通过或驳回审批单 |

申请审批复用业务动作（退费需要 `REFUND_APPLY`），不额外新增"申请"权限，避免出现能申请却不能做业务动作的空转角色。

## 契约

| 操作 | 契约 |
| --- | --- |
| 能力 | `GET /api/approval/capabilities` |
| 策略列表 | `GET /api/approval/policies?schoolId` |
| 维护策略 | `POST /api/approval/policies`（`expectedVersion` 可选） |
| 审批单列表 | `GET /api/approval/requests?schoolId&status` |
| 申请审批 | `POST /api/approval/requests` |
| 审批决定 | `POST /api/approval/requests/{id}/decide` |
| 退费接入 | `POST /api/funds/enrollments/{id}/cancel-hours`、`POST /api/funds/refunds` 增加 `approvalId` |

新增错误码：`409 APPROVAL_REQUIRED`、`409 APPROVAL_NOT_APPROVED`、`409 APPROVAL_MISMATCH`、`409 APPROVAL_ALREADY_USED`、`409 APPROVAL_ALREADY_PENDING`、`409 APPROVAL_NOT_PENDING`、`409 APPROVAL_SELF_DECISION`、`409 VERSION_CONFLICT`。

## 语义顺序（退课时）

1. 校验可退课时（购买 − 已消耗 − 已退）；
2. 服务端按冻结单价计算本次费用减项；
3. 读取策略：金额低于免批额度直接通过；否则校验并消耗审批单；
4. 写退课时与应收减项、调整分配、留差额在账户。

审批不改变金额算法，只决定"这次退费是否被允许"。

## 本批非目标与已知边界

- 多级审批、按角色/岗位的审批人矩阵、审批时效与过期未处理：未实现；
- 转班/退班/延期/优惠/减款等动作的审批：未接入；
- 撤销已通过的审批单、审批意见富文本与附件：未实现；
- 审批通知（站内/邮件）：未实现；
- 「我的权限」页面未展示 `APPROVAL_*`；
- 策略只有"金额阈值"一个维度，未支持按岗位、渠道或客户等级的差异化规则。

## 兼容性说明

在既有退费调用方（本机演示与上一批测试）中，未传 `approvalId` 会在配置了策略且金额达到阈值时被拒绝，返回 `APPROVAL_REQUIRED`；未配置策略时行为不变。本机演示按学校预置了 200 元免批额度，因此 SC01 主例（退 2 课时 200 元）仍是单步完成。
