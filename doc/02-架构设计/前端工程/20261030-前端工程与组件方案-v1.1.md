## 1. 确认范围

DEC-012 确认前端方案 A：已选 React/TypeScript 上采用 Vite、React Router、TanStack Query、Ant Design 与 Ant Design Form；主题变量与 CSS Modules 管理样式；普通界面状态优先放组件内部，跨页面确需共享时再用 Zustand。React Router 优先 Data Mode，具体加载与缓存协作在集成时验证。

管理端采用单页应用、前端独立构建发布，生产交付静态资源；接口使用 DEC-011 的 OpenAPI 派生客户端与统一请求适配。当前不要求前端服务端渲染，不因选 Ant Design 自动选择 Next.js、Umi、Ant Design Pro、第二套主组件库或 AI 界面框架。

具体大版本/补丁、Node/pnpm 版本、生成工具、浏览器支持范围、精确小数/日期工具、排课与打印组件仍需验证。本次只维护文档，不建立工程、安装依赖或实现页面。

## 2. 组件库取舍

| 方向 | 价值 | 代价与本轮选择 |
| --- | --- | --- |
| Ant Design 主组件库 | 表格、表单、树、弹窗等能力集中，操作与主题较容易统一 | 已选；深度定制需遵循组件边界，控制包体与样式覆盖 |
| shadcn/ui 主组件体系 | 组件源代码可直接修改，便于较强的视觉与组合定制 | 备选；承担更多组件组合、演进及复杂业务交互维护 |

本项目优先将定制投入排课工作台和具体业务流程，而非重新维护全部基础控件。主组件库不等于最终视觉，主题、布局、密度与品牌风格仍需设计和用户验收。未来 AI 组件不是本轮主库选型的唯一条件，不因工具示例常用某库就同时引入两套全局样式体系。

官方依据：[Ant Design](https://ant.design/docs/react/introduce/)、[主题定制](https://ant.design/docs/react/customize-theme/)、[shadcn/ui 的代码分发定位](https://ui.shadcn.com/docs)。具体版本与依赖许可在工程引入时核验。

## 3. 工程职责与路由

遵循工程结构文档：app 负责启动、路由与全局装配，features 按业务聚合页面、组件和请求协调，shared 仅承载跨业务稳定能力。避免按所有页面/所有 hooks 大目录堆积，也不为每个简单按钮建立一层无价值包装。

Vite 承担开发构建与静态打包；React Router 组织导航、按路由加载与错误边界。生产入口、深层链接刷新、静态资源基础路径、版本缓存和更新失败应在部署验证中覆盖；不将开发服务器作为生产运行方式。

Data Mode 的路由加载可触发业务预加载，但数据进入统一 Query 缓存，不由 loader 和组件各自请求并维护同一数据。路由可用性/菜单显示改善体验，真实授权仍由服务端执行，不能因路由守卫通过就绕过接口权限。

官方依据：[Vite 构建](https://vite.dev/guide/)、[React Router 模式](https://reactrouter.com/start/modes)。不因引用当前官方页面自动锁定版本。

## 4. 状态所有权

| 状态 | 所有者 | 约束 |
| --- | --- | --- |
| 服务端业务数据 | TanStack Query | 查询、刷新与修改后同步；数据库和服务端规则仍是业务事实来源 |
| 尚未保存的编辑值 | Ant Design Form | 字段值、联动、校验与错误；不持续被后台刷新静默覆盖 |
| 局部交互 | React 组件本地状态 | 展开、弹窗等；可从已有数据推导的值尽量直接推导 |
| 必要跨页面共享交互 | Zustand 按需 | 不复制一套服务端业务缓存，不预先建立全局万能 store |

同一份报名、金额或课表不同时在多个 store 中维护权威副本。服务端刷新/未来 AI 修改与本地未保存编辑冲突时，按版本及明确交互处理，不能自动覆盖用户输入。避免用多组 Effect 相互同步副本。

查询键包含必要的身份/租户、对象、筛选和版本等上下文；退出、身份变化和撤权清理或失效敏感缓存，并处理旧身份请求晚返回的问题。缓存不能作为权限证明，不默认将敏感业务缓存持久化到浏览器本地存储；必要界面偏好与业务材料区分。

官方依据：[TanStack Query 服务端状态](https://tanstack.com/query/latest/docs/framework/react/overview)、[Zustand](https://github.com/pmndrs/zustand)。精确键结构、缓存期限和失效协议后续设计。

## 5. 表单与请求

普通业务表单优先使用 Ant Design Form 一套状态体系，不默认叠加另一套表单状态库；复杂字段封装围绕稳定职责，例如金额输入、资源选择。客户端校验用于及时反馈，不复制整套财务、授权和排课规则作为最终依据。

金额/课时输入保持 DEC-011 的十进制字符串。InputNumber 的 stringMode 可作为适配基础，仍须验证空值、格式化、精度与提交，不将输入组件当精确计算库。日期控件显式转换到契约语义，生日、教学当地时间和实际时刻不能统一转成同一种 JavaScript Date 后发送。

统一请求适配对接 OpenAPI 派生客户端，处理 Cookie/CSRF、业务错误、字段错误、取消和追踪；组件不各写一套响应解析。Query 管理查询，修改通过受控动作；不能把查询的自动重试策略套到收款、退款或发布。关键修改复用持久幂等键及版本条件，前端不能先显示权威入账成功再等待真实结果。

HTTP 请求中不自行授予租户、主体或确认权限。服务端错误映射到可见字段和明确下一步，不只弹一个通用“系统错误”。长任务用真实任务 ID 查询阶段与结果，停止轮询或关闭页面不代表取消服务器任务，取消经过业务契约。

官方依据：[Ant Design Form](https://ant.design/components/form/)、[InputNumber stringMode](https://ant.design/components/input-number/)。

## 6. 可读性、样式与性能

公开业务组件、hooks 和请求协调的中文注释说明业务用途、输入单位、交互前提、错误和副作用，不逐个翻译 JSX 标签。页面保持能读出业务流程；复用通过职责和组合实现，不建立大量布尔开关或任意 schema 配置的万能页面。

主题变量管理全局视觉，CSS Modules 管理局部业务样式；避免广泛覆盖库内部选择器。基础组件升级、主题切换、弹窗/浮层及不同密度下验证一致性。图标、字体和必要资源随交付提供，客户内网运行不依赖公网 CDN；前端构建配置不包含服务器秘密。

独立请求按需并行，按路由加载，重型排课/图表组件按需加载；避免数据加载串行瀑布和首屏加载所有模块。基于实际渲染与性能问题优化，不为每个表达式机械添加 memo，也不提前承诺虚拟表格解决所有复杂交互。

本轮讨论参考 React 性能与组件组合技能，采用数据所有权、请求协调和合理组件组合原则；具体版本相关 API 在版本锁定后核验，不将技能中的 Next.js 或特定 React 版本写法自动设为项目要求。

## 7. 排课、移动端与未来 AI

Ant Design 提供筛选、资源选择和辅助表单，教师/教室时间轴、多班网格、拖拽、批量及冲突反馈是专项工作台。具体日历/网格/拖拽库未随方案 A 批准，先以已有真实样本验证布局、资源视图、交互、并发错误与负载；遵循优先开源的偏好，逐功能核对许可。

例如 FullCalendar Standard 与 Premium 许可不同，不能将基础包许可扩大到全部资源排程功能。前端拖拽表达变更意图，不代表资源已占用或调课成功；保存/发布仍由后端确定性检查，失败与版本冲突在界面明确恢复或提示。

移动端按教师/家长/学员高频场景继续原有范围，不以桌面页面缩窄代替流程设计，也不在当前创建空移动应用。未来 AI 可评估 Ant Design X、其他组件或自建适配，但不在本次开发；任务、方案确认和业务结果组件先服务实际业务，再被助手复用。

官方依据：[FullCalendar 许可分层](https://fullcalendar.io/license)、[Ant Design X](https://x.ant.design/)。本轮不批准付费排程组件或 AI 界面库。

## 8. 验证与未决项
