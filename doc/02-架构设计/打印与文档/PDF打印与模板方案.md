## 1. 已确认方向与未决范围

用户确认统一 PDF 输出流程、HTML/CSS + Chromium 作为首选渲染方案，使用 Playwright Java 调用；模板编辑方式继续待定，打印设备保留适配扩展。该选择服务合同、收据、听课证、课表和报表 PDF，不取消既有套打能力，也不要求像素级复刻旧模板。

首选方向已确认，具体引擎/浏览器版本、字体、Linux/CPU 兼容、模板语法/工具、分页与套打效果在真实样例验证后锁定。网页可视化编辑、Word 模板上传、针式连打、自动选打印机和静默打印尚未确定首期需求或实现；不能因确认渲染方向就批准完整编辑器或设备插件。

可先使用标准受控模板与参数验证输出契约；用户怎样编辑模板仍待定，不把这项工作假设写成最终产品交互。输出流程保留替换渲染器的边界，初期只实现已确定的路径，不提前建设多引擎平台。

## 2. 统一输出契约

目标流程：已授权业务数据快照 + 模板/字体/资源版本 → 渲染任务 → 私有 PDF 原件 → 预览/下载/打印请求。

| 职责 | 内容与边界 |
| --- | --- |
| 业务数据 | 业务服务提供状态、金额/课时、编号、单位及必要字段；复用指标和数据权限，渲染器不再计算权威业务结果 |
| 模板与资源 | 模板身份/版本、适用范围、变量定义、纸张/布局、字体和受控图片；具体编辑器独立选择 |
| 渲染 | 消费明确的数据与资源，生成文件，控制浏览器/进程资源和失败；不直接运行任意业务 SQL 或脚本 |
| 文件与归档 | 文件 ID/版本、业务与模板关联、权限、校验与保留，复用既有文件模块 |
| 打印接入 | 浏览器标准路径及未来设备适配，对纸张/缩放/设备能力作受控处理，真实完成状态有回执边界 |

生成单据不创建收款、不重新分配业务编号，也不修改报名/财务状态。业务事实仍由原应用操作在其事务内确定；模板只表现已有结果。若业务要求先形成正式单据再输出，由对应业务服务处理，不把副作用藏在渲染器中。

数据快照按业务用途明确版本和固化范围，敏感字段在生成前授权。渲染无需重现用户当前管理页面或任意登录后台取数；页面、任务和未来 Agent 通过同一输出契约发起。

## 3. 首选 HTML/CSS 与 Chromium

模板使用受控 HTML/CSS 排版，Playwright Java 调用匹配版本 Chromium 的 PDF 能力。打印样式、纸张尺寸、边距、方向、背景与缩放按模板声明和实际样例验证，不假定屏幕布局直接适合分页输出。

验证中文换行/字体回退、长姓名与条款、表格跨页/重复表头、页码/页眉页脚、横向课表、图片清晰度、金额精度及套打。页眉页脚等模板有独立能力限制，不能把普通页面样式或脚本能力无条件套用。

最终预览优先显示实际生成 PDF，编辑预览与正式输出分别标明状态。模板工具换成网页编辑或 Word 时，仍复用业务快照、版本和归档契约，具体适配另验，不承诺任意 Word 转换完全保留版式。

已有 Playwright 端到端测试选型不代表生产渲染环境配置自动合格；生产浏览器、依赖、权限和资源单独验证。具体版本、模板语法、生成参数、内嵌字体与 PDF 格式要求在样例验证后确定。

## 4. 模板版本、原件与重印

模板身份、版本和适用机构/学校/业务范围明确；草稿、启用与历史版本可区分。模板变量通过受控定义提供，字段权限和业务含义可追溯，不将模板变成任意代码执行入口。

正式 PDF 关联业务对象/数据版本、模板和资源版本、生成任务与文件版本。归档原件保持稳定，重印优先使用原件，不能因为之后修改学员资料或模板，就静默重算和替换历史文件。

更正、作废或特殊重印按对应旧业务规则生成关联版本；保留原件和来源，必要水印或派生版明确身份，不在渲染时改变权威金额/编号。具体更正规则在业务切片中核验，不借技术选型新增财务状态。

生成、预览、下载和重印各自鉴权与审计，文件保持私有。授权变化、文件失效、引用和保留沿用既有文件/导出协议。PDF 输出不自动批准电子签章、税务开票、合同签署平台或 PDF/A 等专项要求。

## 5. 套打与设备适配

保留纸张宽高、方向、边距、字段位置/整体偏移及必要背景开关等配置能力，按实际需求采用物理尺寸表达。具体参数结构、校准和机构/学校/设备适用范围待验证；排版准确不等于所有驱动输出位置一致。

标准路径是实际 PDF 预览、下载和浏览器打印。首期设备需求未明确，先保留针式连续打印、自动选机、纸盒或静默打印的适配扩展，不默认引入插件或承诺跨全部客户终端控制设备。

打印事件区分已生成、已下载、已发起和有回执的完成。浏览器打印接口主要打开打印对话框，发起请求或关闭对话框不能证明纸张已输出；设备适配如有可信回执，再按协议记录完成/失败和重复处理。

实际套打验证打印机硬件、纸张、边距、驱动缩放和进纸偏差；客户提供的 Linux 服务器部署条件不自动决定其所有终端打印机能力。适配协议、设备型号、操作系统和首期实现范围保持待定。

## 6. 内网交付与渲染隔离

匹配的 Playwright/Chromium、运行依赖、允许分发的中文字体和图片资源纳入交付，断网运行不依赖公网下载、字体服务或 CDN。浏览器更新与模板回归共同验证，不能只更新库而继续使用不匹配浏览器。

模板、图片、字体和变量均按输入边界处理。仅允许受控资源引用，不让模板任意访问网络、宿主机文件或内部管理地址；脚本/表达式、资源路径和富文本策略在实际模板方案中明确。业务授权与数据获取留在应用层，浏览器不获取额外业务权限或持有任意生产访问凭据。

生产渲染按最小权限、浏览器隔离和资源限制配置；不直接复制关闭沙箱的测试环境参数。限制并发、进程/内存、执行时间、文件大小和临时空间，失败/取消清理，具体隔离与容器方式按环境验证。

长任务复用持久任务；数据准备、渲染和文件固化分阶段，外部进程/上传不占用业务数据库长事务。重复执行/重印有清楚身份和结果，生成失败不留下被误认正式原件的半文件。

## 7. 备选与验证条件

| 备选 | 适合条件 | 本轮结论 |
| --- | --- | --- |
| OpenHTMLtoPDF | 较简单固定版式，期望纯 Java | 保留备选；CSS 支持和浏览器预览差异需验证，不与首选同时铺开 |
| JasperReports Library | 复杂固定分页、分组汇总和长表报表 | 保留备选；专门模板/设计工具与数据接口需维护，不因库开源假定所有网页设计产品均已获准 |
| Word 模板与转换 | 明确要求业务人员用 Word 排版 | 维护方式待定；转换、中文字体和分页需样例验收，未批准转换服务或工具 |
| PDFBox 等文档处理 | 出现合并、背景/叠加等明确需求 | 可后续评估，不以底层绘制库默认承担全部复杂排版 |

从已有旧系统材料选取合同、收据、多页课表和套打样例，验证真实内容与纸面输出后再锁定版本/配置；不要求先建设编辑器或设备插件才能验证通用流程。

检查还包括源数据/模板变化后的原件重印、跨租户/字段与下载撤权、任务重试/取消、资源访问限制、字体/断网、失败清理和真实打印状态。没有实物回执时不宣称已验证设备完成，样例成功也不替代不同模板的分页测试。

REV-013 持久数据导出现已加入 CSV/XLSX/PDF 格式切片：将受限 CSV 快照构造成转义后的静态 HTML 表格，JavaScript 关闭，使用 Playwright Java 1.64.0 与 Chromium 输出 A4 PDF，任务继续复用现有持久队列和权限复核。此切片不是合同/收据/听课证/课表的模板归档或重印实现。部署必须安装与 Playwright 1.64.0 匹配的 Chromium 和系统依赖，并准备中文字体；容器/生产环境及中文分页效果尚未实测。

本机定向后端验证通过格式与 CSV→HTML 安全转义测试，但 Playwright Chromium 下载源连接被重置，未能运行真实浏览器 PDF 渲染。因此当前不可将 PDF 端到端渲染标记为已验证；生成任务在没有匹配浏览器的运行环境会失败并按现有任务策略重试。测试和部署镜像应固定 Playwright/Chromium 版本并在构建期安装浏览器，不能依赖运行时联网下载。
