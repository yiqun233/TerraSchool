## 1. 任务与范围

CORE-003A依赖IDENTITY-001、ORG-001/002及CORE-005A，落实DEC-008与权限规则基线的角色模板、账号单独增减、动作范围、默认拒绝和DENY优先。用统一计算替代此前读取布尔开关/学校表与维护直接权限的分散判断；HTTP与第二服务入口共用CurrentActor，不根据页面按钮或会话权限快照放行。

本批只覆盖ORGANIZATION_READ（组织查看）与ORGANIZATION_MAINTAIN（校区/部门新增改名）。没有授权管理写API/UI、授权委派、最后有效管理员与并发保护、字段策略、账号运营或其他业务动作。完整CORE-003保持未完成。角色模型可读取、可验证，不提供无保护的管理员入口，也不创建固定产品岗位模板。

## 2. 单一结构与信任边界

| 表 | 权威事实 | 约束 |
| --- | --- | --- |
| identity.permission_role | 租户角色模板，code/name/active/version | 租户内code唯一；模板停用后不参与计算，version预留给后续管理用例 |
| identity.role_action | 模板包含的动作与ALLOW/DENY | 只接受本批两个稳定动作；允许同时有ALLOW/DENY以明确执行拒绝优先 |
| identity.account_role | 将角色分配给同租户账号及某所学校 | 每条明确学校；角色动作仅作用于该学校，不能通过NULL代表全机构 |
| identity.account_permission | 账号独立动作增减 | school_id非空为该校规则；NULL为功能级调整，不代表所有学校 |

账号、角色、学校通过包含tenant_id的联合外键关联；学校联合kind=SCHOOL，不能分配外机构或校区/部门作为学校。NULL功能规则只跳过学校外键，账号归属仍受约束。

这些表属于认证/授权基础设施，与原identity.account一样由专用ts_identity只读跨租户查询。ts_app无identity权限；ts_identity不是owner/超级用户/BYPASSRLS，也没有INSERT/UPDATE/DELETE。结构/转换仅由迁移角色执行。身份基础设施表不伪装为普通RLS业务表，SQL必须以可信会话账号和一致tenant_id限定每项关联，业务数据继续受强制RLS与学校范围双重控制。

## 3. 计算规则

CurrentActor.permissions以一条SQL在同一读取快照内加载当前账号、租户可用状态、账号规则及可用角色的学校规则。账号/租户停用或身份无效时拒绝；不把不同读取时点的ALLOW/DENY拼接。没有权限缓存；角色停用、分配删除或账号拒绝在后续调用生效，与已经开始的调用不承诺瞬时同步回收。

每个动作分别计算：

1. 角色动作在其账号分配学校展开，再与账号直接规则合并。
2. 存在功能级DENY，该动作功能关闭且学校集合为空，任何角色/账号ALLOW都不能覆盖。
3. 否则，存在功能级ALLOW或至少一项学校ALLOW则功能允许；没有ALLOW则默认拒绝。
4. 有效学校集合为该动作全部学校ALLOW减去全部学校DENY。功能级ALLOW本身不增加任何学校；只有学校DENY而无ALLOW也不会产生权限。所有学校均被DENY时可保留功能资格，但范围为空。
5. 维护功能还要求组织查看功能允许；实际维护学校始终为维护有效学校与查看有效学校的交集。查看范围不自动授予维护。

| 输入示例 | 结果 |
| --- | --- |
| 角色允许查看/维护学校A；账号允许查看学校B | 查看A/B，维护A |
| 角色允许维护A；账号拒绝维护A | A不可维护 |
| 角色拒绝维护A；账号允许维护A | A不可维护，账号ALLOW不能越过角色DENY |
| 账号功能级拒绝查看；角色允许查看/维护A | 不能查看或维护A |
| 账号功能级允许查看，没有任何学校ALLOW | 可进入查询但得到空列表，不放开全部学校 |
| 账号拒绝查看A但允许维护A | A不能维护；维护必须与查看相交 |

requireOrganizationReader复用该结果检查查看功能并返回学校范围；requireOrganizationMaintainer返回交集后的维护范围。已有空维护能力查询保持空集合，真正修改任何学校时仍拒绝。组织命令、幂等重放、学校选项与列表没有独立的授权实现副本。

## 4. 本人只读契约与页面

GET /api/session/permissions返回CurrentPermissions：accountId、tenantId、canReadOrganizations、canMaintainOrganizations、readableSchoolIds、maintainableSchoolIds。UUID为字符串，学校数组无顺序承诺；布尔是功能资格，数组是最终数据范围，两者都需判断。接口不接受目标账号/租户，以可信会话确定本人，不返回密码、角色详情或其他账号信息。

未登录401；账号/租户不可用403。账号可用但没有组织查看权限时可200查看自身拒绝/空范围；原/api/session/me及组织查询仍按查看资格返回403。本接口不授予查看组织数据或修改权限的能力。

页面新增“我的权限”，显示本人的功能资格和可查看/维护学校数量；已登录但无查看资格时错误区仍有入口。只在打开窗口时请求，重新打开再次取得当前结果；刷新中隐藏旧值，请求失败显示错误并隐藏旧值。查询带取消信号，退出/身份变化沿用销毁QueryClient的隔离规则。缓存只为显示，后端调用仍复检，不把学校ID列表作为可编辑授权表单。

OpenAPI从运行接口导出并生成前端类型，生成文件不手改、不提交；没有新增客户端重复DTO。

## 5. V5转换与本地升级

新迁移V5不修改已执行V1–V4：旧organization_read=true转为账号功能级READ ALLOW，false转为功能级READ DENY；全部旧school_scope原样转为学校READ ALLOW，包括当前关闭功能账号的潜在分配，由全局DENY继续压住；旧维护ALLOW/DENY全部转为对应动作规则。开启但空学校仍为空，关闭账号不会因角色ALLOW意外启用，也不丢失原有分配。账号ID、密码散列及业务资料不改动。

转换完成后移除旧organization_read列、school_scope与organization_maintenance_permission表，只有一份授权事实。此变化与旧应用不兼容，本批采用既定维护窗口：停本项目服务、备份、执行事务迁移、部署本批版本、核对原账号与有效范围后开放。迁移失败由事务回滚；禁止新旧应用并行或简单回滚旧JAR。应用运行时明确关闭自动Flyway，不为启动而授予DDL。

本机WSL升级前保存项目库自定义格式备份和有效权限快照，升级后逐账号比较查看功能、查看学校和可维护学校；不会停止共享PostgreSQL。备份含敏感数据，留受限.local/dev/backups，不入Git。回退需在隔离库恢复升级前备份并核对，再受控切换，不能直接覆盖共享环境。没有在本批声称生产恢复演练或无停机迁移已完成。

本地种子改为直接写新账号规则；已有seed_history不重复装载或重置账号。角色规则只在合成测试中配置，现有演示账号保持迁移后的直接权限。未来正式授权管理必须先落实委派、最终有效权限/范围、最后管理员保护和并发协议，不能通过给ts_identity写权限临时绕开。

## 6. 验收与剩余项

以真实PG验证无授权拒绝、角色/账号合并、双向DENY优先、功能与学校范围分离、维护与查看交集、跨租户/非学校关联拒绝、角色停用/分配删除生效、普通身份连接不可授权。真实HTTP验证未认证拒绝、本人结果、同一会话撤权后组织访问403。独立旧V4库执行V5核对保留功能开关、潜在分配、空范围、维护ALLOW/DENY与密码散列；组件验证按需读取及重新打开更新。实际结果与失败记录见关联验证文档。

原批次之后已有账号授权管理、角色模板、账号生命周期与会话撤销、学员五字段授权及多域业务动作；不能继续将这些全部记为未实现。更多数据维度、全业务字段矩阵、浏览器 E2E、人工验收、登录失败审计/限流及完整审计仍未收口，当前状态见 F02/03/11/33/37。不将局部授权计算器表述为完整权限产品。
