## 1. 范围与操作

IDENTITY-001 依赖 CORE-001/002，为首片提供数据库账号登录、JDBC Cookie 会话、退出与组织查询所需当前主体复核。依据 DEC-007/008，不引入 JWT 或前端自造租户。该句范围仅为 IDENTITY-001 原切片；后续已提供账号/角色维护、局部审批与授权管理，完整范围与剩余项见 F02/03/27。

| 操作 | 契约/结果 | 权限与边界 |
| --- | --- | --- |
| 获取 CSRF | GET /api/session/csrf → token/headerName/parameterName | 允许未登录，令牌由框架绑定会话；内部 CsrfToken 不作为公开输入 |
| 登录 | POST /api/session/login，表单 username/password 与真实 CSRF | 成功204，凭据错误401，无CSRF403；成功后更新会话身份 |
| 当前主体 | GET /api/session/me → accountId/tenantId/schools | 当前组织查询资格；未登录401，停用/撤权403；不返回密码散列 |
| 本人权限 | GET /api/session/permissions → CurrentPermissions | 已认证且账号/机构可用；无组织READ也可查看自身拒绝或空范围，不能指定他人账号 |
| 退出 | POST /api/session/logout + CSRF → 204 | 使当前会话失效，前端取消旧请求、清空并重建身份缓存 |

登录名暂为部署内全局唯一标识，账号 UUID 与租户分别独立；同一自然人在多租户使用独立账号。按机构重名登录、账号管理及迁移映射需在相关功能落实，不用客户端 tenantId 选择授权身份。

## 2. 数据和信任边界

identity.tenant 管理可用状态；identity.account 保存 tenant_id、登录名、带算法前缀的密码散列和可用状态。CORE-003A已用V5将原organization_read/school_scope及维护直接权限转换为统一角色模板、学校角色分配和账号ALLOW/DENY规则；当前结构和计算以[统一组织授权](角色与账号组织授权.md)为准。普通身份连接仍只有读取权限，没有开放授权写入口。

身份数据跨租户读取是仅限认证的基础设施能力。独立 ts_identity 只读 identity schema；ts_app 无权读取账号表；ts_session 只能访问 infra 会话表。认证 UserDetails 的 principal 使用账号 UUID。请求体/URL 中没有可指定 tenantId、学校权限或管理员身份的入口。

CurrentActor 在每次组织用例调用时重新读取账号、租户可用状态、能力与学校范围，不相信会话中的权限快照。撤权对后续调用生效；与已开始请求并发时不承诺瞬时回收已返回内容。前端查询错误时隐藏旧表格，不能替代后端授权。

默认 Cookie HttpOnly、SameSite=Lax、Secure=true，CSRF 始终启用；本地 HTTP 用独立示例配置显式关闭 Secure。会话30分钟无活动过期，由独立受限数据源存储，Flyway 管表，运行时不自动建表。

## 3. 验证与后续

真实 HTTP 验证未登录/缺CSRF、有效登录、会话持久使用、账号停用后访问拒绝、退出失效；第二入口直接调用同一 OrganizationQueries 仍需当前身份。密码散列由 Spring DelegatingPasswordEncoder 生成，测试账号随机口令只在合成夹具中存在。

组织READ/MAINTAIN的角色合并与账号增减已由CORE-003A实现；尚需授权管理写操作、委派/最后管理员保护、字段策略、账号/租户运营、认证审计与失败记录、限流/锁定策略、密码重置、撤销所有会话和运维初始化。数据库普通连接无权限写账号；不提供默认管理员或文档内置口令。


## ORG-002维护动作授权补充

CurrentActor.requireOrganizationMaintainer已改为复用CORE-003A统一计算：角色与账号规则合并、DENY优先、维护学校与读取学校相交；每次调用用一条SQL快照重新读取。该最小动作策略及限制见[维护设计](../组织资源/校区与部门维护.md)，不是完整角色/字段授权实现。没有新增授权管理API，也未赋予普通身份连接写账号或权限表的能力。


## CORE-005A审计主体补充

CurrentActor.auditSubject仅根据已认证账号UUID查询持久tenant/account归属，允许为停用/撤权后的尝试归属审计；未知或无法核实时不采用请求tenantId补全。此接口不提供业务授权，组织命令仍完整复检。组织失败与拒绝独立追加路径见[失败审计设计](../可观测与审计/组织失败拒绝审计.md)，登录失败审计仍未实现。

## CORE-003B管理入口与身份保护

本人权限响应新增管理功能及可管理学校集合；独立AUTHORIZATION_MANAGE可让没有组织查看资格的有效账号进入管理入口。当前已开放账号授权集合读取/替换，授权管理不再属于全部未实现，详见[设计](账号授权管理与委派保护.md)。身份连接仍只读；业务连接仅新增受强制租户RLS保护的必要账号列读取、authorization_version更新及授权集合写入，不能读取密码散列或停用账号。关闭管理窗口重读本人会话和业务缓存，覆盖自授权、自撤权和保存结果不确定；不重置登录身份或凭据。
