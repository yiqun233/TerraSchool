## 1. 已确认范围

DEC-007 确认首版使用系统账号登录、预留统一登录扩展；客户已有企业微信、钉钉或内网身份系统不作为首版必须接入项。DEC-008 进一步确认 Spring Security + 服务端会话 + Spring Session JDBC/PostgreSQL，权限保留角色、账号增减、按操作的数据范围和字段控制。具体版本与配置后续确定，本次仍只维护文档，不创建代码、数据库或独立身份服务。

继续遵守既有业务基线：租户内独立账号；同一人在不同租户身份独立；平台运营身份独立；员工档案与账号分离；角色功能权限、账号单独增减、数据范围与敏感字段权限；默认拒绝、deny 优先；管理权限不能突破委派边界。

## 2. 已选技术与备选取舍

采用 Spring Security 负责认证与安全集成，浏览器使用服务端会话；初期采用 Spring Session JDBC/PostgreSQL 存储会话，多实例共享存储。技术组合已确认，具体版本、配置和依赖兼容性仍需验证。JDBC 会话存储属于基础设施，不改变业务主数据访问采用 jOOQ 的决定；会话结构纳入 Flyway 迁移，不默认依赖应用启动自动建表。

| 备选 | 价值 | 代价与当前建议 |
| --- | --- | --- |
| 服务端会话 + PostgreSQL | 复用既有数据库，集中管理会话，多实例共享 | 已选；增加数据库会话读写，需要验证清理、并发和负载 |
| 服务端会话 + Redis | 会话存储可单独扩展 | 实际负载证明有价值时再引入，增加运维依赖 |
| 浏览器 JWT 登录 | 支持令牌式认证，某些跨服务场景有价值 | 网页默认不优先；撤销、续期和权限变化仍需设计，并非天然无状态即更简单 |
| 独立身份服务 | 有利于复杂统一登录与身份联邦 | 尚未选择，增加部署与升级成本；系统账号登录并不强制选择或禁止它 |

前后端可分别构建发布，访问入口优先评估同源反向代理。会话 Cookie 配置 Secure、HttpOnly 和适当 SameSite；写请求、登录与退出具备 CSRF 防护。不能因接口返回 JSON 就关闭防护。具体域名、Cookie、超时和并发登录规则待设计。

官方依据：[Spring Session JDBC 与 PostgreSQL](https://docs.spring.io/spring-session/reference/configuration/jdbc.html)、[Spring Security CSRF](https://docs.spring.io/spring-security/reference/servlet/exploits/csrf.html)。这些文档证明框架能力，不代表本项目集成、性能或安全验证已经完成。

## 3. 身份与租户绑定

账号通过稳定 ID 关联租户、认证资料及业务人员，登录名、手机号与显示名不是身份主键。账号改名保留 ID，停用或删除账号不删除业务历史。

机构入口或机构标识只能定位待验证租户，不能直接成为访问授权。验证账号归属与租户可用状态后建立可信上下文，再进入 DEC-006 的业务连接与事务隔离路径。

认证查询和会话读取发生在业务租户上下文建立之前，因此需要受限身份基础设施访问路径，只允许必要的认证、会话及租户状态访问。不得通过普通业务账号持有超级用户/BYPASSRLS 权限解决初始化问题。具体角色、数据源或受控数据库入口尚待设计，身份表和会话表也需明确分类、隔离及访问测试，不机械套用业务表策略。

统一登录扩展将来验证外部身份后映射明确的租户内账号；外部身份提供方和主体标识不能直接充当业务授权。如何首次绑定、解绑与处理冲突在实际接入时设计，不默认按手机号或邮箱跨租户合并账号。

## 4. 已确认权限模型与实现边界

功能、资源范围和字段权限为必须保留的业务约束；DEC-008 已确认角色功能权限、账号增减、按操作的数据范围和字段控制。授权在应用服务执行。具体策略类、查询过滤表达和方法级安全配置随设计细化；不因模型确认自动选择通用权限平台或脚本引擎。

| 层次 | 职责 |
| --- | --- |
| 功能权限 | 操作是否被允许，例如查看报名、排课发布、退款、导出 |
| 数据范围 | 对当前动作可访问哪些学校、校区、部门、本人/团队对象；其他旧维度按已有证据核验 |
| 字段权限 | 对当前对象可查看或修改哪些敏感字段 |
| 业务状态与风险 | 锁月、审批、确认、版本与其他确定性前置条件 |

角色提供功能权限模板，账号增减继续有效，显式 deny 优先。数据范围按操作绑定，不能把不同动作的范围并集后复用。例如“查看所有校区报表”不产生“修改所有校区课表”的权限。

列表、详情、关联选项、聚合、导出、附件和写入统一受控，先权限过滤再分页/统计。页面按钮只提供交互，应用服务执行完整授权；方法级安全只是实现工具，须验证实际代理、调用和任务路径，不能只给 Controller 加注解或只靠查询后过滤。

授权管理检查修改前后最终有效权限及范围，保护最后有效管理员，并发替换有一致协议。这些既有不变量不依赖框架自动实现，须进入业务验证。预置岗位矩阵与渠道/项目等细节随功能对照核验，不重新启动全量访谈。

官方依据：[Spring Security 服务方法授权](https://docs.spring.io/spring-security/reference/servlet/authorization/method-security.html)。项目仍需定义业务策略，框架不会自动生成正确的数据权限。

## 5. 会话与撤销规则

会话只保存必要的稳定身份与认证状态，不把长期权限快照视为权威。后续请求检查账号、租户状态与当前有效权限；初期优先按请求加载或验证，缓存优化必须具有一致失效协议，不允许撤权后继续依赖旧值。

按动作制定撤销协议：退出使相应会话失效；管理员停用、密码重置与安全处置使受影响会话失效；权限变化按新规则执行。撤销状态与请求并发的边界需明确，高风险提交前复检，不能仅删除一条会话记录就宣称所有并发请求立即终止。

任务执行重新验证租户、主体和授权；不把网页登录凭据长期存入任务续命。已经完成的业务通过冲销等对应流程处理，不能通过退出登录自动回滚。具体会话时长、设备数量、密码恢复和 MFA 范围仍待设计，不擅自新增首版产品承诺。

## 6. 未来 Agent 与接入边界

内置助手代表当前员工调用同一应用服务；外部 Agent 将来使用员工委托、管理员客户端限制和当前权限的交集。凭据可到期、撤销与收窄，不复制员工密码或网页登录 Cookie。

远程 MCP 授权可以按届时兼容的 OAuth 体系接入，授权服务器、令牌形式、发现机制及产品交互在实际接入时选择。现在保留调用主体、租户、来源及未来客户端/委托扩展位置，不创建 OAuth 平台、MCP 服务或 AI 功能。模型输出不能成为审批证明、租户身份或任意数据源选择。

官方依据：[MCP 远程授权规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/authorization)。协议会演进，正式接入时重新核验，不在本次锁定全部实现。

## 7. 后续验证与未决项

R3-CORE-001 已验证测试账号的 JDBC 会话、CSRF、基础读写角色、双租户与第二入口，普通业务/会话账号分离，见[验证记录](../../03-研发规范/工程质量/验证记录/20261031-核心技术组合验证记录-v1.0.md)。固定测试身份不是正式账号与授权模型，下面的完整多实例、撤权及管理场景仍须实现时逐项验证，不将局部通过扩大为全部通过。

- 登录前受限认证路径、错误租户/账号组合及统一错误反馈，不能泄露其他客户信息。
- 跨实例读取会话、退出、账号/租户停用、重置密码、权限变化及并发请求，范围和生效边界明确。
- Cookie/CSRF、登录后会话更新、过期与续期、多端登录策略及失败限制。
- 普通入口、任务和模拟第二入口调用同一应用服务，拒绝与状态校验一致。
- 角色、账号增减、操作范围、敏感字段、委派管理和最后管理员并发保护。
- 会话表及索引、属性序列化、结构迁移、清理与升级兼容性，不依赖启动时自动建表获得额外权限。

组合与权限模型已在 DEC-008 确认，不重复选型。未决：具体版本与依赖兼容、会话期限/并发/撤销配置、会话属性序列化及清理、身份基础设施访问路径和数据库角色、部署入口、权限策略与查询过滤的实现细节，以及恢复/MFA 等产品规则的适用范围。统一登录和未来 Agent 接入仍按已确认阶段边界推进。
