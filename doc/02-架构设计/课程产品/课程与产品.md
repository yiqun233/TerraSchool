## 范围与旧系统证据

报名到退款闭环的第二步：提供可售的课程、产品与价格版本，让报名能引用到稳定的商品与规则快照。用户已确认按业务依赖推进的顺序，本批承接学员档案之后。

旧结构 `H_Curricula` 保存课程名称、课程类型、审核与有效标记；`H_Product` 保存产品名称、班型、产品组、购买课时、学习期限、价格、服务费、版本号、有效期与目标；`H_Curricula_Price*` / `H_Product_Version` 保存价格与版本。旧表把价格直接放在产品行上并用布尔字段表达审核与临时状态，本批不继承该做法：价格与课时进入独立版本，发布后不可改写，改价必须新增版本。

## 数据归属与对象

| 对象 | 关键内容 | 权威边界 |
| --- | --- | --- |
| `product.curriculum` | 课程名称、课程类型、科目、启用状态、版本 | 课程名称在同一学校内唯一 |
| `product.product` | 归属课程、产品名称、默认结算模式、启用状态、版本 | 产品属于一个课程，课程必须属于同一学校 |
| `product.price_version` | 版本号、价格、购买课时、服务费、结算模式、学习期限、生效/失效日期、状态、版本 | 同一产品最多一个已发布版本；发布后不可改写 |
| `product.creation_request` | 请求身份、操作者、类型、资源与参数摘要 | 同主体同请求号只产生一次创建事实 |
| `audit.product_event` | 课程/产品/价格的创建、修改、发布、停用 | 记录动作与变化字段名称，不记录金额明细以外的敏感信息 |

金额使用 `numeric(14,2)`、课时使用 `numeric(10,2)`，接口一律使用十进制字符串（`"1000.00"`），服务端按 BigDecimal 校验两位小数与范围，禁止二进制浮点作为权威值。

## 价格版本规则

- 草稿（`DRAFT`）只能修改，不能直接对外报价；
- 发布（`PUBLISHED`）需要独立权限 `PRICE_PUBLISH`，同一产品只允许一个已发布版本，发布新版本时旧版本自动转为 `RETIRED` 并保留为历史；
- 已发布与已停用版本都不能修改金额、课时与有效期，改价必须起草新版本；
- 可售查询（`GET /api/product/sellable`）只返回「产品启用 + 课程启用 + 已发布 + 业务日期落在有效期」的快照，报名据此冻结商品与规则；
- 生效/失效日期是业务日期（`YYYY-MM-DD`），由调用方显式传入，不依赖机器本地时区推断。

本批只把结算模式（0–5）作为受控取值随版本快照，不实现任何结算公式；模式 0–5 的公式与金标准仍属后续批次。

## 权限与数据范围

动作进入统一权限目录，与其他模块共用 ALLOW/DENY 与学校范围计算（DENY 优先，维护范围与查看范围相交）：

| 动作 | 含义 |
| --- | --- |
| `PRODUCT_READ` | 查看课程、产品与价格版本 |
| `PRODUCT_MAINTAIN` | 新建/修改课程与产品、起草与修改价格草稿 |
| `PRICE_PUBLISH` | 发布与停用价格版本，与维护权限分开 |

发布与停用使用单独的动作检查（`requireAction`），不复用维护范围：只有定价发布权的账号不能维护课程产品，只有维护权的账号不能发布价格。学校停用、授权撤销与课程产品写入共用机构锁。

## 操作与契约

| 操作 | 契约 | 说明 |
| --- | --- | --- |
| 能力查询 | `GET /api/product/capabilities` | 可读学校列表、是否可维护、是否可发布 |
| 目录 | `GET /api/product/catalog?schoolId` | 课程与产品，产品带当前已发布价格 |
| 价格历史 | `GET /api/product/price-versions?productId` | 按版本号倒序，含状态 |
| 可售快照 | `GET /api/product/sellable?schoolId&on=YYYY-MM-DD` | 报名使用的商品与规则快照 |
| 新建课程 | `POST /api/product/curricula` | 幂等身份 `requestId` |
| 修改课程 | `POST /api/product/curricula/{id}/update` | 整套提交带 `expectedVersion` |
| 新建产品 | `POST /api/product/products` | 课程须同校；幂等身份 `requestId` |
| 修改产品 | `POST /api/product/products/{id}/update` | 名称、结算模式、启用状态 |
| 起草价格 | `POST /api/product/price-versions` | 幂等身份；金额/课时为字符串 |
| 修改价格 | `POST /api/product/price-versions/{id}/update` | 仅草稿可改 |
| 发布价格 | `POST /api/product/price-versions/{id}/publish` | 需 `PRICE_PUBLISH`，自动作废旧发布版本 |
| 停用价格 | `POST /api/product/price-versions/{id}/retire` | 需 `PRICE_PUBLISH` |

错误使用真实 HTTP 状态与 RFC 9457 问题详情：`403 ACCESS_DENIED`、`409 VERSION_CONFLICT`、`409 IDEMPOTENCY_MISMATCH`、`409 DUPLICATE_CURRICULUM_NAME`、`409 DUPLICATE_PRODUCT_NAME`、`409 PRICE_VERSION_IMMUTABLE`、`409 PRICE_VERSION_NOT_DRAFT`、`409 PRICE_VERSION_NOT_PUBLISHED`、`400 INVALID_INPUT`。

## 事务、并发与审计

1. 事务外先按当前快照取得查看/维护范围，发布动作单独取 `PRICE_PUBLISH` 范围；
2. 事务内取机构锁后复核，防止锁前撤权；
3. 锁内校验学校启用、课程归属与产品可见性；
4. 创建使用「租户 + 操作者 + 请求号」事务级咨询锁与 `creation_request` 双保险；
5. 修改与状态变化使用版本条件更新并检查影响行数；
6. 发布在同一事务内先作废旧发布版本、再发布新版本，避免出现两个可售价格；
7. 成功审计与业务同事务，失败/拒绝进入独立失败审计（动作名见验证记录）。

## 本批非目标

- 结算模式 0–5 的公式、优惠/折扣/券、服务费类型与商品；
- 产品与校区/学校可售范围矩阵（功能清单列为 P1，P0 默认全部可售）；
- 班型、课程阶段/科目树、课程版本与审核流；
- 价格审批流、改价凭证与历史对账报表；
- 课程产品与报名、资金的联动（下一批）。

## 已知边界

- 目录查询单校最多返回 500 条，超出需要后续分页；
- 课程与产品没有业务编号，仅有稳定 UUID，编号规则随合同/收据编号一并确认；
- 「我的权限」页面仍未展示 `PRODUCT_*`/`PRICE_PUBLISH`；
- 价格版本只允许一个已发布版本是当前约定，若业务需要并行多版本报价，需要显式调整约束与选择规则。
