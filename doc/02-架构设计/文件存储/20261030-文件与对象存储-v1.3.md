## 1. 已确认方向

DEC-010：SaaS 必须支持在产品方自己的 Linux 服务器上部署开源对象存储，不限于云厂商托管服务。SeaweedFS 为自建首选，SaaS 与客户版优先复用 S3 兼容接口；云厂商托管存储为可选实现。

首批客户内网环境主要是单台 Linux 服务器，硬盘和备份规格未确定。客户版也可部署 SeaweedFS；受控磁盘目录保留为轻量备选，是否首版实现尚未决定，不能继续将其写成已确认默认方案。

统一文件业务模块以文件 ID、版本和业务关联提供能力，PostgreSQL 保存元数据及关系，附件内容存入独立存储。S3 是接口方向，不要求 AWS，也不保证所有兼容实现功能完全一致。当前只维护设计文档，不创建服务、安装依赖或部署存储。

## 2. 部署边界与取舍

| 形态 | 本轮决定 | 待验证内容 |
| --- | --- | --- |
| SaaS 自建 | SeaweedFS 首选，允许与业务服务位于同一台 Linux 服务器，存储独立进程或容器及数据目录管理 | 资源竞争、持久化、私有访问、恢复和扩容；不自动锁定容器工具或集群 |
| SaaS 托管 | 云对象存储可选，封装在存储适配器内部 | 供应商、API 差异、成本与恢复能力；必要时用供应商适配实现，不强求只改 endpoint |
| 客户内网 | 优先复用同一 S3 访问方式及 SeaweedFS，自包含于内网运行 | 离线交付、配置/凭据、磁盘及备份，不能依赖公网端点 |
| 轻量文件系统 | 保留备选，不是必须同时开发的第二套实现 | 持久目录、路径约束、原子写入、备份和多实例可达性 |

统一访问方式减少不同部署的业务分支，代价是自建对象存储需要维护进程、数据与元数据、监控、升级及恢复。单机支持不等于主机故障高可用，同机多个进程或副本不能算独立故障域；具体多节点拓扑和 SLA 后续设计。

官方依据：[SeaweedFS 单节点、S3 与扩展说明及许可证](https://github.com/seaweedfs/seaweedfs)。按选定开源版本验证所需能力，不把商业版功能或开发分支说明自动当成已具备能力。

## 3. 文件身份与业务所有权

业务模块引用稳定文件 ID 与所需版本，不保存部署机器绝对路径或临时下载 URL 为业务主键。文件模块内部记录存储实例/位置、对象键及必要版本引用，使后续迁移保持业务关联稳定；切换后端仍须搬迁、校验和受控切换，不能仅改配置就声称存量迁移完成。

元数据明确租户、上传/生成主体、原始名称、实际类型/大小、完整性信息、用途、状态、版本及来源；精确字段与类型在实现设计中确定。业务归属通过明确关联表达，不能只凭“知道文件 ID”访问文件。

正式附件、待处理上传和生成结果分别管理。合同/收据等归档件关联业务快照与必要模板版本，避免当前业务变化后重打覆盖原归档事实；导出文件、缩略图和未来解析结果按是否可重建制定策略。多处引用同一文件时，单处解绑不能直接删除其他业务仍引用的内容。

原始材料、提取草稿、人工核实结果与正式档案分开。未来 AI 任务引用固定材料版本，保留来源关系与处理版本，不以当前 URL 或聊天文本作为唯一证据。

## 4. 上传、固化与一致性

数据库与对象存储不视为一个本地原子事务。采用明确上传意图/临时状态，完成实际上传及校验后固化内容版本，再在业务事务中关联并标记可用；输入合法、归属和对象实际存在都需验证，不能只相信客户端的成功标志。

对象键由服务端分配，限制上传用途、大小与类型。临时上传凭据不允许覆盖正式对象或访问任意租户路径。对可重复使用的上传签名，在完成后采用受控最终对象或绑定明确对象版本等协议，防止校验后内容被再次覆盖；精确实现按实际存储能力验证。

同一业务操作重复完成上传或挂接时结果可识别；上传成功而数据库失败、任务重试、多次回调和删除失败都有补偿状态。未完成上传、孤立对象与待删除内容经可靠任务清理，核对关联与保留规则，不能靠不受控目录扫描直接删除正式材料。网络上传、下载和解析不占用长业务事务。

## 5. 权限与传输

存储默认私有，客户端不持有长期存储凭据。租户前缀、对象键不可猜测或存储 ACL 都不代替学校/校区/部门、资源与字段权限。上传、关联、预览、下载、导出结果及删除经过统一业务授权，任务与未来 Agent 也遵循同一入口。

合同、学员资料、财务导出等敏感内容优先经过受控鉴权下载入口，可由受控网关流式传输，不要求应用将整个文件读入内存。短时签名链接只按风险使用，并保护其不进入普通日志或文档。应用账号停用不会自动撤销由仍有效存储凭据签发的已有链接；若要求撤权后限制新的下载请求，必须采用持续受控入口，不承诺收回已下载内容。

对象元数据和文件名作为不可信输入处理，访问路径不能由请求任意指定；预览/解析任务按文件类型和资源边界隔离。具体网关、签名期限、上传方式与扫描/解析工具后续确定。

官方依据：[S3 签名链接可在有效期内多次使用及其凭据语义](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html)。SeaweedFS 和选定托管实现的具体行为需分别核验。

## 6. 保留、备份与恢复

DEC-018 已确认 pgBackRest + restic + SeaweedFS 配套备份、独立加密副本及演练，详见[备份与恢复方案](../备份恢复/20261030-备份与恢复方案-v1.1.md)。SaaS 日常备份优先不中断，客户可约定短暂停写；具体原生内容/元数据导出或快照命令与布局仍需在选定开源版本验证，不能把通用文件扫描当作运行存储的一致备份。

文件正式版本与完整性信息、备份批次进度和物理清理规则在文件模块设计时一起落实：清理考虑引用、备份完成和历史保护范围，恢复清单可核对业务文件引用与实际对象版本。不自动依赖商业恢复功能，也不将镜像同步作为历史备份替代。


按业务用途区分保留期限、可删除条件、引用关系和临时结果过期，不在本次擅自指定天数。业务删除、解绑和物理清理分阶段执行；正式档案保留、业务作废和个人信息处理规则在对应功能设计中明确。

业务 PostgreSQL 与文件存储必须有可对应的恢复点、备份清单或一致性校验协议。恢复同时覆盖业务文件关系、原始对象、所需存储元数据与配置/密钥恢复条件；不能只恢复业务库或只拷贝部分 SeaweedFS 数据文件就宣称附件已完整恢复。存储内部元数据是否使用 PostgreSQL 及其权限/备份边界尚未决定，不与业务表所有权混用。

对象版本控制可辅助误删/覆盖恢复，但不是完整独立备份的替代。备份介质、异机/离线副本、加密密钥保护、保留期、RPO/RTO 与恢复演练根据实际环境确定，不承诺任意单盘配置可满足既有工作假设。恢复演练检查文件数量、关联、版本、完整性与权限，并区分可重建派生结果。

## 7. 备选依据

| 方案 | 本轮结论 |
| --- | --- |
| SeaweedFS | 自建首选；优先验证开源版本的实际 S3 功能、私有访问和恢复 |
| Garage | 轻量备选；官方兼容表对版本控制等列有差异，按实际版本核验 |
| Ceph RGW | 客户已有平台时可评估接入，当前不要求额外建设 Ceph 集群 |
| MinIO 社区仓库 | 已归档，不作为本轮默认新选型；不恢复上一轮技术锁定 |
| 云厂商托管存储 | 可选实现，不再作为 SaaS 必须使用的唯一方案 |

依据：[Garage 自身兼容说明](https://garagehq.deuxfleurs.fr/documentation/reference-manual/s3-compatibility/)、[Ceph RGW](https://docs.ceph.com/en/squid/radosgw/)、[MinIO 仓库状态](https://github.com/minio/minio)。这些是讨论时的能力/状态资料，不能替代最终版本测试或作为跨产品能力的永久保证。

## 8. 验证与未决项

工程验证覆盖：私有对象读写、签名/受控下载、完整性与固化后不可意外覆盖、跨租户与跨资源拒绝、上传及关联失败补偿、重复完成/删除、引用与保留冲突、任务重启、客户内网无公网运行，以及数据库与对象存储配套恢复。按实际用例验证大文件、分段/范围请求及并发；不为未出现的需求提前建设视频平台或通用网盘。

未决为 SeaweedFS 与 SDK 的稳定版本/许可依赖、所需 S3 操作清单、单机/多节点拓扑与存储元数据、凭据和网关配置、磁盘/备份与 SLA、保留期限、托管供应商及文件系统备选的首版范围。Excel 工具与导入导出流程已另在 DEC-020 确认，见[报表与导入导出方案](../报表与数据交换/20261030-报表与导入导出方案-v1.1.md)；PDF 输出与首选方向已另在 DEC-021 确认，见[PDF 打印与模板方案](../打印与文档/20261030-PDF打印与模板方案-v1.0.md)；具体渲染版本/效果后验，模板编辑方式待定，OCR 与 AI 解析未选。当前未创建或部署服务，未执行存储运行测试。
