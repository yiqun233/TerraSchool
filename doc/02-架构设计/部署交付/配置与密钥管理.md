## 1. 已确认范围

用户比较配置文件、配置中心、受限文件、SOPS 加密文件和 OpenBao 密钥服务后，表示“这个目前没什么想法，先按你说的来”。首期采用上一轮推荐的基础组合：外部 YAML/少量普通环境变量、Spring Boot 结构化读取与校验、受限文件按服务挂载密钥。业务设置继续按已有权限、版本、生效范围与审计规则管理。

当前不要求引入集中配置中心、SOPS + age 或 OpenBao；它们保留为有明确需求时的备选，不随基础方案批准自动安装或建设。前端只接收公开配置，未来凭据访问保留受控边界，具体格式、工具版本、目录与流程在工程中验证。

## 2. 配置分类与所有权

| 类别 | 例子 | 首期方式与边界 |
| --- | --- | --- |
| 普通部署参数 | 数据库地址、存储端点、端口、资源限制 | 外部 YAML，少量普通环境变量用于受控覆盖；随部署记录版本 |
| 部署密钥 | 数据库密码、存储密钥、证书私钥、必要主密钥 | 受限宿主机文件，通过 Compose secrets/只读挂载按服务提供；不进普通 YAML、产品 Git 或镜像 |
| 业务配置 | 价格规则、审批规则、机构参数 | 数据库及业务管理入口，统一授权、作用范围、版本、生效与审计；不作为任意部署参数编辑 |
| 前端公开配置 | 公开访问地址、系统标题等必要信息 | 只向浏览器提供公开值，运行配置结构与加载方式后验；服务端授权独立执行 |

环境来源与业务归属分别管理，不按客户名复制代码分支。SaaS 与客户版复用业务代码，配置不暗中开启公网依赖；内网部署的本地服务和未来模型地址可由受控配置适配。

## 3. 外部化配置与校验

后端使用 Spring Boot 外部化配置及结构化绑定/校验，明确必填项、类型、范围和组合约束。保持标准框架加载机制，不另外建设一套通用配置平台。

- 仓库维护无秘密的示例和安全默认值，生产关键项缺失或非法时启动失败；不能静默使用开发凭据或连接错误环境。
- 明确实际配置来源、覆盖顺序与允许覆盖范围，部署清单记录配置版本；诊断只输出必要且脱敏的信息，不整体导出密钥值。
- 普通环境变量用于适合覆盖的非敏感参数。密钥优先来自挂载文件，Spring Boot 可通过 configtree 读取，具体键名和绑定配置后验。
- 连接、资源或密钥变更逐项说明是否需要重启/重建连接，不承诺任意配置热更新。初期按维护窗口执行受控变化，不在业务界面提供任意修改运行环境的入口。
- 测试、生产和客户独立部署分开配置与凭据，不把当前服务器可用状态作为其他部署默认值。

前端 Vite 构建变量会进入客户端产物，不保存服务器秘密。默认同域接入；必要的公开运行配置按白名单提供，具体文件/接口格式、缓存和版本联动继续验证。功能展示开关不替代后端授权。

## 4. 首期密钥文件与注入

密钥由部署环境独立生成或安全提供，保存在产品仓库外的受限宿主机目录，按服务显式授予读取权限，当前通过 Compose 环境变量注入（与 DEC-017 的目标形态存在偏离，见 [CI 打包与多环境部署](CI打包与多环境部署.md)）；Compose secrets/只读挂载尚未落地。文件拥有者、服务 UID、目录与文件权限、挂载行为必须在选定 Linux 环境实际验证，不能简单假定容器内外权限一定一致。

Compose 在当前单机模式中主要挂载文件，不自动加密宿主机文件。该方案允许运行密钥以明文文件存在受控运行环境，保护依赖主机权限、服务隔离、安全分发和受控备份；不宣称可阻止已获得宿主机管理权限的主体读取。

- 不将秘密放进 Git、镜像、前端、命令行参数、日志、错误或诊断产物；示例使用明显占位值，不提供通用生产默认密码。
- 应用运行、迁移和备份凭据分开，按实际用途授权；普通业务角色不得因注入机制获得 RLS 绕过或自动建表权限。
- 每套部署使用独立凭据，服务只读取需要的文件，第三方/客户环境与 SaaS 不共享一套密钥。
- 数据库连接密码由部署环境提供，不从尚未连接的业务数据库中读取，避免启动依赖循环。
- 日志和审计记录操作、对象、结果及必要版本信息，不记录密钥原文。CI 不因能构建程序自动取得生产凭据，参考资料也不参与配置分发。

## 5. 更换、备份与恢复

密钥更换按数据库、存储、证书等各自机制设计受控步骤，明确权限、受影响服务、是否重启、验证结果、撤销旧凭据及失败处置。替换一个挂载文件不等于服务已重新加载，也不等于外部系统已撤销旧凭据。

备份需保护配置和恢复必需的凭据/解密条件，限定访问和恢复用途；主密钥与加密数据的备份保管边界明确，不能把所有解密条件与密文任意打包分发。备份方向已在 DEC-018 确认 pgBackRest 仓库加密及 restic 文件仓库，见[备份与恢复方案](../备份恢复/备份与恢复方案.md)；加密配置、介质、保留和恢复协议仍待验证，当前不宣称已实现加密备份或自动轮换。

恢复验证同时检查数据库、对象及存储元数据、配置/证书和密钥条件；登录密码不可逆哈希，不纳入可解密密钥设计。更换主密钥、文件加密密钥和真实数据库/API 凭据属于不同动作，未来实现时分别验证。

## 6. 未来凭据管理边界

未来由机构配置模型、渠道或外部系统凭据时，业务通过稳定的凭据引用访问，按租户、用途与当前授权校验；AI 参数和工具返回不携带实际秘密。需要恢复原文的业务托管凭据采用成熟加密实现，主密钥在业务数据库之外，并保留版本与更换/恢复条件。

这是底座设计约束，当前不创建通用凭据平台、模型适配或 AI 功能。具体加密实现、密钥版本、提供者适配和管理界面在真实接入时验证，不因未来可能接入而先引入独立服务。登录密码继续使用适当不可逆密码哈希。

## 7. 备选与演进条件

| 备选 | 保留价值 | 本轮结论 |
| --- | --- | --- |
| Nacos 等配置中心 | 多应用/多环境集中发布和监听 | 当前无明确需求，不作为首期依赖；热更新仍需应用安全切换机制 |
| SOPS + age | 敏感配置加密留存和交付，无需额外常驻服务 | 后续需要时评估；解密私钥、明文落点与恢复仍须管理，未批准加密文件入库例外 |
| OpenBao | 集中授权、读取审计及支持系统的动态凭据 | 后续需求触发；需维护身份、解封、租约、可用性和恢复，不设为客户单机必需服务 |
| 环境变量/明文 .env 存密钥 | 兼容某些既有平台，注入简单 | 不作为本产品生产密钥主方案；出现客户平台约束时受控适配 |

这些工具可以与文件注入组合。保存、分发和读取的职责保持清楚，不让业务模块依赖特定工具；未来增强不要求重写业务契约。SOPS 和 OpenBao 可以在适当准备后内网使用，不把其备选状态解释为必须联网或能力不足。

## 8. 验证与未决实现

正式工程前验证选定组件版本、标准配置覆盖/绑定与校验、文件权限/挂载、冷启动和断网、缺失/错误凭据、脱敏、凭据更换与服务重启，以及配套恢复。以后启用 B 时增加旧新实例配置/密钥兼容，实际建设密钥服务时再验证其不可用行为。

具体目录、UID、键名、示例、配置白名单、工具/库版本、轮换操作、公开配置格式、加密实现及备份工具尚未锁定。本方案最初的选型记录不代表这些生产配置已实现或运行验证通过。正式业务工程已创建，实际本地配置与当前交付缺口见 F35；不据本方案自动生成凭据或修改服务器，Git 仍按每次明确授权处理。

## 9. 官方能力依据

- [Nacos](https://nacos.io/en/docs/latest/what-is-nacos/)、[SOPS](https://getsops.io/docs/)与[OpenBao](https://openbao.org/docs/what-is-openbao/)：比较过的备选能力，具体采用需另行验证。
