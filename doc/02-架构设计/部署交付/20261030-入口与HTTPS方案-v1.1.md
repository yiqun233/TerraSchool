## 1. 确认范围

用户对是否存在必须沿用的网关/代理/证书规范回复“没有已知限制，按推荐方案设计”。标准入口采用 Nginx 开源版，按上一轮推荐设计 HTTPS、同域前后端访问及客户现有入口接入能力。

这表示当前没有已知强制外部约束，不代表所有未来客户均无要求。保留客户已有反向代理、网关和证书体系接入能力，不强制重复设置入口层。

配置与密钥经过另行比较后，用户确认先按推荐基础方案执行，现以 DEC-017 为准：外部 YAML/结构化校验与受限文件按服务注入。SOPS/OpenBao 及集中配置服务保留备选，前端公开配置具体加载格式等仍待验证。

## 2. 入口职责

浏览器通过 HTTPS 入口访问前端静态资源和后端业务接口。默认按同域路径转发设计，具体路径、域名、端口与代理层数在工程配置中验证。

- Nginx 负责接入与转发、静态资源、TLS、请求限制及代理行为；应用服务继续完成租户、权限、字段、状态、幂等和审计。
- 数据库与存储管理端口留在受限网络；文件下载与预览沿用文件模块授权，不能因由代理提供文件而跳过业务检查。
- 后端只接受由可信部署代理提供的来源与协议信息，明确头部清理/重建和直连限制。Host、转发头或代理分组不能单独建立可信租户身份。
- 网页会话继续遵守 Cookie/CSRF 决策；外部 Agent 的未来委托接入不通过关闭网页防护实现。
- 静态页面回退与 API/下载错误分开，不能将接口错误统一替换为 SPA HTML；缓存策略区分入口页、带版本静态资源与敏感业务响应。

## 3. HTTPS 与证书

SaaS 使用可信证书，明确续期、到期检查和失败处置；客户内网支持客户证书体系。没有现有体系时，内网 CA 的签发、终端信任安装和恢复方法另行设计，不能以忽略浏览器证书错误代替交付。

证书域名/IP、完整链、私钥保护、TLS 配置和更换/重载需验证。客户断网运行不依赖公网证书签发或续期；证书签发工具与自动化方式未选定。私钥不进入源码、镜像、前端或日志，密钥文件注入基线已在 DEC-017 确认，实际路径、权限和更换配置待验证。

## 4. 初期发布与后续演进

沿用 DEC-015：初期维护窗口升级，后续应用双版本切换。入口支持受控检查、更新与重载；新应用就绪、流量切换、在途请求和旧应用退出需要协同验证，不以代理重载成功代表业务发布通过。

上传、下载、普通业务请求及未来流式响应按用途设置缓冲、大小和超时；流式能力只预留代理支持，不在本次创建 AI 接口。关键写操作的代理重试策略与业务幂等一起验证，避免不确定结果下重复副作用。

Nginx 开源版为当前标准选择，不以付费版特有能力为前提。现有入口接入、冗余与高可用拓扑另按需求确定，选择 Nginx 不表示已建设故障切换。

## 5. 备选与验证

Caddy 保留为比较过的备选，自动 HTTPS 与本地 CA 可用，但客户端信任及客户证书规范仍须处理。当前优先统一 Nginx 配置与交付路径，不宣称 Caddy 无法内网使用，也不引入独立 API 网关平台。

工程阶段验证 HTTPS/证书链与断网运行、深层链接和 API 错误、Cookie/CSRF、可信转发头、租户/文件授权、上传下载、重载和维护、后续旧新共存及流式连接。具体稳定版本、证书工具、配置、资源限制、缓存和代理重试范围仍待验证。

当前仅维护文档，未安装 Nginx、修改服务器或运行代理/业务测试。配置与密钥管理及备选取舍见[配置与密钥管理](20261030-配置与密钥管理-v1.1.md)，首期基础方案已确认，备选服务未自动批准，运行配置后验。
