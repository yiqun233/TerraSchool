本文件夹是项目重新开始后的完整文档入口。项目是在旧培训学校综合业务系统基础上做业务升级与重新实现，业务事实来自旧系统源码、数据库脚本、手册和业务确认。旧系统原始材料保存在同级的 [参考资料](../参考资料/)。

上一轮新项目的代码、技术栈锁定、实现进度和实现评审不再作为开发依据。新项目尚未开始实现；已确认 Java/Spring Boot 业务核心、PostgreSQL 与 React/TypeScript 前端，具体组件、版本及部署布局继续设计；AI 编排和模型后置选择。当前只维护干净的需求、原则、证据与执行路线。

当前业务以已有需求和旧系统为基线，不重新开展全量调研。下一步重点见[开发前准备与工程规范](03-研发规范/20261030-开发前准备与工程规范-v1.6.md)：确定工程规范、项目结构和技术选型，局部业务细节随功能实现核对。

## 使用方式

- 功能范围看功能清单；业务规则看规则基线；交付顺序看执行路线；未决问题看问题清单。
- “已确认需求”“工作假设”“待确认”“建议”不能混为同一种状态。
- 每项功能建立“旧系统证据 → 新需求 → 规则 → 操作契约 → 验收案例 → 任务”的追踪关系。
- P0–P3 表示业务范围层次；R0–R9 表示执行路线，均不表示工期或日期。
- 未来 AI 功能另行规划；现在先保证多入口业务调用、授权、可靠执行和数据追溯的设计能力。
- doc/ 与根 AGENT.md 是当前开发文档和操作依据；参考资料/ 保留为独立对照材料，不提交 Git。

## 登录范围与身份方案

DEC-007 确认首版系统账号登录、统一登录扩展；DEC-008 确认 Spring Security、服务端会话及 Spring Session JDBC/PostgreSQL 存储，保留角色、账号增减、按操作的数据范围与字段控制。见[登录会话与权限方案](02-架构设计/身份权限/20261030-登录会话与权限方案-v1.0.md)。具体版本、配置和权限实现细节继续设计，尚未创建代码或验证集成。下一轮优先讨论后台任务与可靠业务事件。
