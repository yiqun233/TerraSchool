## 状态边界

REQ 编号对应范围基线的每一个能力行；SUP 是工程支撑细项，AI 是未来能力。重复业务入口保留范围来源，不把条目数当作独立功能数或完成率。F 是模块汇总，REV 是执行任务。

开发：未开始 / 进行中 / 局部实现 / 已实现 / 暂缓。验证：未验证 / 局部有证据 / 已验证。验收：未提请 / 待验收 / 已验收。暂缓表示依赖或阶段后置，范围继续保留；等待确认不自动等于开发暂停。

首次建账依据现有 F 台账、相关设计、测试线索及验证记录。局部有证据不代表本轮重跑，更不代表该能力全集通过；“已验证”必须链接明确覆盖本细项范围的记录。“已验收”必须有验收人、日期、案例和结论。当前无足够仓库证据把任一细项记为已验收。

问题列引用 Q/C/BQ；资料列引用 DATA，表示关闭验收所需证据尚需核验，不推断资料全部缺失。不清楚的功能先记录，等待期间继续无关能力。细项内若出现混合进度，可按 `REQ-A01.1` 等稳定后缀进一步拆分，同时保留父项汇总；子项沿用同一 F 模块，“已做范围”以“子能力名：具体覆盖”书写，生成器检查父项存在。子项完成不自动关闭父项。
