## 1. 推进方法

业务范围与主要规则已有基线，不重新启动全量需求调研。当前优先确定工程规范、文档规范、项目结构和技术选型，并设计核心领域与契约，随后验证底座与一个真实业务切片，再扩展首版全闭环。迁移、权限、并发、报表和对账从切片开始贯穿，不能留到最后集中补齐。

R0–R9 只表达依赖与交付顺序，不给出工期、人员编制或完成日期。P0–P3 表示业务范围，与执行路线不是同一维度。每个阶段交付可核验成果，不以目录数量、接口数量或页面演示代替验收。

当前状态：R0文档基线已形成，R3隔离原型已验证；用户已授权正式工程，R4已分批交付账号会话、租户隔离、组织查询/维护、失败审计和本批组织统一授权，实际记录见文末。SC01报名资金闭环仍未实现，其他专项按依赖继续落实。旧代码被删除不代表新项目已完成功能；决策见[技术决策记录](../05-决策与问题/20261030-技术决策记录-v1.19.md)。下面R0–R9保留阶段目标，具体已交付范围以文末实施记录为准。

| R6 P0 全业务展开 | 补齐首版全部规则与场景 | 招生、报名、收费、单/多班排课、考勤、全结算、审批报表与交付工具 | 功能清单 P0 验收完成，关键并发与权限专项通过 |
| R7 迁移与正式交付 | 将可靠迁移、恢复和客户上线做成产品能力 | 全量/部分迁移、历史查询、对账、切换回退、运维与内网交付验证 | 业务与财务验收、恢复演练、首版闭环达标后才开放真实业务 |
| R8 P1/P2 扩展 | 补齐运营和标准全量需求 | 按功能清单交付增强模块 | 逐项追踪、复用底座，无新入口绕过规则 |
| R9 外部集成与未来 AI | 按真实需求增加适配能力 | 客户集成、受控扩展；未来模型与 Agent 接入 | 单项另行定范围；AI 不绑定本阶段全部结束，也不在本次提前开发 |

R1 的工程规范、R2 的领域设计、R5 的最小数据装载持续支撑后续；旧系统对照与金标准按具体功能持续补充；R7 是正式交付收敛，不是首次开始迁移。R6 领域包按实际依赖组合推进，不要求先把一个大模块全部做完再首次调用下一个模块。

## 3. R1：工程准备与规范

当前先落实[开发前准备与工程规范](../03-研发规范/20261030-开发前准备与工程规范-v1.24.md)，结合 R2/R3 确定项目结构与技术组合。以下是后续功能开发持续进行的旧系统对照工作，不是要求用户重新确认全部业务，也不是全部完成后才能选型或开工。

| 任务 | 输出 | 验收 |
| --- | --- | --- |
| REF-001 功能追踪 | 旧菜单、手册章节、接口、表和定制来源映射到功能 ID | 每项明确 P0–P3、待确认或放弃；未覆盖项可见，不声称已全量核对 |
| REF-002 业务角色与操作 | 岗位工作流、角色 × 动作 × 数据范围矩阵 | 读、写、选项、导出、敏感字段和管理委派有一致规则 |
| REF-003 财务金标准 | 结算 0–5、退费、冲销、差额、锁月、团培、尾差案例 | 旧代码行为和财务预期冲突逐项定结论；不能用模型推算代替确认 |
| REF-004 排课基准 | 真实或经确认的班级、教师、教室、学员、占用与旧结果 | 单班和多班都有样本；冲突按操作区分；无解与兜底清楚 |
| REF-005 迁移样本与依赖 | 最终库结构、脱敏样本、机构边界、历史与在读清单 | 单位、累计字段、附件、跨校区依赖及多库情形已识别 |

在未决问题不影响的范围可继续考证和设计；未确认金额公式或权限边界不能进入对应生产规则实现。

## 4. R2：领域与应用契约

应输出：

1. 机构、学校、校区、部门、人员、学员家长、产品、报名、资金、课次等概念与关系，不先指定 SQL 字段类型。
2. 报名、支付、退款、课次、审批、订阅的状态转换及并行状态维度。
3. 每项关键操作的输入输出、主体、权限、范围、版本、幂等、失败、审计及副作用。
4. 收款分配、关课入账、退款、转班、锁月等原子边界，以及可异步投影/通知清单。
5. 指标目录初稿、材料来源与核实状态、历史兼容与规则版本策略。
6. 一个从导入到退款的切片时序图，验证各领域契约能组合，避免循环依赖和双重权威数据。

退出时，页面和未来 AI 仅是不同调用入口；不需要模型、聊天记录或页面状态才能完成核心业务校验。

## 5. R3：技术选型

主干方向已通过 DEC-001 至 DEC-021 确认，不重复选择语言/框架、数据库和已选组件。按 DEC-022 分阶段验证兼容组合与关键风险，版本经验证后锁定；选择、例外和结果维护在技术决策与工程质量文档，重大路线/付费依赖/部署要求变化再讨论。实际原型验证与正式编码启动范围另行明确。

关键风险原型限定范围：

- 同一租户下细粒度授权及跨租户读写隔离。
- 复杂事务、并发退款、关课和锁月的正确性。
- 排课计算与课表交互的真实负载。
- 长任务的领取、重启恢复、幂等及事件可靠性。
- 客户内网安装、升级、备份恢复，以及未来本地模型可接入性。

原型仅用于验证方案，不默认成为正式代码。技术方案确认后建立全新的工程、构建基线、依赖锁定与决策记录；不恢复上一轮工程再宣布已选型。

## 6. R4：底座与最小实现范式

| 工作包 | 交付重点 |
| --- | --- |
| CORE-001 工程与契约 | 可复现构建、环境配置、依赖策略、契约与文档同步方式、DEC-015 发布/任务恢复/版本兼容及 DEC-018 配套备份和隔离恢复的最小验证 |
| CORE-002 身份与租户 | 落实 DEC-006 的共享表/tenant_id/RLS、事务连接上下文、角色分离与非数据库资源隔离；明确主体来源、可用状态、撤销与平台边界，并验证双租户及连接池复用拒绝 |
| CORE-003 授权 | 落实 DEC-008 的角色、账号增减、按操作的数据范围与字段控制，验证委派管理、撤权和并发保护；合法选项查询可用 |
| CORE-004 应用入口 | 有类型契约、服务级校验、稳定错误、版本检查和统一上下文 |
| CORE-005 可追溯 | DEC-019 应用动作审计、关键成功同事务/失败拒绝独立记录、租户字段授权、JSON 日志脱敏轮转、请求/任务关联、受限指标及必要告警验证 |

不要一次性建设所有通用平台。DEC-009 已选 PostgreSQL + db-scheduler + 事务 Outbox，worker 按需独立运行；任务、幂等和可靠事件在首个真实用例中落实，验证事务回滚、崩溃重试、取消竞态、旧执行者提交和租户权限，再抽出复用部分。

底座退出验证：同一业务经正常入口和模拟第二入口调用时，授权与校验一致；未认证、缺租户、越范围、撤权和错误输入被拒；并发授权不会放大权限或清空最后管理员；不用真实大模型。

## 7. R5：首个纵向切片

DEC-022 已确认沿用本节切片。以脱敏旧样本装载一所学校及必要人员/资源，先明确领域所有权、状态、应用操作、资金履约原子边界和一种结算路径的证据与预期，再完成：

```text
产品与价格 → 客户/学员/家长 → 一条报名 → 一笔收款及分配
→ 一个班与一节课的排课草稿 → 发布/确认 → 考勤
→ 课次关闭与消费入账 → 部分退课时/退款 → 指标查询与对账
```

SC01 已由用户确认采用普通报名/平均价格模式1、1000元10课时、消费1课时100元、退2课时200元，先到账户再独立确认现金退出；阶段数值和适用边界见[验收样例](../01-业务需求/业务切片/20261031-首个业务切片验收样例-v0.2.md)。该人工基准有旧源码分支依据，但尚未运行新业务或迁移真实旧快照。不能以此删掉其余模式，复杂档案查重、团培、多班、多产品和跨月等在 R6 展开，单/多班自动排课仍属于完整 P0。

切片同时覆盖不同岗位及数据范围、重复提交、一次并发冲突、任务失败和业务审计。需要长任务的部分验证重启恢复。UI 可以简洁，但必须能查看实际业务结果和错误，不能只有接口演示。

DEC-022 要求用页面接口及测试中的第二调用入口调用同一应用服务，验证授权、校验、事务与审计一致；无需模型、聊天界面或外部 Agent 运行时。排课草稿创建与发布仍为不同动作，发布按适用确认规则执行；退款经任一入口均检查权限、实际可退金额及并发条件，测试入口不能成为绕过控制的后门。

| 验收维度 | 切片必须给出的证据 |
| --- | --- |
| 正常业务 | 旧样本来源及映射可追溯；报名、资金分配、课次和退款关联正确；金额/课时/状态与已确认预期逐项对账 |
| 授权与隔离 | 不同岗位及范围可用；未授权、跨租户、无效状态或过期方案被拒；两个调用入口执行相同业务规则 |
| 幂等与并发 | 重复提交不重复入账；至少一种真实并发冲突保持不变量；失败不遗留半套权威事实 |
| 任务与结果 | 使用持久任务的部分验证中断/重试/恢复及结果权限，审计可追溯；页面能看到真实结果与可理解错误 |

本节定义首个可验收闭环，不代表完整 P0 或正式上线已就绪；阶段准备与上线条件统一见[工程准备规范](../03-研发规范/20261030-开发前准备与工程规范-v1.24.md)。

退出时确认：权威金额/课时可对账，事实与投影区分，调整有单据，历史规则与新规则边界明确，跨模块依赖未出现反向绕过。若模型不成立先修模型，再扩大功能。

## 9. R7：迁移与交付

迁移工具支持四种模式、依赖闭包、规则映射、重复运行、全量及增量边界、附件与历史查询。对账分数量、金额、课时、状态、财务期间和关系完整性，不只看行数。

正式切换前进行至少一次完整演练，包括在读业务继续结算、部分退款、失败重跑和恢复；DEC-018 的数据库/附件/配置/密钥配套恢复及任务/外部副作用控制纳入实际校验。业务与财务确认差异，零差异目标和例外处置有记录。开放写入前与写入后的回退分别验证。

安全、性能、恢复、可观测和 SaaS/客户内网交付根据明确要求验收。没有实现 AI 不影响业务版验收；客户内网业务运行不得被未启用的云端 AI 依赖阻断。

## 10. R8/R9：后续范围与 AI

- P1：学习顾问、教师课酬、住宿、公开课与活动、绩效、跨校共享、移动端及消息，按依赖推进，不擅自删项。
- P2：高级流程、学习计划、问卷考试进阶、服务券、自修、OA/采购、报表设计器、多语言/币种、自定义字段；具体默认开启与可选方式待确认。
- P3：支付、消息和客户渠道深度集成、会议、呼叫中心、CRM、电子合同、财务系统、硬件、独立产品线与受控客户扩展。
- AI：相关业务操作和权限已稳定后，单独确认实际首发场景、范围和接入方式；可以选择已经成熟的业务能力试点，不要求先完成所有 P1–P3，也不把现在列出的场景提前排为当前开发任务。
