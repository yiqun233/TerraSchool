## 1. 推进方法

业务范围与主要规则已有基线，不重新启动全量需求调研。当前优先确定工程规范、文档规范、项目结构和技术选型，并设计核心领域与契约，随后验证底座与一个真实业务切片，再扩展首版全闭环。迁移、权限、并发、报表和对账从切片开始贯穿，不能留到最后集中补齐。

R0–R9 只表达依赖与交付顺序，不给出工期、人员编制或完成日期。P0–P3 表示业务范围，与执行路线不是同一维度。每个阶段交付可核验成果，不以目录数量、接口数量或页面演示代替验收。

当前状态：R0 已完成文档整理；R1 工程规范与准备清单已形成草案，Java/Spring Boot、PostgreSQL、React/TypeScript 主线和 AI 辅助定位已确认，具体组件、版本与工程结构继续设计，正式实现未开始。旧代码被删除不代表新项目已完成功能；决策见[技术决策记录](../05-决策与问题/20261030-技术决策记录-v1.10.md)，不自行创建代码骨架。

## 2. 总体路线

| 阶段 | 目标 | 核心交付物 | 依赖与退出条件 |
| --- | --- | --- | --- |
| R0 文档重启 | 建立干净、可独立使用的需求与执行基线 | 本文件夹、旧资料入口、未决事项 | 无旧技术锁定、无旧实现进度、关键业务范围和 AI 需求有出处 |
| R1 工程准备与规范 | 确定开发、文档、结构、契约与验证规范 | [工程准备规范](../03-研发规范/20261030-开发前准备与工程规范-v1.11.md)、旧系统对照入口、技术讨论输入 | 准备事项可执行；局部业务核验不作为全项目启动门槛 |
| R2 领域与能力设计 | 先确定数据所有权、操作和一致性边界 | 概念模型、状态与操作目录、权限矩阵、事务/事件清单 | 纵向切片在设计上可贯通，功能不依赖页面才能成立 |
| R3 技术选型与风险验证 | 细化已确认主线的组件和版本，不继承旧实现 | 备选比较、关键原型结果、新决策记录 | 方案覆盖复杂业务、租户、安全、本地部署和扩展约束，经确认后才建正式工程 |
| R4 底座与开发范式 | 建立最小可靠工程与业务调用规范 | 身份与隔离、应用入口、错误/审计、契约、验证与发布基础 | 多入口授权一致、跨租户拒绝、可重复构建与最小部署验证通过 |
| R5 首个纵向业务切片 | 用小范围真实业务检验全链模型 | 从旧样本导入到部分退款和报表的可运行闭环 | 金额、课时、状态、权限和对账正确，失败可解释；不能作为完整 P0 上线 |
| R6 P0 全业务展开 | 补齐首版全部规则与场景 | 招生、报名、收费、单/多班排课、考勤、全结算、审批报表与交付工具 | 功能清单 P0 验收完成，关键并发与权限专项通过 |
| R7 迁移与正式交付 | 将可靠迁移、恢复和客户上线做成产品能力 | 全量/部分迁移、历史查询、对账、切换回退、运维与内网交付验证 | 业务与财务验收、恢复演练、首版闭环达标后才开放真实业务 |
| R8 P1/P2 扩展 | 补齐运营和标准全量需求 | 按功能清单交付增强模块 | 逐项追踪、复用底座，无新入口绕过规则 |
| R9 外部集成与未来 AI | 按真实需求增加适配能力 | 客户集成、受控扩展；未来模型与 Agent 接入 | 单项另行定范围；AI 不绑定本阶段全部结束，也不在本次提前开发 |

R1 的工程规范、R2 的领域设计、R5 的最小数据装载持续支撑后续；旧系统对照与金标准按具体功能持续补充；R7 是正式交付收敛，不是首次开始迁移。R6 领域包按实际依赖组合推进，不要求先把一个大模块全部做完再首次调用下一个模块。

## 3. R1：工程准备与规范

当前先落实[开发前准备与工程规范](../03-研发规范/20261030-开发前准备与工程规范-v1.11.md)，结合 R2/R3 确定项目结构与技术组合。以下是后续功能开发持续进行的旧系统对照工作，不是要求用户重新确认全部业务，也不是全部完成后才能选型或开工。

| 任务 | 输出 | 验收 |
| --- | --- | --- |
| REF-001 功能追踪 | 旧菜单、手册章节、接口、表和定制来源映射到功能 ID | 每项明确 P0–P3、待确认或放弃；未覆盖项可见，不声称已全量核对 |
| REF-002 业务角色与操作 | 岗位工作流、角色 × 动作 × 数据范围矩阵 | 读、写、选项、导出、敏感字段和管理委派有一致规则 |
| REF-003 财务金标准 | 结算 0–5、退费、冲销、差额、锁月、团培、尾差案例 | 旧代码行为和财务预期冲突逐项定结论；不能用模型推算代替确认 |
| REF-004 排课基准 | 真实或经确认的班级、教师、教室、学员、占用与旧结果 | 单班和多班都有样本；冲突按操作区分；无解与兜底清楚 |
| REF-005 迁移样本与依赖 | 最终库结构、脱敏样本、机构边界、历史与在读清单 | 单位、累计字段、附件、跨校区依赖及多库情形已识别 |

在未决问题不影响的范围可继续考证和设计；未确认金额公式或权限边界不能进入对应生产规则实现。

## 4. R2：领域与应用契约

应输出：

1. 机构、学校、校区、部门、人员、学员家长、产品、报名、资金、课次等概念与关系，不先指定 SQL 字段类型。
2. 报名、支付、退款、课次、审批、订阅的状态转换及并行状态维度。
3. 每项关键操作的输入输出、主体、权限、范围、版本、幂等、失败、审计及副作用。
4. 收款分配、关课入账、退款、转班、锁月等原子边界，以及可异步投影/通知清单。
5. 指标目录初稿、材料来源与核实状态、历史兼容与规则版本策略。
6. 一个从导入到退款的切片时序图，验证各领域契约能组合，避免循环依赖和双重权威数据。

退出时，页面和未来 AI 仅是不同调用入口；不需要模型、聊天记录或页面状态才能完成核心业务校验。

## 5. R3：技术选型

按问题清单讨论语言/框架、数据与隔离、界面、身份、文件、任务、报表、部署和观测。每项记录约束、至少合理备选、放弃原因、代价和验证证据；必要时合并相互关联的选择。

关键风险原型限定范围：

- 同一租户下细粒度授权及跨租户读写隔离。
- 复杂事务、并发退款、关课和锁月的正确性。
- 排课计算与课表交互的真实负载。
- 长任务的领取、重启恢复、幂等及事件可靠性。
- 客户内网安装、升级、备份恢复，以及未来本地模型可接入性。

原型仅用于验证方案，不默认成为正式代码。技术方案确认后建立全新的工程、构建基线、依赖锁定与决策记录；不恢复上一轮工程再宣布已选型。

## 6. R4：底座与最小实现范式

| 工作包 | 交付重点 |
| --- | --- |
| CORE-001 工程与契约 | 可复现构建、环境配置、依赖策略、契约与文档同步方式、最小部署验证 |
| CORE-002 身份与租户 | 落实 DEC-006 的共享表/tenant_id/RLS、事务连接上下文、角色分离与非数据库资源隔离；明确主体来源、可用状态、撤销与平台边界，并验证双租户及连接池复用拒绝 |
| CORE-003 授权 | 落实 DEC-008 的角色、账号增减、按操作的数据范围与字段控制，验证委派管理、撤权和并发保护；合法选项查询可用 |
| CORE-004 应用入口 | 有类型契约、服务级校验、稳定错误、版本检查和统一上下文 |
| CORE-005 可追溯 | 业务审计接口、敏感信息处理、请求关联、必要指标与故障定位 |

不要一次性建设所有通用平台。DEC-009 已选 PostgreSQL + db-scheduler + 事务 Outbox，worker 按需独立运行；任务、幂等和可靠事件在首个真实用例中落实，验证事务回滚、崩溃重试、取消竞态、旧执行者提交和租户权限，再抽出复用部分。

底座退出验证：同一业务经正常入口和模拟第二入口调用时，授权与校验一致；未认证、缺租户、越范围、撤权和错误输入被拒；并发授权不会放大权限或清空最后管理员；不用真实大模型。

## 7. R5：首个纵向切片

从旧样本装载一所学校及必要人员/资源，完成：

```text
产品与价格 → 客户/学员/家长 → 一条报名 → 一笔收款及分配
→ 一个班与一节课的排课草稿 → 发布/确认 → 考勤
→ 课次关闭与消费入账 → 部分退课时/退款 → 指标查询与对账
```

先选已确认金标准的一种结算路径验证边界；不能以此删掉其余模式。复杂档案查重、团培、多班、多产品和跨月等在 R6 展开。

切片同时覆盖不同岗位及数据范围、重复提交、一次并发冲突、任务失败和业务审计。需要长任务的部分验证重启恢复。UI 可以简洁，但必须能查看实际业务结果和错误，不能只有接口演示。

退出时确认：权威金额/课时可对账，事实与投影区分，调整有单据，历史规则与新规则边界明确，跨模块依赖未出现反向绕过。若模型不成立先修模型，再扩大功能。

## 8. R6：P0 全业务展开

| 工作包 | 交付范围 | 关键验收 |
| --- | --- | --- |
| BIZ-001 组织与主数据 | 学校、校区、部门、员工、教师、教室、字典、编号与资源占用 | 组织约束、账号生命周期、资源权限和树并发 |
| BIZ-002 产品与招生 | 课程、班型、产品版本、价格、优惠、服务费、渠道、公私海、分配回收、跟进查重 | 有效期、归属、例外与审计 |
| BIZ-003 档案与报名 | 学员家长关系、多产品/多班/插班/仅服务费、审核、转退延期、合同打印归档 | 履约单元、查重合并、历史不被覆盖 |
| BIZ-004 收款与账户 | 定金、尾款、分配、票据、审核、余额与流水 | 幂等、守恒、并发和对账 |
| BIZ-005 教务与排课 | 班级、单班和多班自动排课、自动排老师/教室、冲突、锁定、草稿、发布确认 | 基准、无解、取消、失败回退、资源竞争 |
| BIZ-006 考勤与结算 | 缺勤、补课、换课、关闭、模式 0–5、团培、服务费、额外消费、退费冲销、差额锁月 | 全金标准、历史续算、关课/退款/锁月并发 |
| BIZ-007 审批与报表 | 已确认固定审批、指标和核心报表、权限过滤、查询导出 | 申请审批执行链、口径对平、无重复聚合 |
| BIZ-008 业务交付工具 | 导入、导出、附件、合同/收据/听课证/课表打印、审计查询 | 校验报告、任务进度、下载鉴权、正确编号与金额 |

收款与财务、考勤与结算等应共同设计；不能等教务全部实现后才设计财务模型。自动排课与 AI 无关，属于确定性业务能力，不能因为 AI 后置而延期。

P0 总验收：完整业务闭环及全部 P0 候选中已批准事项通过；12 项报表/导出候选与六类审批的最终范围需在对应开发前确认。没有确认的项目标注状态，不能以“默认全部通过”关闭任务。

## 9. R7：迁移与交付

迁移工具支持四种模式、依赖闭包、规则映射、重复运行、全量及增量边界、附件与历史查询。对账分数量、金额、课时、状态、财务期间和关系完整性，不只看行数。

正式切换前进行至少一次完整演练，包括在读业务继续结算、部分退款、失败重跑和恢复。业务与财务确认差异，零差异目标和例外处置有记录。开放写入前与写入后的回退分别验证。

安全、性能、恢复、可观测和 SaaS/客户内网交付根据明确要求验收。没有实现 AI 不影响业务版验收；客户内网业务运行不得被未启用的云端 AI 依赖阻断。

## 10. R8/R9：后续范围与 AI

- P1：学习顾问、教师课酬、住宿、公开课与活动、绩效、跨校共享、移动端及消息，按依赖推进，不擅自删项。
- P2：高级流程、学习计划、问卷考试进阶、服务券、自修、OA/采购、报表设计器、多语言/币种、自定义字段；具体默认开启与可选方式待确认。
- P3：支付、消息和客户渠道深度集成、会议、呼叫中心、CRM、电子合同、财务系统、硬件、独立产品线与受控客户扩展。
- AI：相关业务操作和权限已稳定后，单独确认实际首发场景、范围和接入方式；可以选择已经成熟的业务能力试点，不要求先完成所有 P1–P3，也不把现在列出的场景提前排为当前开发任务。

AI 初期为辅助助手，未来主入口保留为演进可能，普通业务页面始终独立可用。未来 AI 交付复用既有操作：资料提取先保存待核实草稿，排课只调用确定性排课服务，问数只组合已定义指标，外部 Agent 使用员工受限委托。模型替换不改变核心业务规则。

## 11. 任务管理与完成标准

任务状态使用：未开始、设计中、待确认、可开发、开发中、待验证、待验收、完成。没有代码阶段不提前标记开发完成。

每个任务记录：关联功能和规则、依赖、输入材料、范围与非目标、交付物、验收案例、验证命令或可复现步骤、结果、未决项和文档变化。新增范围先进入功能清单，技术变化先形成决策。

一个可交付代码批次完成应同时具备：业务正确、授权与隔离、适当单元/集成/契约/端到端验证、并发与失败处理、文档一致、必要的可观测与运维说明，以及一次只读评审。覆盖率数字和构建成功不替代真实业务验收。

## 12. 下一次讨论入口

统一仓库/模块化单体、jOOQ + Flyway，以及标准 SaaS 共享库/表 + tenant_id + PostgreSQL RLS 已确认。DEC-008 已确认 Spring Security、服务端会话、Spring Session JDBC/PostgreSQL 及权限模型；版本、配置与集成仍需验证。DEC-009 已确认 PostgreSQL + db-scheduler + 事务 Outbox，worker 按需独立运行，业务资金履约保持强事务边界。DEC-010 已选 SeaweedFS 自建首选，SaaS/客户版优先复用 S3 接口，云托管可选。DEC-011 已确认 REST/JSON + OpenAPI、主要业务 UUIDv7、BigDecimal/numeric 与十进制字符串，以及时间/分页/错误/幂等并发约定。DEC-012 已选方案 A：Vite、React Router、TanStack Query、Ant Design/Form 及按需 Zustand，版本/浏览器和专项组件后验。下一次优先讨论工程工具与质量门禁：构建/依赖锁定、格式与静态检查、测试、架构约束及 CI；不自动安装工具或开始实现。存储版本/拓扑、硬盘、备份及打印引擎仍需细化。具体隔离策略、恢复方案和其他工程细节继续验证。已确认业务直接作为选型输入，局部规则在对应功能实现时对照旧代码和环境，只有实际冲突或新增取舍才询问用户。以[技术决策记录](../05-决策与问题/20261030-技术决策记录-v1.10.md)中的生效范围为准；具体版本和未批准组件不自动锁定。
